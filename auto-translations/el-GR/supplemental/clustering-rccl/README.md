# Ομαδοποίηση Δύο Ryzen™ AI Halo με RCCL

## Επισκόπηση

Το Ryzen™ AI Halo σας είναι ήδη ικανό να εκτελεί μεγάλα γλωσσικά μοντέλα τοπικά. Η ομαδοποίηση (clustering) πηγαίνει αυτό ένα βήμα παραπέρα, συνδυάζοντας τη μνήμη GPU πολλαπλών συστημάτων μέσω ενός τοπικού δικτύου, δίνοντάς σας πρόσβαση σε ακόμα μεγαλύτερα μοντέλα με ισχυρότερη λογική συλλογιστική, καλύτερη παραγωγή κώδικα και βαθύτερη πολυγλωσσική κατανόηση, όλα εξ ολοκλήρου στο δικό σας υλικό.

Αυτό το playbook σάς διδάσκει πώς να ομαδοποιήσετε δύο συστήματα Ryzen AI Halo χρησιμοποιώντας RCCL (ROCm Communication Collectives Library) με το vLLM και να εκτελέσετε το Qwen3.5-397B, ένα μοντέλο με 397 δισεκατομμύρια παραμέτρους, σε αμφότερα τα μηχανήματα με επιτάχυνση ROCm.

## Τι Θα Μάθετε

- Πώς να επεκτείνετε την εκχώρηση VRAM σε συστήματα Ryzen AI Halo
- Εκκίνηση του vLLM με υποστήριξη ROCm
- Ρύθμιση του RCCL για πολυκομβικό tensor-parallel inference σε δύο συστήματα Ryzen AI Halo
- Εκτέλεση ενός μοντέλου 397 δισεκατομμυρίων παραμέτρων σε δύο δικτυωμένα συστήματα Ryzen AI Halo

## Προαπαιτούμενα

### Υλικό

Αυτό το playbook απαιτεί δύο μονάδες Ryzen AI Halo και έναν διακόπτη Ethernet, συνδεδεμένα σε τοπολογία αστέρα με κάθε μονάδα καλωδιωμένη απευθείας στον διακόπτη.

| Στοιχείο | Ποσότητα | Περιγραφή |

## Φυσική Ρύθμιση Υλικού

> **Σημείωση**: Ολοκληρώστε αυτό το βήμα τόσο στο Μηχάνημα 1 όσο και στο Μηχάνημα 2.

Συνδέστε κάθε μονάδα Ryzen AI Halo στον διακόπτη Ethernet χρησιμοποιώντας καλώδιο Cat 7 (ή ανώτερο). Αυτό δημιουργεί τη σύνδεση 10Gbps που χρησιμοποιείται για επικοινωνία υψηλής ταχύτητας μεταξύ των κόμβων.

### 1. Προσδιορισμός Διεπαφών Δικτύου

Σε κάθε μηχάνημα, βρείτε το όνομα της διεπαφής δικτύου του και σημειώστε το (θα αναφέρεται στο υπόλοιπο των οδηγιών ως `IFNAME`). Εκτελέστε:

```bash
ip route get 1.1.1.1 | grep -oP 'dev \K\S+'
```

Αυτό εκτυπώνει απευθείας το όνομα της διεπαφής, για παράδειγμα:

```bash
enp191s0
```

### 2. Επαλήθευση Ταχυτήτων Σύνδεσης Δικτύου

Επιβεβαιώστε ότι η σύνδεση είναι ενεργή και λειτουργεί στην πλήρη ταχύτητα ελέγχοντας την ταχύτητα της διεπαφής σας:

```bash
sudo ethtool <IFNAME> | grep Speed
```

> **Σημείωση**: Αντικαταστήστε το `<IFNAME>` με το όνομα της διεπαφής εξόδου από [1. Προσδιορισμός Διεπαφών Δικτύου](#1-determine-network-interfaces)

Θα πρέπει να δείτε ταχύτητα `10000Mb/s`:

```bash
	Speed: 10000Mb/s
```

> **Σημείωση**: Αν η ταχύτητα είναι χαμηλότερη από `10000Mb/s` ή η σύνδεση δεν ενεργοποιείται, ελέγξτε τη σύνδεση του καλωδίου και επιβεβαιώστε ότι η θύρα του διακόπτη έχει ρυθμιστεί στα 10Gbps. Ορισμένοι διακόπτες απαιτούν την απενεργοποίηση της αυτόματης διαπραγμάτευσης και τον χειροκίνητο καθορισμό της ταχύτητας σύνδεσης· ανατρέξτε στην τεκμηρίωση του διακόπτη σας.

## Επέκταση Εκχώρησης VRAM

### Ρύθμιση Μνήμης για Εκτέλεση Μεγάλων Μοντέλων

Στο Linux, το ROCm χρησιμοποιεί μια κοινόχρηστη δεξαμενή μνήμης συστήματος, και αυτή η δεξαμενή είναι ρυθμισμένη από προεπιλογή στο μισό της μνήμης του συστήματος.

Αυτό το ποσό μπορεί να αυξηθεί αλλάζοντας τη ρύθμιση σελίδας του Translation Table Manager (TTM) του πυρήνα, με τις ακόλουθες οδηγίες. Η AMD συνιστά τη ρύθμιση της ελάχιστης αποκλειστικής VRAM στο BIOS (0.5 GB).

* Εγκαταστήστε το εργαλείο pipx και προσθέστε τη διαδρομή για τα εγκατεστημένα wheels του pipx στη διαδρομή αναζήτησης του συστήματος.

  ```bash
  sudo apt install pipx
  pipx ensurepath
  ```

* Εγκαταστήστε το wheel amd-debug-tools από το PyPI.
  ```bash
  pipx install amd-debug-tools
  ```

* Εκτελέστε το εργαλείο amd-ttm για να ερωτήσετε τις τρέχουσες ρυθμίσεις για κοινόχρηστη μνήμη.
  ```bash
  amd-ttm
  ```

* Επαναρυθμίστε τις ρυθμίσεις κοινόχρηστης μνήμης στα **120 GB**:
  ```bash
  amd-ttm --set 120
  ```

* Επανεκκινήστε το σύστημα για να τεθούν σε ισχύ οι αλλαγές.

## Αρχικοποίηση Container vLLM

> **Σημείωση**: Ολοκληρώστε αυτό το βήμα τόσο στο Μηχάνημα 1 όσο και στο Μηχάνημα 2.

Το Ryzen AI Halo σας διατίθεται με το vLLM συσκευασμένο μέσα σε μια προδημιουργημένη εικόνα container, την οποία εκτελείτε χρησιμοποιώντας το Podman, ένα δωρεάν εργαλείο container ανοιχτού κώδικα.

### 1. Δημιουργία του Καταλόγου Λήψης Μοντέλων

Όταν εξυπηρετείτε το μοντέλο Qwen3.5-397B σε αυτό το playbook, το vLLM θα κατεβάσει αυτόματα τα βάρη του μοντέλου στο σύστημά σας. Για να βεβαιωθείτε ότι αυτά τα βάρη είναι προσβάσιμα από μέσα στο container, δημιουργήστε πρώτα έναν κατάλογο μοντέλων που μπορεί να προσαρτήσει το container:

```bash
mkdir -p ~/.local/share/vLLM/models
```

### 2. Εκκίνηση του Container vLLM

Η παρακάτω εντολή εκκινεί το container και σας μεταφέρει σε ένα διαδραστικό κέλυφος. Προσαρτά τον κατάλογο μοντέλων που μόλις δημιουργήσατε και περνά το `IFNAME` σας στα `NCCL_SOCKET_IFNAME` και `GLOO_SOCKET_IFNAME`, ενημερώνοντας το RCCL (η βιβλιοθήκη που χρησιμοποιεί το vLLM για να συντονίζει τα GPU σε όλη την ομάδα) ποια διεπαφή να χρησιμοποιήσει.

Ξεκινήστε το container με:

```bash
sudo podman run -it --name vllm_cluster --replace --pull missing --network=host --device /dev/kfd --device /dev/dri -v ~/.local/share/vLLM/models:/opt/vLLM/models --env HF_HOME=/opt/vLLM/models --entrypoint="bin/bash" --shm-size=64g --pids-limit=-1 -e NCCL_SOCKET_IFNAME=<IFNAME> -e GLOO_SOCKET_IFNAME=<IFNAME> oci-registry.ryai.dev/ryai-vllm:latest
```

> **Σημείωση**: Αντικαταστήστε το `<IFNAME>` με το όνομα της διεπαφής εξόδου από [1. Προσδιορισμός Διεπαφών Δικτύου](#1-determine-network-interfaces)

## Εκτέλεση του Μοντέλου στην Ομάδα (Cluster)

Το vLLM χρησιμοποιεί το Ray για την οργάνωση της ομάδας και το RCCL για τη διαχείριση της επικοινωνίας GPU-προς-GPU μεταξύ κόμβων. Ένα μηχάνημα λειτουργεί ως ο **κόμβος-κεφαλή** (head node) (Μηχάνημα 1), συντονίζοντας το inference. Το άλλο εντάσσεται ως **κόμβος-εργάτης** (worker node) (Μηχάνημα 2), συνεισφέροντας τη μνήμη GPU και την υπολογιστική ισχύ του.

> **Σημείωση**: Το Ray είναι μια προαιρετική εξάρτηση για το vLLM και είναι διαθέσιμο μόνο μέσα από το προδιαμορφωμένο container Podman.

Κατά την εκκίνηση, το vLLM κατακερματίζει (shards) το μοντέλο σε αμφότερους τους κόμβους χρησιμοποιώντας tensor parallelism. Μόλις φορτωθεί, το inference προχωρά σαν να εκτελείται σε έναν μόνο επιταχυντή.

#### Αποτροπή Σφαλμάτων OOM του Ray

Από προεπιλογή, το Ray παρακολουθεί τη μνήμη του κεντρικού υπολογιστή σε κάθε κόμβο και τερματίζει τη μεγαλύτερη διεργασία όταν η χρήση μνήμης ξεπερνά το 95%. Στο Ryzen™ AI Halo σας, το GPU και ο κεντρικός υπολογιστής μοιράζονται μία δεξαμενή μνήμης, οπότε η φόρτωση ενός μοντέλου μπορεί να προκαλέσει ένα `ray.exceptions.OutOfMemoryError` και να τερματίσει τη διεργασία worker.

Για να το αποτρέψουμε αυτό, θα εξάγουμε (export) `RAY_memory_monitor_refresh_ms=0` σε κάθε μηχάνημα πριν από την εκκίνηση και την ένταξη στην ομάδα.
### Βήμα 1: Εκκίνηση του Ray Head Node (Machine 1)

Στο Machine 1, εκκινήστε τον κόμβο-κεφαλή Ray (head node) για να αρχικοποιήσετε το cluster:

```bash
export RAY_memory_monitor_refresh_ms=0
ray start --head --port=6379 --node-ip-address=<MACHINE_1_IP> --num-gpus=1
```

> **Εύρεση `<MACHINE_1_IP>`**: Στο Machine 1, εκτελέστε `hostname -I | awk '{print $1}'` για να βρείτε τη τοπική του διεύθυνση IP.

### Βήμα 2: Συμμετοχή στο Cluster (Machine 2)

Στο Machine 2, συνδεθείτε στον κόμβο-κεφαλή για να σχηματίσετε το cluster:

```bash
export RAY_memory_monitor_refresh_ms=0
ray start --address=<MACHINE_1_IP>:6379 --node-ip-address=<MACHINE_2_IP> --num-gpus=1
```

> **Εύρεση `<MACHINE_2_IP>`**: Στο Machine 2, εκτελέστε `hostname -I | awk '{print $1}'` για να βρείτε τη τοπική του διεύθυνση IP.

### Βήμα 3: Εξυπηρέτηση του Μοντέλου (Machine 1)

Στο Machine 1, εκκινήστε τον διακομιστή vLLM. Αυτό θα κατεβάσει αυτόματα το μοντέλο και θα ξεκινήσει την εξυπηρέτησή του και στους δύο κόμβους:

```bash
vllm serve Qwen/Qwen3.5-397B-A17B-GPTQ-Int4 \
  --port 7000 \
  --host 0.0.0.0 \
  --max-model-len 32768 \
  --gpu-memory-utilization 0.9 \
  --dtype float16 \
  --tensor-parallel-size 2 \
  --distributed-executor-backend ray \
  --enforce-eager \
  --language-model-only \
  --reasoning-parser qwen3
```

#### Αναφορά Παραμέτρων

| Σημαία | Σκοπός |
|------|---------|
| `--port` | Θύρα εξυπηρέτησης του HTTP API |
| `--host` | Διεύθυνση IP στην οποία θα συνδεθεί ο διακομιστής (`0.0.0.0` για όλα τα interfaces) |
| `--max-model-len` | Μέγιστο μήκος περιβάλλοντος σε tokens |
| `--gpu-memory-utilization` | Ποσοστό μνήμης GPU προς εκχώρηση (0.0–1.0) |
| `--dtype` | Τύπος δεδομένων για τα βάρη του μοντέλου |
| `--tensor-parallel-size` | Αριθμός GPU στα οποία θα κατανεμηθεί το μοντέλο (ορίστε τον συνολικό αριθμό GPU στο cluster) |
| `--distributed-executor-backend` | Backend για εκτέλεση σε πολλαπλούς κόμβους (`ray` για αναπτύξεις cluster) |
| `--enforce-eager` | Απενεργοποιεί τη μεταγλώττιση CUDA graph για συμβατότητα |
| `--language-model-only` | Παραλείπει τη φόρτωση βοηθητικών στοιχείων του μοντέλου (π.χ. vision encoder) |
| `--reasoning-parser` | Ενεργοποιεί τη δομημένη ανάλυση εξόδου συλλογιστικής (reasoning) για το μοντέλο |

Για την πλήρη χρήση των παραμέτρων, ανατρέξτε στην [τεκμηρίωση vLLM](https://docs.vllm.ai/en/latest/configuration/engine_args/).

## Πρόσβαση στο Μοντέλο

Το vLLM εκθέτει ένα API συμβατό με OpenAI, οπότε μπορείτε να συνδέσετε οποιονδήποτε συμβατό client ή περιβάλλον στο cluster σας. Μια δημοφιλής επιλογή είναι το [Open WebUI](https://github.com/open-webui/open-webui), το οποίο παρέχει ένα περιβάλλον συνομιλίας μέσω browser.

Για να συνδέσετε το Open WebUI στο endpoint του vLLM σας:

1. Ανοίξτε **Settings** > **Admin Panel** > **Connections**
2. Κάντε κλικ στο **+** στο **Manage OpenAI API Connections**
3. Ορίστε το **Connection Type** σε **External**
4. Ορίστε το **URL** σε `http://<MACHINE_1_IP>:7000/v1`
5. Κάτω από το **Auth**, επιλέξτε **None** από το αναπτυσσόμενο μενού
6. Αφήστε το πεδίο **Model IDs** κενό για αυτόματη ανακάλυψη όλων των μοντέλων από το endpoint

> **Εύρεση `<MACHINE_1_IP>`**: Στο Machine 1, εκτελέστε `hostname -I | awk '{print $1}'` για να βρείτε τη τοπική του διεύθυνση IP. Αν αποκτάτε πρόσβαση στο Open WebUI από το ίδιο το Machine 1, μπορείτε να χρησιμοποιήσετε `http://localhost:7000/v1`.

![Ρυθμίσεις σύνδεσης Open WebUI για το endpoint vLLM](assets/openwebui-connection.png)

Μόλις συνδεθείτε, επιλέξτε το μοντέλο από το αναπτυσσόμενο μενού μοντέλων στο Open WebUI και ξεκινήστε τη συνομιλία. Το μοντέλο τώρα εκτελείται και στους δύο κόμβους Ryzen AI Halo:

## Επόμενα Βήματα

- **Εξερευνήστε άλλα μοντέλα**: Ανακαλύψτε νέα μοντέλα στο [Hugging Face](https://huggingface.co/models?&sort=trending) που ταιριάζουν στη συνολική μνήμη GPU του cluster σας
- **Επεκταθείτε σε τέσσερις κόμβους**: Προσθέστε δύο ακόμη συστήματα Ryzen AI Halo ως επιπλέον Ray workers για να κατανείμετε τα μοντέλα σε ακόμη περισσότερα GPU. Αυτό απαιτεί έναν διακόπτη Ethernet με τουλάχιστον τέσσερις θύρες, μία για κάθε κόμβο. Ακολουθήστε το [Βήμα 2: Συμμετοχή στο Cluster](#step-2-join-the-cluster-machine-2) σε κάθε επιπλέον worker και αυξήστε ανάλογα το `--tensor-parallel-size`
- **Δοκιμάστε άλλες στρατηγικές παραλληλισμού**: Το vLLM υποστηρίζει [expert parallel](https://docs.vllm.ai/en/latest/serving/expert_parallel_deployment/) για μοντέλα mixture-of-experts και [data parallel](https://docs.vllm.ai/en/latest/serving/data_parallel_deployment/) για υψηλότερη απόδοση. Πειραματιστείτε με τα `--enable-expert-parallel` και `--data-parallel-size` για να βρείτε τη βέλτιστη διαμόρφωση για τον φόρτο εργασίας σας
