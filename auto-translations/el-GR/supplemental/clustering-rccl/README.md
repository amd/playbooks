# Σύνδεση δύο Ryzen™ AI Halo σε Cluster με RCCL

## Επισκόπηση

Το Ryzen™ AI Halo σας είναι ήδη ικανό να εκτελεί μεγάλα γλωσσικά μοντέλα τοπικά. Η δημιουργία cluster προχωρά ένα βήμα παραπέρα, συνδυάζοντας τη μνήμη GPU πολλαπλών συστημάτων μέσω τοπικού δικτύου, δίνοντάς σας πρόσβαση σε ακόμα μεγαλύτερα μοντέλα με ισχυρότερη συλλογιστική, καλύτερη δημιουργία κώδικα και βαθύτερη πολύγλωσση κατανόηση, όλα εξ ολοκλήρου στο δικό σας υλικό.

Αυτό το playbook σάς διδάσκει πώς να συνδέσετε δύο συστήματα Ryzen AI Halo σε cluster χρησιμοποιώντας RCCL (ROCm Communication Collectives Library) με vLLM και να εκτελέσετε το Qwen3.5-397B, ένα μοντέλο 397B παραμέτρων, και στις δύο μηχανές με επιτάχυνση ROCm.

## Τι θα Μάθετε

- Πώς να επεκτείνετε την κατανομή VRAM σε συστήματα Ryzen AI Halo
- Εκκίνηση vLLM με υποστήριξη ROCm
- Διαμόρφωση RCCL για παράλληλη εκτέλεση tensor σε πολλαπλούς κόμβους μεταξύ δύο συστημάτων Ryzen AI Halo
- Εκτέλεση μοντέλου 397B παραμέτρων σε δύο δικτυωμένα συστήματα Ryzen AI Halo

## Προαπαιτούμενα

### Υλικό

Αυτό το playbook απαιτεί δύο μονάδες Ryzen AI Halo και έναν διακόπτη Ethernet, συνδεδεμένους σε τοπολογία αστέρα με κάθε μονάδα καλωδιωμένη απευθείας στον διακόπτη.

| Εξάρτημα | Ποσότητα | Περιγραφή |
|-----------|----------|-------------|
| Ryzen AI Halo | 2 | Κόμβοι υπολογισμού που αποτελούν το cluster |
| Διακόπτης Ethernet 10Gbps | 1 | Κεντρικός διακόπτης για επικοινωνία μεταξύ πολλαπλών κόμβων Ryzen AI Halo (τουλάχιστον 2 θύρες) |
| Καλώδιο Ethernet | 2 | Συνδέει κάθε μονάδα Halo στον διακόπτη (συνιστάται Cat 7 ή υψηλότερο) |

> **Σημείωση**: Απαιτούνται δύο θύρες διακόπτη Ethernet για τη σύνδεση των δύο μονάδων Ryzen AI Halo. Απαιτείται τρίτη θύρα εάν αποκτάτε πρόσβαση στο μοντέλο από ξεχωριστή μηχανή-πελάτη αντί από μία από τις μονάδες Halo.

## Φυσική Εγκατάσταση Υλικού

> **Σημείωση**: Ολοκληρώστε αυτό το βήμα και στη Μηχανή 1 και στη Μηχανή 2.

Συνδέστε κάθε μονάδα Ryzen AI Halo στον διακόπτη Ethernet χρησιμοποιώντας καλώδιο Cat 7 (ή υψηλότερο). Αυτό δημιουργεί τη σύνδεση 10Gbps που χρησιμοποιείται για υψηλής ταχύτητας επικοινωνία μεταξύ των κόμβων.

### 1. Προσδιορισμός Διεπαφών Δικτύου

Σε κάθε μηχανή, βρείτε το όνομα της διεπαφής δικτύου της και σημειώστε το (θα αναφέρεται στο υπόλοιπο των οδηγιών ως `IFNAME`). Εκτελέστε:

```bash
ip route get 1.1.1.1 | grep -oP 'dev \K\S+'
```

Αυτό εκτυπώνει απευθείας το όνομα της διεπαφής, για παράδειγμα:

```bash
enp191s0
```

### 2. Επαλήθευση Ταχυτήτων Σύνδεσης Δικτύου

Επιβεβαιώστε ότι η σύνδεση είναι ενεργή και λειτουργεί στην πλήρη ταχύτητά της ελέγχοντας την ταχύτητα της διεπαφής σας:

```bash
sudo ethtool <IFNAME> | grep Speed
```

> **Σημείωση**: Αντικαταστήστε το `<IFNAME>` με το όνομα διεπαφής εξόδου από το [1. Προσδιορισμός Διεπαφών Δικτύου](#1-determine-network-interfaces)

Θα πρέπει να δείτε ταχύτητα `10000Mb/s`:

```bash
	Speed: 10000Mb/s
```

> **Σημείωση**: Εάν η ταχύτητα είναι χαμηλότερη από `10000Mb/s` ή η σύνδεση δεν ενεργοποιείται, ελέγξτε τη σύνδεση του καλωδίου και επιβεβαιώστε ότι η θύρα του διακόπτη έχει ρυθμιστεί στα 10Gbps. Ορισμένοι διακόπτες απαιτούν απενεργοποίηση της αυτόματης διαπραγμάτευσης και χειροκίνητη ρύθμιση της ταχύτητας σύνδεσης· ανατρέξτε στην τεκμηρίωση του διακόπτη σας.

## Επέκταση Κατανομής VRAM

> **Σημείωση**: Ολοκληρώστε αυτό το βήμα και στη Μηχανή 1 και στη Μηχανή 2.

### Διαμόρφωση Μνήμης για Εκτέλεση Μεγάλων Μοντέλων

Στο Linux, το ROCm χρησιμοποιεί ένα κοινόχρηστο σύνολο μνήμης συστήματος, και αυτό το σύνολο διαμορφώνεται από προεπιλογή στο μισό της μνήμης συστήματος.

Αυτό το ποσό μπορεί να αυξηθεί αλλάζοντας τη ρύθμιση σελίδας Translation Table Manager (TTM) του πυρήνα, με τις παρακάτω οδηγίες. Η AMD συνιστά να ορίσετε την ελάχιστη αποκλειστική VRAM στο BIOS (0,5 GB).

* Εγκαταστήστε το βοηθητικό πρόγραμμα pipx και προσθέστε τη διαδρομή για τους τροχούς που εγκαθίστανται από το pipx στη διαδρομή αναζήτησης του συστήματος.

  ```bash
  sudo apt install pipx
  pipx ensurepath
  ```

* Εγκαταστήστε τον τροχό amd-debug-tools από το PyPI.
  ```bash
  pipx install amd-debug-tools
  ```

* Εκτελέστε το εργαλείο amd-ttm για να υποβάλετε ερώτημα σχετικά με τις τρέχουσες ρυθμίσεις κοινόχρηστης μνήμης.
  ```bash
  amd-ttm
  ```

* Επαναδιαμορφώστε τις ρυθμίσεις κοινόχρηστης μνήμης σε **120 GB**:
  ```bash
  amd-ttm --set 120
  ```

* Επανεκκινήστε το σύστημα για να τεθούν σε ισχύ οι αλλαγές.

## Αρχικοποίηση Container vLLM

> **Σημείωση**: Ολοκληρώστε αυτό το βήμα και στη Μηχανή 1 και στη Μηχανή 2.

Το Ryzen AI Halo σας παρέχεται με το vLLM συσκευασμένο μέσα σε μια προκατασκευασμένη εικόνα container, την οποία εκτελείτε χρησιμοποιώντας το Podman, ένα δωρεάν και ανοιχτού κώδικα εργαλείο container.

### 1. Δημιουργία Καταλόγου Λήψης Μοντέλου

Όταν εξυπηρετείτε το μοντέλο Qwen3.5-397B σε αυτό το playbook, το vLLM θα κατεβάσει αυτόματα τα βάρη του μοντέλου στο σύστημά σας. Για να βεβαιωθείτε ότι αυτά τα βάρη είναι προσβάσιμα από το εσωτερικό του container, δημιουργήστε πρώτα έναν κατάλογο μοντέλων που μπορεί να προσαρτήσει το container:

```bash
mkdir -p ~/.local/share/vLLM/models
```

### 2. Εκκίνηση του Container vLLM

Η παρακάτω εντολή εκκινεί το container και σας ρίχνει σε ένα διαδραστικό κέλυφος. Προσαρτά τον κατάλογο μοντέλων που μόλις δημιουργήσατε και περνά το `IFNAME` σας στα `NCCL_SOCKET_IFNAME` και `GLOO_SOCKET_IFNAME`, ενημερώνοντας το RCCL (τη βιβλιοθήκη που χρησιμοποιεί το vLLM για τον συντονισμό GPU σε όλο το cluster) ποια διεπαφή να χρησιμοποιήσει.

Εκκινήστε το container με:

```bash
sudo podman run -it --name vllm_cluster --replace --pull missing --network=host --device /dev/kfd --device /dev/dri -v ~/.local/share/vLLM/models:/opt/vLLM/models --env HF_HOME=/opt/vLLM/models --entrypoint="bin/bash" --shm-size=64g -e NCCL_SOCKET_IFNAME=<IFNAME> -e GLOO_SOCKET_IFNAME=<IFNAME> oci-registry.ryai.dev/ryai-vllm:latest
```

> **Σημείωση**: Αντικαταστήστε το `<IFNAME>` με το όνομα διεπαφής εξόδου από το [1. Προσδιορισμός Διεπαφών Δικτύου](#1-determine-network-interfaces)

## Εκτέλεση του Μοντέλου στο Cluster

Το vLLM χρησιμοποιεί το Ray για την ενορχήστρωση του cluster και το RCCL για τη διαχείριση της επικοινωνίας GPU-προς-GPU μεταξύ κόμβων. Μία μηχανή λειτουργεί ως **κόμβος κεφαλής** (Μηχανή 1), συντονίζοντας την εκτέλεση. Η άλλη συμμετέχει ως **κόμβος εργαζόμενου** (Μηχανή 2), συνεισφέροντας τη μνήμη GPU και την υπολογιστική ισχύ της.

> **Σημείωση**: Το Ray είναι προαιρετική εξάρτηση για το vLLM και είναι διαθέσιμο μόνο από το εσωτερικό του προδιαμορφωμένου container Podman.

Κατά την εκκίνηση, το vLLM κατανέμει το μοντέλο και στους δύο κόμβους χρησιμοποιώντας παραλληλισμό tensor. Μόλις φορτωθεί, η εκτέλεση προχωρά σαν να εκτελείται σε έναν μόνο επιταχυντή.

### Βήμα 1: Εκκίνηση του Κόμβου Κεφαλής Ray (Μηχανή 1)

Στη Μηχανή 1, εκκινήστε τον κόμβο κεφαλής Ray για να αρχικοποιήσετε το cluster:

```bash
ray start --head --port=6379 --node-ip-address=<MACHINE_1_IP> --num-gpus=1
```

> **Εύρεση `<MACHINE_1_IP>`**: Στη Μηχανή 1, εκτελέστε `hostname -I | awk '{print $1}'` για να βρείτε την τοπική διεύθυνση IP της.

### Βήμα 2: Σύνδεση στο Cluster (Μηχανή 2)

Στη Μηχανή 2, συνδεθείτε στον κόμβο κεφαλής για να σχηματίσετε το cluster:

```bash
ray start --address=<MACHINE_1_IP>:6379 --node-ip-address=<MACHINE_2_IP> --num-gpus=1
```

> **Εύρεση `<MACHINE_2_IP>`**: Στη Μηχανή 2, εκτελέστε `hostname -I | awk '{print $1}'` για να βρείτε την τοπική διεύθυνση IP της.

### Βήμα 3: Εξυπηρέτηση του Μοντέλου (Μηχανή 1)

Στη Μηχανή 1, εκκινήστε τον διακομιστή vLLM. Αυτό θα κατεβάσει αυτόματα το μοντέλο και θα αρχίσει να το εξυπηρετεί και στους δύο κόμβους:

```bash
vllm serve Qwen/Qwen3.5-397B-A17B-GPTQ-Int4 \
  --port 7000 \
  --host 0.0.0.0 \
  --max-model-len 32768 \
  --gpu-memory-utilization 0.9 \
  --dtype float16 \
  --tensor-parallel-size 2 \
  --distributed-executor-backend ray \
  --enforce-eager \
  --language-model-only \
  --reasoning-parser qwen3
```

#### Αναφορά Παραμέτρων

| Σημαία | Σκοπός |
|------|---------|
| `--port` | Θύρα για εξυπηρέτηση του HTTP API |
| `--host` | Διεύθυνση IP για δέσμευση του διακομιστή (`0.0.0.0` για όλες τις διεπαφές) |
| `--max-model-len` | Μέγιστο μήκος περιβάλλοντος σε tokens |
| `--gpu-memory-utilization` | Κλάσμα μνήμης GPU για κατανομή (0,0–1,0) |
| `--dtype` | Τύπος δεδομένων για τα βάρη του μοντέλου |
| `--tensor-parallel-size` | Αριθμός GPU για κατανομή του μοντέλου (ορίστε στο σύνολο των GPU στο cluster) |
| `--distributed-executor-backend` | Backend για εκτέλεση σε πολλαπλούς κόμβους (`ray` για αναπτύξεις cluster) |
| `--enforce-eager` | Απενεργοποιεί τη μεταγλώττιση γραφήματος CUDA για συμβατότητα |
| `--language-model-only` | Παραλείπει τη φόρτωση βοηθητικών στοιχείων μοντέλου (π.χ., κωδικοποιητής όρασης) |
| `--reasoning-parser` | Ενεργοποιεί δομημένη ανάλυση εξόδου συλλογιστικής για το μοντέλο |

Για πλήρη χρήση παραμέτρων, ανατρέξτε στην [τεκμηρίωση vLLM](https://docs.vllm.ai/en/latest/configuration/engine_args/).

## Πρόσβαση στο Μοντέλο

Το vLLM εκθέτει ένα API συμβατό με OpenAI, οπότε μπορείτε να συνδέσετε οποιοδήποτε συμβατό πρόγραμμα-πελάτη ή διεπαφή στο cluster σας. Μια δημοφιλής επιλογή είναι το [Open WebUI](https://github.com/open-webui/open-webui), που παρέχει διεπαφή συνομιλίας μέσω προγράμματος περιήγησης.

Για να συνδέσετε το Open WebUI στο endpoint vLLM σας:

1. Ανοίξτε **Ρυθμίσεις** > **Πίνακας Διαχειριστή** > **Συνδέσεις**
2. Κάντε κλικ στο **+** στο **Διαχείριση Συνδέσεων OpenAI API**
3. Ορίστε τον **Τύπο Σύνδεσης** σε **Εξωτερικός**
4. Ορίστε τη **Διεύθυνση URL** σε `http://<MACHINE_1_IP>:7000/v1`
5. Στο **Έλεγχος Ταυτότητας**, επιλέξτε **Κανένας** από το αναπτυσσόμενο μενού
6. Αφήστε τα **Αναγνωριστικά Μοντέλου** κενά για αυτόματη ανακάλυψη όλων των μοντέλων από το endpoint

> **Εύρεση `<MACHINE_1_IP>`**: Στη Μηχανή 1, εκτελέστε `hostname -I | awk '{print $1}'` για να βρείτε την τοπική διεύθυνση IP της. Εάν αποκτάτε πρόσβαση στο Open WebUI από την ίδια τη Μηχανή 1, μπορείτε να χρησιμοποιήσετε `http://localhost:7000/v1`.

Μόλις συνδεθείτε, επιλέξτε το μοντέλο από το αναπτυσσόμενο μενού μοντέλων στο Open WebUI και ξεκινήστε τη συνομιλία. Το μοντέλο εκτελείται τώρα και στους δύο κόμβους Ryzen AI Halo σας:

![Συνομιλία με το Qwen3.5-397B στο Open WebUI](assets/openwebui-chat.png)

## Επόμενα Βήματα

- **Εξερευνήστε άλλα μοντέλα**: Ανακαλύψτε νέα μοντέλα στο [Hugging Face](https://huggingface.co/models?&sort=trending) που χωράνε στη συνδυασμένη μνήμη GPU του cluster σας
- **Κλιμάκωση σε τέσσερις κόμβους**: Προσθέστε δύο ακόμα συστήματα Ryzen AI Halo ως επιπλέον εργαζόμενους Ray για κατανομή μοντέλων σε ακόμα περισσότερες GPU. Αυτό απαιτεί διακόπτη Ethernet με τουλάχιστον τέσσερις θύρες, μία για κάθε κόμβο. Ακολουθήστε το [Βήμα 2: Σύνδεση στο Cluster](#step-2-join-the-cluster-machine-2) σε κάθε επιπλέον εργαζόμενο και αυξήστε ανάλογα το `--tensor-parallel-size`
- **Δοκιμάστε άλλες στρατηγικές παραλληλισμού**: Το vLLM υποστηρίζει [παράλληλο ειδικό](https://docs.vllm.ai/en/latest/serving/expert_parallel_deployment/) για μοντέλα mixture-of-experts και [παράλληλο δεδομένων](https://docs.vllm.ai/en/latest/serving/data_parallel_deployment/) για υψηλότερη απόδοση. Πειραματιστείτε με `--enable-expert-parallel` και `--data-parallel-size` για να βρείτε την καλύτερη διαμόρφωση για το φόρτο εργασίας σας
