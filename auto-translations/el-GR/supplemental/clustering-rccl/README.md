# Δημιουργία Cluster με Δύο Ryzen™ AI Halo χρησιμοποιώντας RCCL

## Επισκόπηση

Το Ryzen™ AI Halo σας είναι ήδη ικανό να εκτελεί μεγάλα γλωσσικά μοντέλα τοπικά. Η δημιουργία cluster πηγαίνει αυτό ένα βήμα παραπέρα, συνδυάζοντας τη μνήμη GPU πολλαπλών συστημάτων μέσω τοπικού δικτύου, δίνοντάς σας πρόσβαση σε ακόμα μεγαλύτερα μοντέλα με ισχυρότερη ικανότητα συλλογισμού, καλύτερη παραγωγή κώδικα και βαθύτερη πολυγλωσσική κατανόηση, εξ ολοκλήρου στο δικό σας υλικό.

Αυτό το playbook σας διδάσκει πώς να δημιουργήσετε cluster δύο συστημάτων Ryzen AI Halo χρησιμοποιώντας το RCCL (ROCm Communication Collectives Library) με vLLM και να εκτελέσετε το Qwen3.5-397B, ένα μοντέλο 397 δισεκατομμυρίων παραμέτρων, σε αμφότερα τα μηχανήματα με επιτάχυνση ROCm.

## Τι Θα Μάθετε

- Πώς να επεκτείνετε την κατανομή VRAM σε συστήματα Ryzen AI Halo
- Εκκίνηση του vLLM με υποστήριξη ROCm
- Διαμόρφωση του RCCL για συμπερασμό tensor-parallel πολλαπλών κόμβων σε δύο συστήματα Ryzen AI Halo
- Εκτέλεση ενός μοντέλου 397 δισεκατομμυρίων παραμέτρων σε δύο διασυνδεδεμένα συστήματα Ryzen AI Halo

## Προαπαιτούμενα

### Υλικό

Αυτό το playbook απαιτεί δύο μονάδες Ryzen AI Halo και έναν διακόπτη Ethernet, συνδεδεμένα σε τοπολογία αστέρα με κάθε μονάδα καλωδιωμένη απευθείας στον διακόπτη.

| Στοιχείο | Ποσότητα | Περιγραφή |

| Καλώδιο Ethernet | 2 | Συνδέει κάθε μονάδα Halo με τον διακόπτη (συνιστάται Cat 7 ή υψηλότερο) |

> **Σημείωση**: Απαιτούνται δύο θύρες διακόπτη Ethernet για τη σύνδεση των δύο μονάδων Ryzen AI Halo. Απαιτείται τρίτη θύρα εάν έχετε πρόσβαση στο μοντέλο από ξεχωριστό μηχάνημα-πελάτη αντί από μία από τις μονάδες Halo.

## Ρύθμιση Φυσικού Υλικού

> **Σημείωση**: Ολοκληρώστε αυτό το βήμα τόσο στο Μηχάνημα 1 όσο και στο Μηχάνημα 2.

Συνδέστε κάθε μονάδα Ryzen AI Halo στον διακόπτη Ethernet χρησιμοποιώντας καλώδιο Cat 7 (ή υψηλότερο). Αυτό δημιουργεί τη σύνδεση 10Gbps που χρησιμοποιείται για επικοινωνία υψηλής ταχύτητας μεταξύ των κόμβων.

### 1. Προσδιορισμός Διεπαφών Δικτύου

Σε κάθε μηχάνημα, βρείτε το όνομα της διεπαφής δικτύου του και σημειώστε το (θα αναφέρεται στο υπόλοιπο των οδηγιών ως `IFNAME`). Εκτελέστε:

```bash
ip route get 1.1.1.1 | grep -oP 'dev \K\S+'
```

Αυτό εκτυπώνει απευθείας το όνομα της διεπαφής, για παράδειγμα:

```bash
enp191s0
```

### 2. Επαλήθευση Ταχυτήτων Σύνδεσης Δικτύου

Επιβεβαιώστε ότι η σύνδεση είναι ενεργή και λειτουργεί στην πλήρη ταχύτητα ελέγχοντας την ταχύτητα της διεπαφής σας:

```bash
sudo ethtool <IFNAME> | grep Speed
```

> **Σημείωση**: Αντικαταστήστε το `<IFNAME>` με το όνομα διεπαφής εξόδου από το [1. Προσδιορισμός Διεπαφών Δικτύου](#1-determine-network-interfaces)

Θα πρέπει να δείτε ταχύτητα `10000Mb/s`:

```bash
	Speed: 10000Mb/s
```

> **Σημείωση**: Εάν η ταχύτητα είναι χαμηλότερη από `10000Mb/s` ή η σύνδεση δεν ενεργοποιείται, ελέγξτε τη σύνδεση του καλωδίου και επιβεβαιώστε ότι η θύρα του διακόπτη έχει ρυθμιστεί στα 10Gbps. Ορισμένοι διακόπτες απαιτούν απενεργοποίηση της αυτόματης διαπραγμάτευσης και χειροκίνητο ορισμό της ταχύτητας σύνδεσης· ανατρέξτε στην τεκμηρίωση του διακόπτη σας.

## Επέκταση Κατανομής VRAM

> **Σημείωση**: Ολοκληρώστε αυτό το βήμα τόσο στο Μηχάνημα 1 όσο και στο Μηχάνημα 2.

### Διαμόρφωση Μνήμης για Εκτέλεση Μεγάλων Μοντέλων

Στο Linux, το ROCm χρησιμοποιεί μια κοινόχρηστη δεξαμενή μνήμης συστήματος, και αυτή η δεξαμενή είναι διαμορφωμένη από προεπιλογή στο μισό της μνήμης συστήματος.

Αυτή η ποσότητα μπορεί να αυξηθεί αλλάζοντας τη ρύθμιση σελίδας του Translation Table Manager (TTM) του πυρήνα, με τις παρακάτω οδηγίες. Η AMD συνιστά τον ορισμό της ελάχιστης αποκλειστικής VRAM στο BIOS (0.5 GB).

* Εγκαταστήστε το βοηθητικό πρόγραμμα pipx και προσθέστε τη διαδρομή για τα wheels που εγκαθιστά το pipx στη διαδρομή αναζήτησης του συστήματος.

  ```bash
  sudo apt install pipx
  pipx ensurepath
  ```

* Εγκαταστήστε το wheel amd-debug-tools από το PyPI.
  ```bash
  pipx install amd-debug-tools
  ```

* Εκτελέστε το εργαλείο amd-ttm για να ερωτήσετε τις τρέχουσες ρυθμίσεις για κοινόχρηστη μνήμη.
  ```bash
  amd-ttm
  ```

* Επαναδιαμορφώστε τις ρυθμίσεις κοινόχρηστης μνήμης σε **120 GB**:
  ```bash
  amd-ttm --set 120
  ```

* Επανεκκινήστε το σύστημα για να τεθούν σε ισχύ οι αλλαγές.

## Αρχικοποίηση Container vLLM

> **Σημείωση**: Ολοκληρώστε αυτό το βήμα τόσο στο Μηχάνημα 1 όσο και στο Μηχάνημα 2.

Το Ryzen AI Halo σας διατίθεται με το vLLM συσκευασμένο μέσα σε ένα προκατασκευασμένο container image, το οποίο εκτελείτε χρησιμοποιώντας το Podman, ένα δωρεάν εργαλείο container ανοιχτού κώδικα.

### 1. Δημιουργία του Καταλόγου Λήψης Μοντέλου

Όταν εξυπηρετείτε το μοντέλο Qwen3.5-397B σε αυτό το playbook, το vLLM θα κατεβάσει αυτόματα τα βάρη του μοντέλου στο σύστημά σας. Για να βεβαιωθείτε ότι αυτά τα βάρη είναι προσβάσιμα από μέσα στο container, δημιουργήστε πρώτα έναν κατάλογο μοντέλων που μπορεί να προσαρτήσει το container:

```bash
mkdir -p ~/.local/share/vLLM/models
```

### 2. Εκκίνηση του Container vLLM

Η παρακάτω εντολή εκκινεί το container και σας μεταφέρει σε ένα διαδραστικό shell. Προσαρτά τον κατάλογο μοντέλων που μόλις δημιουργήσατε και περνάει το `IFNAME` σας στα `NCCL_SOCKET_IFNAME` και `GLOO_SOCKET_IFNAME`, ενημερώνοντας το RCCL (τη βιβλιοθήκη που χρησιμοποιεί το vLLM για τον συντονισμό των GPU σε όλο το cluster) ποια διεπαφή να χρησιμοποιήσει.

Ξεκινήστε το container με:

```bash
sudo podman run -it --name vllm_cluster --replace --pull missing --network=host --device /dev/kfd --device /dev/dri -v ~/.local/share/vLLM/models:/opt/vLLM/models --env HF_HOME=/opt/vLLM/models --entrypoint="bin/bash" --shm-size=64g --pids-limit=-1 -e NCCL_SOCKET_IFNAME=<IFNAME> -e GLOO_SOCKET_IFNAME=<IFNAME> oci-registry.ryai.dev/ryai-vllm:latest
```

> **Σημείωση**: Αντικαταστήστε το `<IFNAME>` με το όνομα διεπαφής εξόδου από το [1. Προσδιορισμός Διεπαφών Δικτύου](#1-determine-network-interfaces)

## Εκτέλεση του Μοντέλου στο Cluster

Το vLLM χρησιμοποιεί το Ray για τον συντονισμό του cluster και το RCCL για τη διαχείριση της επικοινωνίας GPU-προς-GPU μεταξύ κόμβων. Ένα μηχάνημα λειτουργεί ως ο **κύριος κόμβος** (Μηχάνημα 1), συντονίζοντας τον συμπερασμό. Το άλλο συμμετέχει ως **κόμβος εργασίας** (Μηχάνημα 2), συνεισφέροντας τη μνήμη GPU και την υπολογιστική του ισχύ.

> **Σημείωση**: Το Ray είναι μια προαιρετική εξάρτηση για το vLLM και είναι διαθέσιμο μόνο μέσα από το προδιαμορφωμένο container Podman.

Κατά την εκκίνηση, το vLLM κατατμεί το μοντέλο σε αμφότερους τους κόμβους χρησιμοποιώντας tensor parallelism. Μόλις φορτωθεί, ο συμπερασμός προχωρά σαν να εκτελείται σε έναν μόνο επιταχυντή.

### Βήμα 1: Εκκίνηση του Κύριου Κόμβου Ray (Μηχάνημα 1)

Στο Μηχάνημα 1, ξεκινήστε τον κύριο κόμβο Ray για να αρχικοποιήσετε το cluster:

```bash
ray start --head --port=6379 --node-ip-address=<MACHINE_1_IP> --num-gpus=1
```

> **Εύρεση `<MACHINE_1_IP>`**: Στο Μηχάνημα 1, εκτελέστε `hostname -I | awk '{print $1}'` για να βρείτε τη τοπική του διεύθυνση IP.
### Βήμα 2: Συμμετοχή στο Cluster (Machine 2)

Στη Machine 2, συνδεθείτε στον head node για να σχηματίσετε το cluster:

```bash
ray start --address=<MACHINE_1_IP>:6379 --node-ip-address=<MACHINE_2_IP> --num-gpus=1
```

> **Εύρεση `<MACHINE_2_IP>`**: Στη Machine 2, εκτελέστε `hostname -I | awk '{print $1}'` για να βρείτε την τοπική της διεύθυνση IP.

### Βήμα 3: Προβολή του Μοντέλου (Machine 1)

Στη Machine 1, εκκινήστε τον vLLM server. Αυτό θα κατεβάσει αυτόματα το μοντέλο και θα ξεκινήσει να το εξυπηρετεί και στους δύο κόμβους:

```bash
vllm serve Qwen/Qwen3.5-397B-A17B-GPTQ-Int4 \
  --port 7000 \
  --host 0.0.0.0 \
  --max-model-len 32768 \
  --gpu-memory-utilization 0.9 \
  --dtype float16 \
  --tensor-parallel-size 2 \
  --distributed-executor-backend ray \
  --enforce-eager \
  --language-model-only \
  --reasoning-parser qwen3
```

#### Αναφορά Παραμέτρων

| Flag | Σκοπός |
|------|---------|
| `--port` | Θύρα εξυπηρέτησης του HTTP API |
| `--host` | Διεύθυνση IP στην οποία θα δεσμευτεί ο server (`0.0.0.0` για όλες τις διεπαφές) |
| `--max-model-len` | Μέγιστο μήκος context σε tokens |
| `--gpu-memory-utilization` | Ποσοστό μνήμης GPU προς εκχώρηση (0.0–1.0) |
| `--dtype` | Τύπος δεδομένων για τα βάρη του μοντέλου |
| `--tensor-parallel-size` | Αριθμός GPU στα οποία θα κατακερματιστεί το μοντέλο (ορίστε το στο σύνολο των GPU στο cluster) |
| `--distributed-executor-backend` | Backend για εκτέλεση πολλαπλών κόμβων (`ray` για αναπτύξεις cluster) |
| `--enforce-eager` | Απενεργοποιεί τη μεταγλώττιση CUDA graph για συμβατότητα |
| `--language-model-only` | Παραλείπει τη φόρτωση βοηθητικών στοιχείων μοντέλου (π.χ. vision encoder) |
| `--reasoning-parser` | Ενεργοποιεί τη δομημένη ανάλυση εξόδου συλλογιστικής (reasoning) για το μοντέλο |

Για την πλήρη χρήση των παραμέτρων, ανατρέξτε στην [τεκμηρίωση vLLM](https://docs.vllm.ai/en/latest/configuration/engine_args/).

## Πρόσβαση στο Μοντέλο

Το vLLM εκθέτει ένα API συμβατό με OpenAI, οπότε μπορείτε να συνδέσετε οποιονδήποτε συμβατό client ή διεπαφή στο cluster σας. Μια δημοφιλής επιλογή είναι το [Open WebUI](https://github.com/open-webui/open-webui), το οποίο παρέχει μια διεπαφή συνομιλίας βασισμένη σε browser.

Για να συνδέσετε το Open WebUI στο vLLM endpoint σας:

1. Ανοίξτε **Settings** > **Admin Panel** > **Connections**
2. Κάντε κλικ στο **+** στο **Manage OpenAI API Connections**
3. Ορίστε το **Connection Type** σε **External**
4. Ορίστε το **URL** σε `http://<MACHINE_1_IP>:7000/v1`
5. Στο **Auth**, επιλέξτε **None** από το αναπτυσσόμενο μενού
6. Αφήστε το **Model IDs** κενό για να ανακαλυφθούν αυτόματα όλα τα μοντέλα από το endpoint

> **Εύρεση `<MACHINE_1_IP>`**: Στη Machine 1, εκτελέστε `hostname -I | awk '{print $1}'` για να βρείτε την τοπική της διεύθυνση IP. Αν αποκτάτε πρόσβαση στο Open WebUI από την ίδια τη Machine 1, μπορείτε να χρησιμοποιήσετε `http://localhost:7000/v1`.

Μόλις συνδεθείτε, επιλέξτε το μοντέλο από το αναπτυσσόμενο μενού μοντέλων στο Open WebUI και ξεκινήστε να συνομιλείτε. Το μοντέλο εκτελείται πλέον και στους δύο κόμβους Ryzen AI Halo:

## Επόμενα Βήματα

- **Εξερευνήστε άλλα μοντέλα**: Ανακαλύψτε νέα μοντέλα στο [Hugging Face](https://huggingface.co/models?&sort=trending) που χωρούν στη συνδυασμένη μνήμη GPU του cluster σας
- **Κλιμάκωση σε τέσσερις κόμβους**: Προσθέστε δύο ακόμη συστήματα Ryzen AI Halo ως επιπλέον Ray workers για να κατακερματίσετε μοντέλα σε ακόμη περισσότερα GPU. Αυτό απαιτεί ένα Ethernet switch με τουλάχιστον τέσσερις θύρες, μία για κάθε κόμβο. Ακολουθήστε το [Βήμα 2: Συμμετοχή στο Cluster](#step-2-join-the-cluster-machine-2) σε κάθε επιπλέον worker και αυξήστε ανάλογα το `--tensor-parallel-size`
- **Δοκιμάστε άλλες στρατηγικές παραλληλισμού**: Το vLLM υποστηρίζει [expert parallel](https://docs.vllm.ai/en/latest/serving/expert_parallel_deployment/) για μοντέλα mixture-of-experts και [data parallel](https://docs.vllm.ai/en/latest/serving/data_parallel_deployment/) για υψηλότερη απόδοση. Πειραματιστείτε με τα `--enable-expert-parallel` και `--data-parallel-size` για να βρείτε την καλύτερη διαμόρφωση για τον φόρτο εργασίας σας
