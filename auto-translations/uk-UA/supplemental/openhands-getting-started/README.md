## Огляд

[OpenHands](https://github.com/All-Hands-AI/OpenHands) — це програмний AI-агент,
який може писати код, виконувати команди, переглядати веб-сторінки та редагувати
файли в реальному робочому середовищі. Замість того щоб копіювати пропозиції з
вікна чату, ви вказуєте агенту на теку проєкту і дозволяєте йому виконати
роботу: реалізувати функцію, виправити помилку, написати тести або пояснити
кодову базу.

[Agent Canvas](https://github.com/OpenHands/agent-canvas) — це рекомендований
браузерний інтерфейс для запуску OpenHands. Одна команда `agent-canvas` запускає
сервер агента, серверну частину автоматизації та веб-фронтенд разом, тож ви
можете вести розмову з агентом прямо з браузера.

Щоб усе залишалося на вашій системі AMD, агент спілкується з локальною моделлю,
яку обслуговує Lemonade Server. Lemonade надає доступ до цієї моделі через
API, сумісний з OpenAI, тож Agent Canvas може налаштувати її як будь-яку іншу
кінцеву точку у стилі OpenAI, а модель, ваш код і контекст розмови залишаються
на вашій машині.

У цьому посібнику ви запустите локальну модель, запустите Agent Canvas,
налаштуєте його на цю модель і виконаєте своє перше завдання з кодування на
реальній теці проєкту.

## Що ви дізнаєтеся

- Як запустити Lemonade Server і переконатися, що локальна модель відповідає на запити чату
- Як встановити та запустити Agent Canvas із пакета npm
- Як налаштувати Agent Canvas на використання локальної моделі Lemonade як LLM
- Як розпочати розмову в OpenHands і спостерігати, як агент редагує файли та виконує
  команди в робочому середовищі
- Як переглянути зміни, внесені агентом, і скеровувати його подальшими повідомленнями

## Основні поняття

| Поняття | Що це | Роль у цьому посібнику |
| --- | --- | --- |
| Lemonade Server | Локальна платформа обслуговування LLM, створена для обладнання AMD, яка надає API, сумісний з OpenAI. Ваші дані ніколи не залишають вашу машину. | Запускає модель, яка живить агента. |
| OpenHands | AI-агент, що читає та редагує файли, виконує команди оболонки та переглядає веб-сторінки в межах робочого середовища. | Агент, яким ви керуєте з чату. |
| Agent Canvas | Браузерний інтерфейс і серверна частина, що запускає розмови OpenHands та показує виклики інструментів і зміни файлів. | Запускає стек і приймає вашу розмову. |
| Робоче середовище (Workspace) | Тека проєкту, яку агенту дозволено читати та змінювати. | Ціль редагувань і команд агента. |

## 1. Запустіть Lemonade Server

Запустіть модель з CLI Lemonade:

```bash
lemonade config set llamacpp.backend=vulkan
lemonade config set ctx_size=65536
lemonade run "Qwen3.6-35B-A3B-GGUF"
```

Lemonade надає доступ до API, сумісного з OpenAI, за адресою:

```text
http://127.0.0.1:13305/api/v1
```



## 2. Перевірте локальну модель

Переконайтеся, що Lemonade може обслуговувати вибрану модель:

```bash
curl -s "http://127.0.0.1:13305/api/v1/models" | python3 -m json.tool
```

Потім надішліть невеликий запит чату:

```bash
curl -sS "http://127.0.0.1:13305/api/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "Qwen3.6-35B-A3B-GGUF",
    "messages": [
      {"role": "user", "content": "Reply with exactly: OK"}
    ],
    "temperature": 0,
    "max_tokens": 64
  }' | python3 -m json.tool
```

Якщо у відповідь повертається масив `choices`, Lemonade готовий для Agent Canvas.

## 3. Встановіть і запустіть Agent Canvas

Встановіть опублікований пакет Agent Canvas глобально:

```bash
npm install -g @openhands/agent-canvas
```

Потім запустіть повний стек із терміналу:

```bash
agent-canvas
```

За замовчуванням Agent Canvas запускається на `http://localhost:8000`.
Відкрийте цю адресу у вашому браузері. Якщо порт 8000 вже зайнятий, передайте
`--port` (або `-p`) під час запуску Agent Canvas:

```bash
agent-canvas --port 3000
```

Та сама команда працює в PowerShell у Windows. Потім відкрийте
`http://localhost:3000` замість цього. Стандартна локальна серверна частина
має відображатися як справна (healthy) на головному екрані.

Команда `agent-canvas` запускає сервер агента, серверну частину автоматизації
та веб-фронтенд разом. Вам потрібна лише ця одна команда, щоб запустити
OpenHands локально.

## 4. Налаштуйте локальну LLM

Під час першого запуску Agent Canvas відкриває процес налаштування. У цьому
процесі:

1. Залиште **OpenHands** обраним як агент і натисніть **Next**.
2. На екрані **Set up your LLM** оберіть **Advanced**.
3. Залиште для **Authentication** значення **API key**.
4. Встановіть для **Custom Model** значення `openai/Qwen3.6-35B-A3B-GGUF`.
5. Встановіть для **Base URL** значення `http://127.0.0.1:13305/api/v1`.
6. У полі **API Key** введіть будь-яке непорожнє значення-заповнювач, наприклад
   `lemonade-local`. Lemonade не вимагає справжнього ключа, але клієнту
   OpenHands потрібне якесь значення для надсилання.
7. Натисніть **Next**.

Заповнені розширені (Advanced) налаштування мають виглядати так. Поле API-ключа
приховане інтерфейсом.

![Розширені налаштування LLM Agent Canvas при першому запуску з моделлю Lemonade та локальною базовою адресою](assets/01-llm-advanced-settings.png)

Agent Canvas зберігає ці значення як профіль LLM. Якщо ваша версія просить дати
цьому профілю ім'я, використайте ім'я без пробілів, наприклад `lemonade-local`.
Якщо пізніше ви зміните модель, відкрийте **Settings > LLM** і оновіть ті самі
розширені поля. Ви можете перемикатися між збереженими профілями з поля вводу
чату за допомогою команди `/model`.

## 5. Відкрийте робоче середовище

Агент може читати та змінювати файли лише в межах робочого середовища, яке ви
обираєте. Перед початком завдання вкажіть Agent Canvas на теку вашого проєкту:

1. На головному екрані оберіть **Open Workspace**.
2. Виберіть теку, що містить ваш проєкт (наприклад, git-репозиторій, над яким
   має працювати агент).
3. Розпочніть нову розмову в цьому робочому середовищі.

Усе, що робить агент — читання файлів, виконання команд, редагування коду —
обмежене цим робочим середовищем.

![Головний екран Agent Canvas після налаштування](assets/02-agent-canvas-home.png)
## 6. Виконайте своє перше завдання з кодування

Коли робочий простір відкрито, а локальну LLM обрано, введіть конкретне
завдання в чат. Гарне перше завдання — невелике й таке, що легко перевірити,
наприклад:

```text
Create a new file called hello.py that defines a function greet(name) that
returns "Hello, {name}!", and add a small test that prints greet("World")
when run as a script.
```

Спостерігайте за хронологією розмови. OpenHands:

- Прочитає робочий простір, щоб зрозуміти його структуру.
- Створить `hello.py` із запитаною функцією та блоком тестування.
- За потреби виконає `python3 hello.py`, щоб перевірити результат.
- Повідомить у чаті про виконані дії та вивід будь-яких команд.

Ви повинні побачити новий файл у робочому просторі, а фінальне повідомлення
агента має описувати внесену зміну. Це і є той момент, заради якого все
затівалося: агент написав і виконав реальний код у вашій проєктній теці.

## 7. Перегляньте роботу агента та скеровуйте його

Після завершення кроку агентом перегляньте його роботу, перш ніж приймати
наступний крок:

- **Зміни у файлах**: скористайтеся файловим браузером робочого простору або
  переглядом відмінностей (diff) агента, щоб точно побачити, що було додано,
  змінено або видалено.
- **Вивід команд**: розгорніть будь-яку виконану агентом команду, щоб побачити
  stdout, stderr та код завершення.
- **Подальші кроки**: якщо результат не той, якого ви очікували, дайте
  відповідь у тій самій розмові з виправленням. Агент зберігає попередній
  контекст і продовжує роботу над тими самими файлами.

Наприклад, якщо тест не вивів очікуване привітання, напишіть у відповідь:

```text
The script did not print anything. Run python3 hello.py and fix it so the
greet("World") test prints to stdout.
```

Агент повторно прочитає файл, виконає команду, діагностує проблему та знову
відредагує файл — усе в межах тієї самої розмови.

## Усунення несправностей

- **`agent-canvas` відсутній у PATH:** перевстановіть за допомогою
  `npm install -g @openhands/agent-canvas` і переконайтеся, що каталог
  глобальних бінарних файлів npm є в PATH. У Windows виконайте
  `npm config get prefix`; отриманий каталог, зазвичай `%APPDATA%\npm` або
  `%USERPROFILE%\.npm-global`, має бути в PATH користувача, перш ніж
  `agent-canvas` можна буде запустити з нового термінала.
- **`npm install -g` завершується помилкою прав доступу:** налаштуйте
  глобальний каталог npm, що належить користувачу, потім знову відкрийте
  термінал і повторно встановіть Agent Canvas.

  <!-- @os:linux -->
  ```bash
  mkdir -p ~/.npm-global
  npm config set prefix ~/.npm-global
  echo 'export PATH="$HOME/.npm-global/bin:$PATH"' >> ~/.profile
  . ~/.profile
  npm install -g @openhands/agent-canvas
  ```
  <!-- @os:end -->

  <!-- @os:windows -->
  ```powershell
  New-Item -ItemType Directory -Force "$env:USERPROFILE\.npm-global"
  npm config set prefix "$env:USERPROFILE\.npm-global"
  $env:Path = "$env:USERPROFILE\.npm-global;$env:Path"
  npm install -g @openhands/agent-canvas
  ```

  Щоб зробити зміну PATH у Windows постійною, додайте
  `%USERPROFILE%\.npm-global` до PATH користувача через **Settings > System >
  About > Advanced system settings > Environment Variables** і відкрийте новий
  термінал.
  <!-- @os:end -->
- **Інтерфейс завантажується, але серверна частина показує статус "unhealthy":**
  зачекайте кілька секунд, поки сервер агента завершить запуск, а потім
  оновіть сторінку. Якщо статус залишається "unhealthy", перезапустіть
  `agent-canvas` і перевірте вивід термінала на наявність помилок.
- **Запити чату Lemonade завершуються помилкою з'єднання:** переконайтеся,
  що `curl -fsS "http://127.0.0.1:13305/api/v1/health"` виконується успішно,
  і що Lemonade досі обслуговує модель — перевірте це командою
  `lemonade status`.
- **Агент видає помилку про довжину контексту або ліміт токенів:**
  перезапустіть Lemonade з більшим значенням `ctx_size` (наприклад,
  `ctx_size=65536`) і почніть нову розмову, щоб агент не переносив
  надто велику історію.
- **Агент виконує правки низької якості або неповні:** перемкніться на більшу
  модель у Lemonade або поставте агенту менше й конкретніше завдання та
  дайте йому завершити його, перш ніж просити наступну зміну.
- **Відсутній `uv`:** встановіть його з
  [посібника зі встановлення uv](https://docs.astral.sh/uv/getting-started/installation/).
  Agent Canvas використовує `uv` для керування Python-середовищем сервера
  агента.

## Наступні кроки

- Спробуйте більше завдання в тому самому робочому просторі, наприклад,
  додайте файл модульного тесту або виправте відому помилку, і перегляньте
  diff агента, перш ніж зберегти зміну.
- Підключіть MCP-сервер, наприклад GitHub або Slack, у розділі **Customize**,
  щоб агент міг читати issue або публікувати оновлення під час роботи.
- Збережіть кілька профілів LLM (швидку невелику модель і потужнішу велику
  модель) і перемикайтеся між ними за допомогою `/model` прямо під час
  розмови.
- Перейдіть до [автоматизацій OpenHands](https://docs.openhands.dev/openhands/usage/automations/overview),
  щоб перетворити повторювані цикли розробки на заплановані або
  подієво-керовані запуски агента.
