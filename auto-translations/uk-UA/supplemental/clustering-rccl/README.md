# Кластеризація двох Ryzen™ AI Halo за допомогою RCCL

## Огляд

Ваш Ryzen™ AI Halo вже здатний запускати великі мовні моделі локально. Кластеризація розширює ці можливості, об'єднуючи GPU-пам'ять кількох систем через локальну мережу та надаючи доступ до ще більших моделей із потужнішим міркуванням, кращою генерацією коду та глибшим багатомовним розумінням — і все це виключно на вашому власному обладнанні.

Цей посібник навчить вас, як об'єднати дві системи Ryzen AI Halo у кластер за допомогою RCCL (ROCm Communication Collectives Library) разом із vLLM та запустити Qwen3.5-397B — модель із 397 мільярдами параметрів — на обох машинах із прискоренням ROCm.

## Що ви дізнаєтесь

- Як розширити виділення VRAM на системах Ryzen AI Halo
- Запуск vLLM із підтримкою ROCm
- Налаштування RCCL для багатовузлового тензорно-паралельного виведення на двох системах Ryzen AI Halo
- Запуск моделі з 397 мільярдами параметрів на двох об'єднаних у мережу системах Ryzen AI Halo

## Передумови

### Обладнання

Для цього посібника потрібні два пристрої Ryzen AI Halo та один комутатор Ethernet, з'єднані у зіркоподібній топології, де кожен пристрій підключений безпосередньо до комутатора.

| Компонент | Кількість | Опис |
|-----------|----------|-------------|
| Ryzen AI Halo | 2 | Обчислювальні вузли, що утворюють кластер |
| Комутатор Ethernet 10 Гбіт/с | 1 | Центральний комутатор для забезпечення зв'язку між вузлами Ryzen AI Halo (щонайменше 2 порти) |
| Кабель Ethernet | 2 | З'єднує кожен пристрій Halo з комутатором (рекомендується Cat 7 або вище) |

> **Примітка**: Для підключення двох пристроїв Ryzen AI Halo потрібні два порти комутатора Ethernet. Третій порт необхідний, якщо ви звертаєтесь до моделі з окремої клієнтської машини, а не з одного з пристроїв Halo.

## Фізичне налаштування обладнання

> **Примітка**: Виконайте цей крок на обох машинах — Machine 1 і Machine 2.

Підключіть кожен пристрій Ryzen AI Halo до комутатора Ethernet за допомогою кабелю Cat 7 (або вище). Це встановлює з'єднання 10 Гбіт/с, яке використовується для високошвидкісного зв'язку між вузлами.

### 1. Визначення мережевих інтерфейсів

На кожній машині знайдіть назву її мережевого інтерфейсу та запишіть її (у подальших інструкціях вона позначатиметься як `IFNAME`). Виконайте:

```bash
ip route get 1.1.1.1 | grep -oP 'dev \K\S+'
```

Це виведе назву інтерфейсу безпосередньо, наприклад:

```bash
enp191s0
```

### 2. Перевірка швидкості мережевого з'єднання

Переконайтеся, що з'єднання активне та працює на повній швидкості, перевіривши швидкість вашого інтерфейсу:

```bash
sudo ethtool <IFNAME> | grep Speed
```

> **Примітка**: Замініть `<IFNAME>` на назву інтерфейсу, отриману в розділі [1. Визначення мережевих інтерфейсів](#1-determine-network-interfaces)

Ви повинні побачити швидкість `10000Mb/s`:

```bash
	Speed: 10000Mb/s
```

> **Примітка**: Якщо швидкість нижча за `10000Mb/s` або з'єднання не встановлюється, перевірте підключення кабелю та переконайтеся, що порт комутатора налаштований на 10 Гбіт/с. Деякі комутатори вимагають вимкнення автоузгодження та ручного встановлення швидкості з'єднання; зверніться до документації вашого комутатора.

## Розширення виділення VRAM

> **Примітка**: Виконайте цей крок на обох машинах — Machine 1 і Machine 2.

### Налаштування пам'яті для запуску великих моделей

У Linux ROCm використовує спільний пул системної пам'яті, який за замовчуванням налаштований на половину системної пам'яті.

Цей обсяг можна збільшити, змінивши налаштування сторінок Translation Table Manager (TTM) ядра, дотримуючись наведених нижче інструкцій. AMD рекомендує встановити мінімальний виділений VRAM у BIOS (0,5 ГБ).

* Встановіть утиліту pipx та додайте шлях для встановлених pipx пакетів до системного шляху пошуку.

  ```bash
  sudo apt install pipx
  pipx ensurepath
  ```

* Встановіть пакет amd-debug-tools з PyPI.
  ```bash
  pipx install amd-debug-tools
  ```

* Запустіть інструмент amd-ttm для перегляду поточних налаштувань спільної пам'яті.
  ```bash
  amd-ttm
  ```

* Перенастройте параметри спільної пам'яті на **120 ГБ**:
  ```bash
  amd-ttm --set 120
  ```

* Перезавантажте систему, щоб зміни набули чинності.

## Ініціалізація контейнера vLLM

> **Примітка**: Виконайте цей крок на обох машинах — Machine 1 і Machine 2.

Ваш Ryzen AI Halo постачається з vLLM, упакованим у попередньо зібраний образ контейнера, який ви запускаєте за допомогою Podman — безкоштовного інструменту для роботи з контейнерами з відкритим вихідним кодом.

### 1. Створення каталогу для завантаження моделей

Коли ви розгортаєте модель Qwen3.5-397B у цьому посібнику, vLLM автоматично завантажить ваги моделі на вашу систему. Щоб ці ваги були доступні зсередини контейнера, спочатку створіть каталог моделей, який контейнер зможе підключити:

```bash
mkdir -p ~/.local/share/vLLM/models
```

### 2. Запуск контейнера vLLM

Наведена нижче команда запускає контейнер і переводить вас в інтерактивну оболонку. Вона підключає щойно створений каталог моделей і передає ваш `IFNAME` до `NCCL_SOCKET_IFNAME` та `GLOO_SOCKET_IFNAME`, вказуючи RCCL (бібліотеці, яку vLLM використовує для координації GPU у кластері), який інтерфейс використовувати.

Запустіть контейнер командою:

```bash
sudo podman run -it --name vllm_cluster --replace --pull missing --network=host --device /dev/kfd --device /dev/dri -v ~/.local/share/vLLM/models:/opt/vLLM/models --env HF_HOME=/opt/vLLM/models --entrypoint="bin/bash" --shm-size=64g -e NCCL_SOCKET_IFNAME=<IFNAME> -e GLOO_SOCKET_IFNAME=<IFNAME> oci-registry.ryai.dev/ryai-vllm:latest
```

> **Примітка**: Замініть `<IFNAME>` на назву інтерфейсу, отриману в розділі [1. Визначення мережевих інтерфейсів](#1-determine-network-interfaces)

## Запуск моделі на кластері

vLLM використовує Ray для оркестрації кластера та RCCL для обробки GPU-to-GPU зв'язку між вузлами. Одна машина виступає як **головний вузол** (Machine 1), координуючи виведення. Інша приєднується як **робочий вузол** (Machine 2), надаючи свою GPU-пам'ять та обчислювальні ресурси.

> **Примітка**: Ray є необов'язковою залежністю для vLLM і доступний лише зсередини попередньо налаштованого контейнера Podman.

Під час запуску vLLM розподіляє модель між обома вузлами за допомогою тензорного паралелізму. Після завантаження виведення відбувається так, ніби воно виконується на одному прискорювачі.

### Крок 1: Запуск головного вузла Ray (Machine 1)

На Machine 1 запустіть головний вузол Ray для ініціалізації кластера:

```bash
ray start --head --port=6379 --node-ip-address=<MACHINE_1_IP> --num-gpus=1
```

> **Як знайти `<MACHINE_1_IP>`**: На Machine 1 виконайте `hostname -I | awk '{print $1}'`, щоб знайти її локальну IP-адресу.

### Крок 2: Приєднання до кластера (Machine 2)

На Machine 2 підключіться до головного вузла для формування кластера:

```bash
ray start --address=<MACHINE_1_IP>:6379 --node-ip-address=<MACHINE_2_IP> --num-gpus=1
```

> **Як знайти `<MACHINE_2_IP>`**: На Machine 2 виконайте `hostname -I | awk '{print $1}'`, щоб знайти її локальну IP-адресу.

### Крок 3: Розгортання моделі (Machine 1)

На Machine 1 запустіть сервер vLLM. Це автоматично завантажить модель і почне її обслуговування на обох вузлах:

```bash
vllm serve Qwen/Qwen3.5-397B-A17B-GPTQ-Int4 \
  --port 7000 \
  --host 0.0.0.0 \
  --max-model-len 32768 \
  --gpu-memory-utilization 0.9 \
  --dtype float16 \
  --tensor-parallel-size 2 \
  --distributed-executor-backend ray \
  --enforce-eager \
  --language-model-only \
  --reasoning-parser qwen3
```

#### Довідник параметрів

| Прапор | Призначення |
|------|---------|
| `--port` | Порт для обслуговування HTTP API |
| `--host` | IP-адреса для прив'язки сервера (`0.0.0.0` для всіх інтерфейсів) |
| `--max-model-len` | Максимальна довжина контексту в токенах |
| `--gpu-memory-utilization` | Частка GPU-пам'яті для виділення (0.0–1.0) |
| `--dtype` | Тип даних для ваг моделі |
| `--tensor-parallel-size` | Кількість GPU для розподілу моделі (встановіть рівним загальній кількості GPU у кластері) |
| `--distributed-executor-backend` | Бекенд для багатовузлового виконання (`ray` для кластерних розгортань) |
| `--enforce-eager` | Вимикає компіляцію графів CUDA для забезпечення сумісності |
| `--language-model-only` | Пропускає завантаження допоміжних компонентів моделі (наприклад, кодувальника зображень) |
| `--reasoning-parser` | Вмикає структурований розбір виводу міркувань для моделі |

Для повного опису використання параметрів зверніться до [документації vLLM](https://docs.vllm.ai/en/latest/configuration/engine_args/).

## Доступ до моделі

vLLM надає API, сумісний з OpenAI, тому ви можете підключити будь-який сумісний клієнт або інтерфейс до вашого кластера. Одним із популярних варіантів є [Open WebUI](https://github.com/open-webui/open-webui), який надає браузерний інтерфейс для чату.

Щоб підключити Open WebUI до вашого кінцевого пункту vLLM:

1. Відкрийте **Settings** > **Admin Panel** > **Connections**
2. Натисніть **+** у розділі **Manage OpenAI API Connections**
3. Встановіть **Connection Type** на **External**
4. Встановіть **URL** на `http://<MACHINE_1_IP>:7000/v1`
5. У розділі **Auth** виберіть **None** зі спадного меню
6. Залиште **Model IDs** порожнім для автоматичного виявлення всіх моделей із кінцевого пункту

> **Як знайти `<MACHINE_1_IP>`**: На Machine 1 виконайте `hostname -I | awk '{print $1}'`, щоб знайти її локальну IP-адресу. Якщо ви звертаєтесь до Open WebUI безпосередньо з Machine 1, можна використати `http://localhost:7000/v1`.

![Налаштування підключення Open WebUI до кінцевого пункту vLLM](assets/openwebui-connection.png)

Після підключення виберіть модель зі спадного меню моделей у Open WebUI та почніть спілкування. Модель тепер працює на обох ваших вузлах Ryzen AI Halo:

![Спілкування з Qwen3.5-397B у Open WebUI](assets/openwebui-chat.png)

## Наступні кроки

- **Досліджуйте інші моделі**: Відкривайте нові моделі на [Hugging Face](https://huggingface.co/models?&sort=trending), які вміщуються в об'єднану GPU-пам'ять вашого кластера
- **Масштабування до чотирьох вузлів**: Додайте ще два системи Ryzen AI Halo як додаткові робочі вузли Ray для розподілу моделей на ще більшу кількість GPU. Для цього потрібен комутатор Ethernet щонайменше з чотирма портами — по одному для кожного вузла. Виконайте [Крок 2: Приєднання до кластера](#step-2-join-the-cluster-machine-2) на кожному додатковому робочому вузлі та відповідно збільшіть `--tensor-parallel-size`
- **Спробуйте інші стратегії паралелізму**: vLLM підтримує [паралелізм експертів](https://docs.vllm.ai/en/latest/serving/expert_parallel_deployment/) для моделей типу mixture-of-experts та [паралелізм даних](https://docs.vllm.ai/en/latest/serving/data_parallel_deployment/) для підвищення пропускної здатності. Експериментуйте з `--enable-expert-parallel` та `--data-parallel-size`, щоб знайти оптимальну конфігурацію для вашого робочого навантаження
