# Кластеризація двох Ryzen™ AI Halo за допомогою RCCL

## Огляд

Ваш Ryzen™ AI Halo вже здатний локально запускати великі мовні моделі. Кластеризація йде далі, об’єднуючи пам’ять GPU кількох систем через локальну мережу, надаючи доступ до ще більших моделей із сильнішим міркуванням, кращою генерацією коду та глибшим розумінням багатьох мов — і все це повністю на вашому власному обладнанні.

Цей посібник навчить вас кластеризувати дві системи Ryzen AI Halo за допомогою RCCL (ROCm Communication Collectives Library) разом із vLLM та запускати Qwen3.5-397B, модель із 397 мільярдами параметрів, на обох машинах з прискоренням ROCm.

## Що ви дізнаєтесь

- Як розширити виділення VRAM на системах Ryzen AI Halo
- Запуск vLLM з підтримкою ROCm
- Налаштування RCCL для тензорно-паралельного інференсу на кількох вузлах між двома системами Ryzen AI Halo
- Запуск моделі з 397 мільярдами параметрів на двох мережевих системах Ryzen AI Halo

## Передумови

### Обладнання

Для цього посібника потрібні два блоки Ryzen AI Halo та один Ethernet-комутатор, з’єднані в топології «зірка», де кожен блок підключено безпосередньо до комутатора.

| Компонент | Кількість | Опис |
|-----------|----------|-------------|
| Ryzen AI Halo | 2 | Обчислювальні вузли, що утворюють кластер |
| 10-гігабітний Ethernet-комутатор | 1 | Центральний комутатор для забезпечення зв’язку між кількома вузлами Ryzen AI Halo (щонайменше 2 порти) |
| Ethernet-кабель | 2 | З’єднує кожен блок Halo з комутатором (рекомендується Cat 7 або вище) |

> **Примітка**: Для з’єднання двох блоків Ryzen AI Halo потрібні два порти Ethernet-комутатора. Третій порт потрібен, якщо ви звертаєтесь до моделі з окремої клієнтської машини, а не з одного з блоків Halo.

## Налаштування фізичного обладнання

> **Примітка**: Виконайте цей крок на Машині 1 та Машині 2.

Підключіть кожен блок Ryzen AI Halo до Ethernet-комутатора за допомогою кабелю Cat 7 (або вище). Це встановлює 10-гігабітний зв’язок, який використовується для високошвидкісного обміну даними між вузлами.

### 1. Визначення мережевих інтерфейсів

На кожній машині знайдіть назву її мережевого інтерфейсу та запишіть її (у подальших інструкціях вона буде позначатися як `IFNAME`). Виконайте:

```bash
ip route get 1.1.1.1 | grep -oP 'dev \K\S+'
```

Це виведе назву інтерфейсу безпосередньо, наприклад:

```bash
enp191s0
```

### 2. Перевірка швидкості мережевого з’єднання

Переконайтеся, що з’єднання активне та працює на повній швидкості, перевіривши швидкість вашого інтерфейсу:

```bash
sudo ethtool <IFNAME> | grep Speed
```

> **Примітка**: Замініть `<IFNAME>` на назву вихідного інтерфейсу з [1. Визначення мережевих інтерфейсів](#1-determine-network-interfaces)

Ви маєте побачити швидкість `10000Mb/s`:

```bash
	Speed: 10000Mb/s
```

> **Примітка**: Якщо швидкість нижча за `10000Mb/s` або з’єднання не встановлюється, перевірте кабельне з’єднання та переконайтеся, що порт комутатора налаштовано на 10 Гбіт/с. Деякі комутатори вимагають вимкнення автоузгодження та ручного встановлення швидкості з’єднання; зверніться до документації свого комутатора.

## Розширення виділення VRAM

> **Примітка**: Виконайте цей крок на Машині 1 та Машині 2.

### Налаштування пам’яті для запуску великих моделей

У Linux ROCm використовує спільний пул системної пам’яті, і цей пул за замовчуванням налаштовано на половину обсягу системної пам’яті.

Цей обсяг можна збільшити, змінивши налаштування сторінок Translation Table Manager (TTM) ядра, дотримуючись наведених нижче інструкцій. AMD рекомендує встановити мінімальний обсяг виділеної VRAM у BIOS (0,5 ГБ).

* Встановіть утиліту pipx та додайте шлях до встановлених через pipx wheel-пакетів у системний шлях пошуку.

  ```bash
  sudo apt install pipx
  pipx ensurepath
  ```

* Встановіть wheel-пакет amd-debug-tools з PyPI.
  ```bash
  pipx install amd-debug-tools
  ```

* Запустіть інструмент amd-ttm, щоб отримати поточні налаштування спільної пам’яті.
  ```bash
  amd-ttm
  ```

* Перенастройте параметри спільної пам’яті на **120 ГБ**:
  ```bash
  amd-ttm --set 120
  ```

* Перезавантажте систему, щоб зміни набули чинності.

## Ініціалізація контейнера vLLM

> **Примітка**: Виконайте цей крок на Машині 1 та Машині 2.

Ваш Ryzen AI Halo постачається з vLLM, упакованим у готовий образ контейнера, який ви запускаєте за допомогою Podman — безкоштовного інструменту для контейнерів з відкритим вихідним кодом.

### 1. Створення директорії для завантаження моделі

Коли ви запустите обслуговування моделі Qwen3.5-397B у цьому посібнику, vLLM автоматично завантажить ваги моделі у вашу систему. Щоб переконатися, що ці ваги доступні зсередини контейнера, спочатку створіть директорію для моделей, яку контейнер зможе змонтувати:

```bash
mkdir -p ~/.local/share/vLLM/models
```

### 2. Запуск контейнера vLLM

Наведена нижче команда запускає контейнер і переводить вас в інтерактивну оболонку. Вона монтує щойно створену директорію моделей та передає ваш `IFNAME` у `NCCL_SOCKET_IFNAME` та `GLOO_SOCKET_IFNAME`, повідомляючи RCCL (бібліотеці, яку vLLM використовує для координації GPU у кластері), який інтерфейс використовувати.

Запустіть контейнер за допомогою:

```bash
sudo podman run -it --name vllm_cluster --replace --pull missing --network=host --device /dev/kfd --device /dev/dri -v ~/.local/share/vLLM/models:/opt/vLLM/models --env HF_HOME=/opt/vLLM/models --entrypoint="bin/bash" --shm-size=64g -e NCCL_SOCKET_IFNAME=<IFNAME> -e GLOO_SOCKET_IFNAME=<IFNAME> oci-registry.ryai.dev/ryai-vllm:latest
```

> **Примітка**: Замініть `<IFNAME>` на назву вихідного інтерфейсу з [1. Визначення мережевих інтерфейсів](#1-determine-network-interfaces)

## Запуск моделі на кластері

vLLM використовує Ray для оркестрації кластера та RCCL для обробки зв’язку GPU-GPU між вузлами. Одна машина виступає в ролі **головного вузла** (Машина 1), координуючи інференс. Інша приєднується як **робочий вузол** (Машина 2), надаючи свою пам’ять GPU та обчислювальні потужності.

> **Примітка**: Ray є опціональною залежністю для vLLM і доступний лише всередині попередньо налаштованого контейнера Podman.

Під час запуску vLLM розподіляє модель між обома вузлами за допомогою тензорного паралелізму. Після завантаження інференс відбувається так, ніби виконується на одному прискорювачі.

### Крок 1: Запуск головного вузла Ray (Машина 1)

На Машині 1 запустіть головний вузол Ray, щоб ініціалізувати кластер:

```bash
ray start --head --port=6379 --node-ip-address=<MACHINE_1_IP> --num-gpus=1
```

> **Пошук `<MACHINE_1_IP>`**: На Машині 1 виконайте `hostname -I | awk '{print $1}'`, щоб знайти її локальну IP-адресу.
### Крок 2: Приєднання до кластера (Машина 2)

На Машині 2 підключіться до головного вузла, щоб сформувати кластер:

```bash
ray start --address=<MACHINE_1_IP>:6379 --node-ip-address=<MACHINE_2_IP> --num-gpus=1
```

> **Пошук `<MACHINE_2_IP>`**: на Машині 2 виконайте `hostname -I | awk '{print $1}'`, щоб знайти її локальну IP-адресу.

### Крок 3: Обслуговування моделі (Машина 1)

На Машині 1 запустіть сервер vLLM. Це автоматично завантажить модель і почне обслуговувати її на обох вузлах:

```bash
vllm serve Qwen/Qwen3.5-397B-A17B-GPTQ-Int4 \
  --port 7000 \
  --host 0.0.0.0 \
  --max-model-len 32768 \
  --gpu-memory-utilization 0.9 \
  --dtype float16 \
  --tensor-parallel-size 2 \
  --distributed-executor-backend ray \
  --enforce-eager \
  --language-model-only \
  --reasoning-parser qwen3
```

#### Довідник параметрів

| Прапорець | Призначення |
|------|---------|
| `--port` | Порт для обслуговування HTTP API |
| `--host` | IP-адреса для прив’язки сервера (`0.0.0.0` для всіх інтерфейсів) |
| `--max-model-len` | Максимальна довжина контексту в токенах |
| `--gpu-memory-utilization` | Частка пам’яті GPU для виділення (0.0–1.0) |
| `--dtype` | Тип даних для ваг моделі |
| `--tensor-parallel-size` | Кількість GPU для розподілу моделі (встановіть загальну кількість GPU в кластері) |
| `--distributed-executor-backend` | Бекенд для багатовузлового виконання (`ray` для кластерних розгортань) |
| `--enforce-eager` | Вимикає компіляцію CUDA graph для сумісності |
| `--language-model-only` | Пропускає завантаження допоміжних компонентів моделі (наприклад, кодувальника зображень) |
| `--reasoning-parser` | Вмикає структуроване розбирання виводу міркувань для моделі |

Повний опис використання параметрів дивіться в [документації vLLM](https://docs.vllm.ai/en/latest/configuration/engine_args/).

## Доступ до моделі

vLLM надає API, сумісний з OpenAI, тому ви можете підключити будь-який сумісний клієнт або інтерфейс до вашого кластера. Одним із популярних варіантів є [Open WebUI](https://github.com/open-webui/open-webui), який надає чат-інтерфейс на основі браузера.

Щоб підключити Open WebUI до вашої кінцевої точки vLLM:

1. Відкрийте **Settings** > **Admin Panel** > **Connections**
2. Натисніть **+** на **Manage OpenAI API Connections**
3. Встановіть **Connection Type** на **External**
4. Встановіть **URL** на `http://<MACHINE_1_IP>:7000/v1`
5. У розділі **Auth** виберіть **None** зі спадного списку
6. Залиште **Model IDs** порожнім, щоб автоматично виявити всі моделі з кінцевої точки

> **Пошук `<MACHINE_1_IP>`**: на Машині 1 виконайте `hostname -I | awk '{print $1}'`, щоб знайти її локальну IP-адресу. Якщо ви отримуєте доступ до Open WebUI з самої Машини 1, можна використати `http://localhost:7000/v1`.

![Налаштування підключення Open WebUI до кінцевої точки vLLM](assets/openwebui-connection.png)

Після підключення виберіть модель зі спадного списку моделей в Open WebUI та почніть спілкування. Модель тепер працює на обох ваших вузлах Ryzen AI Halo:

![Спілкування з Qwen3.5-397B в Open WebUI](assets/openwebui-chat.png)

## Наступні кроки

- **Дослідіть інші моделі**: знайдіть нові моделі на [Hugging Face](https://huggingface.co/models?&sort=trending), які вписуються в загальний обсяг пам’яті GPU вашого кластера
- **Масштабуйте до чотирьох вузлів**: додайте ще дві системи Ryzen AI Halo як додаткові робочі вузли Ray, щоб розподіляти моделі на ще більшу кількість GPU. Для цього потрібен Ethernet-комутатор щонайменше з чотирма портами, по одному на кожен вузол. Виконайте [Крок 2: Приєднання до кластера](#step-2-join-the-cluster-machine-2) на кожному додатковому робочому вузлі та відповідно збільште `--tensor-parallel-size`
- **Спробуйте інші стратегії паралелізму**: vLLM підтримує [expert parallel](https://docs.vllm.ai/en/latest/serving/expert_parallel_deployment/) для моделей типу mixture-of-experts та [data parallel](https://docs.vllm.ai/en/latest/serving/data_parallel_deployment/) для вищої пропускної здатності. Поекспериментуйте з `--enable-expert-parallel` та `--data-parallel-size`, щоб знайти найкращу конфігурацію для вашого навантаження
