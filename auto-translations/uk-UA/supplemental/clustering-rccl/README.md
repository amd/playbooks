# Кластеризація двох Ryzen™ AI Halo за допомогою RCCL

## Огляд

Ваш Ryzen™ AI Halo вже здатний локально запускати великі мовні моделі. Кластеризація йде далі, об’єднуючи обсяг пам’яті GPU кількох систем через локальну мережу, надаючи вам доступ до ще більших моделей із потужнішим міркуванням, кращою генерацією коду та глибшим розумінням багатьох мов — і все це повністю на вашому власному обладнанні.

Цей посібник навчить вас кластеризувати дві системи Ryzen AI Halo за допомогою RCCL (ROCm Communication Collectives Library) разом із vLLM і запускати Qwen3.5-397B, модель із 397 млрд параметрів, на обох машинах одночасно з прискоренням ROCm.

## Що ви дізнаєтесь

- Як розширити виділення VRAM на системах Ryzen AI Halo
- Запуск vLLM з підтримкою ROCm
- Налаштування RCCL для тензорно-паралельного багатовузлового інференсу на двох системах Ryzen AI Halo
- Запуск моделі з 397 млрд параметрів на двох з’єднаних у мережу системах Ryzen AI Halo

## Попередні вимоги

### Апаратне забезпечення

Для цього посібника потрібні два блоки Ryzen AI Halo та один Ethernet-комутатор, з’єднані за топологією «зірка», де кожен блок підключено безпосередньо до комутатора.

| Компонент | Кількість | Опис |
|-----------|----------|-------------|
| Ryzen AI Halo | 2 | Обчислювальні вузли, що утворюють кластер |
| 10Gbps Ethernet-комутатор | 1 | Центральний комутатор, що забезпечує зв’язок між кількома вузлами Ryzen AI Halo (щонайменше 2 порти) |
| Ethernet-кабель | 2 | З’єднує кожен блок Halo з комутатором (рекомендовано Cat 7 або вище) |

> **Примітка**: Для з’єднання двох блоків Ryzen AI Halo потрібно два порти Ethernet-комутатора. Третій порт потрібен, якщо ви звертаєтеся до моделі з окремої клієнтської машини, а не з одного з блоків Halo.

## Налаштування фізичного обладнання

> **Примітка**: Виконайте цей крок як на Machine 1, так і на Machine 2.

Підключіть кожен блок Ryzen AI Halo до Ethernet-комутатора за допомогою кабелю Cat 7 (або вище). Це встановить з’єднання 10 Гбіт/с, що використовується для високошвидкісної комунікації між вузлами.

### 1. Визначення мережевих інтерфейсів

На кожній машині знайдіть назву її мережевого інтерфейсу та запишіть її (надалі в інструкціях вона позначатиметься як `IFNAME`). Виконайте:

```bash
ip route get 1.1.1.1 | grep -oP 'dev \K\S+'
```

Це виведе назву інтерфейсу безпосередньо, наприклад:

```bash
enp191s0
```

### 2. Перевірка швидкості мережевого з’єднання

Переконайтеся, що з’єднання активне та працює на повній швидкості, перевіривши швидкість вашого інтерфейсу:

```bash
sudo ethtool <IFNAME> | grep Speed
```

> **Примітка**: Замініть `<IFNAME>` на назву вихідного інтерфейсу з [1. Визначення мережевих інтерфейсів](#1-determine-network-interfaces)

Ви повинні побачити швидкість `10000Mb/s`:

```bash
	Speed: 10000Mb/s
```

> **Примітка**: Якщо швидкість нижча за `10000Mb/s` або з’єднання не встановлюється, перевірте кабельне з’єднання та переконайтесь, що порт комутатора налаштовано на 10 Гбіт/с. Деякі комутатори вимагають вимкнення автоузгодження та ручного встановлення швидкості з’єднання; зверніться до документації вашого комутатора.

## Розширення виділення VRAM

> **Примітка**: Виконайте цей крок як на Machine 1, так і на Machine 2.

### Налаштування пам’яті для запуску великих моделей

У Linux ROCm використовує спільний пул системної пам’яті, і за замовчуванням цей пул налаштовано на половину обсягу системної пам’яті.

Цей обсяг можна збільшити, змінивши налаштування сторінок Translation Table Manager (TTM) ядра, дотримуючись наведених нижче інструкцій. AMD рекомендує встановити мінімальний виділений обсяг VRAM у BIOS (0.5 ГБ).

* Встановіть утиліту pipx та додайте шлях до встановлених pipx пакетів у системний шлях пошуку.

  ```bash
  sudo apt install pipx
  pipx ensurepath
  ```

* Встановіть пакет amd-debug-tools з PyPI.
  ```bash
  pipx install amd-debug-tools
  ```

* Запустіть інструмент amd-ttm, щоб дізнатися поточні налаштування спільної пам’яті.
  ```bash
  amd-ttm
  ```

* Переналаштуйте параметри спільної пам’яті на **120 ГБ**:
  ```bash
  amd-ttm --set 120
  ```

* Перезавантажте систему, щоб зміни набули чинності.

## Ініціалізація контейнера vLLM

> **Примітка**: Виконайте цей крок як на Machine 1, так і на Machine 2.

Ваш Ryzen AI Halo постачається з vLLM, упакованим у готовий образ контейнера, який ви запускаєте за допомогою Podman — безкоштовного інструменту для роботи з контейнерами з відкритим кодом.

### 1. Створення каталогу для завантаження моделі

Коли ви розгортатимете модель Qwen3.5-397B у цьому посібнику, vLLM автоматично завантажить ваги моделі у вашу систему. Щоб забезпечити доступ до цих ваг з контейнера, спочатку створіть каталог моделей, який контейнер зможе змонтувати:

```bash
mkdir -p ~/.local/share/vLLM/models
```

### 2. Запуск контейнера vLLM

Наведена нижче команда запускає контейнер і переносить вас в інтерактивну оболонку. Вона монтує щойно створений каталог моделей і передає ваш `IFNAME` у `NCCL_SOCKET_IFNAME` та `GLOO_SOCKET_IFNAME`, повідомляючи RCCL (бібліотеці, яку vLLM використовує для координації GPU в кластері), який інтерфейс використовувати.

Запустіть контейнер за допомогою:

```bash
sudo podman run -it --name vllm_cluster --replace --pull missing --network=host --device /dev/kfd --device /dev/dri -v ~/.local/share/vLLM/models:/opt/vLLM/models --env HF_HOME=/opt/vLLM/models --entrypoint="bin/bash" --shm-size=64g --pids-limit=-1 -e NCCL_SOCKET_IFNAME=<IFNAME> -e GLOO_SOCKET_IFNAME=<IFNAME> oci-registry.ryai.dev/ryai-vllm:latest
```

> **Примітка**: Замініть `<IFNAME>` на назву вихідного інтерфейсу з [1. Визначення мережевих інтерфейсів](#1-determine-network-interfaces)

## Запуск моделі на кластері

vLLM використовує Ray для оркестрації кластера та RCCL для обробки комунікації GPU-GPU між вузлами. Одна машина виступає як **головний вузол** (Machine 1), координуючи інференс. Інша приєднується як **робочий вузол** (Machine 2), надаючи свою пам’ять GPU та обчислювальні ресурси.

> **Примітка**: Ray є опціональною залежністю для vLLM і доступний лише в межах попередньо налаштованого контейнера Podman.

Під час запуску vLLM розподіляє модель між обома вузлами за допомогою тензорного паралелізму. Після завантаження інференс відбувається так, ніби виконується на одному прискорювачі.

#### Запобігання помилкам Ray OOM

За замовчуванням Ray відстежує використання пам’яті хоста на кожному вузлі та завершує найбільший процес, коли використання пам’яті перевищує 95%. На вашому Ryzen™ AI Halo GPU та хост використовують один спільний пул пам’яті, тому завантаження моделі може спричинити помилку `ray.exceptions.OutOfMemoryError` і завершення робочого процесу.

Щоб запобігти цьому, ми експортуємо `RAY_memory_monitor_refresh_ms=0` на кожній машині перед запуском кластера та приєднанням до нього.
### Крок 1: Запуск головного вузла Ray (Машина 1)

На Машині 1 запустіть головний вузол Ray, щоб ініціалізувати кластер:

```bash
export RAY_memory_monitor_refresh_ms=0
ray start --head --port=6379 --node-ip-address=<MACHINE_1_IP> --num-gpus=1
```

> **Пошук `<MACHINE_1_IP>`**: на Машині 1 виконайте `hostname -I | awk '{print $1}'`, щоб знайти її локальну IP-адресу.

### Крок 2: Приєднання до кластера (Машина 2)

На Машині 2 підключіться до головного вузла, щоб сформувати кластер:

```bash
export RAY_memory_monitor_refresh_ms=0
ray start --address=<MACHINE_1_IP>:6379 --node-ip-address=<MACHINE_2_IP> --num-gpus=1
```

> **Пошук `<MACHINE_2_IP>`**: на Машині 2 виконайте `hostname -I | awk '{print $1}'`, щоб знайти її локальну IP-адресу.

### Крок 3: Розгортання моделі (Машина 1)

На Машині 1 запустіть сервер vLLM. Це автоматично завантажить модель і почне обслуговувати її на обох вузлах:

```bash
vllm serve Qwen/Qwen3.5-397B-A17B-GPTQ-Int4 \
  --port 7000 \
  --host 0.0.0.0 \
  --max-model-len 32768 \
  --gpu-memory-utilization 0.9 \
  --dtype float16 \
  --tensor-parallel-size 2 \
  --distributed-executor-backend ray \
  --enforce-eager \
  --language-model-only \
  --reasoning-parser qwen3
```

#### Довідник параметрів

| Прапорець | Призначення |
|------|---------|
| `--port` | Порт для обслуговування HTTP API |
| `--host` | IP-адреса для прив’язки сервера (`0.0.0.0` для всіх інтерфейсів) |
| `--max-model-len` | Максимальна довжина контексту в токенах |
| `--gpu-memory-utilization` | Частка пам'яті GPU для виділення (0.0–1.0) |
| `--dtype` | Тип даних для ваг моделі |
| `--tensor-parallel-size` | Кількість GPU для розподілу моделі (встановіть загальну кількість GPU у кластері) |
| `--distributed-executor-backend` | Бекенд для виконання на кількох вузлах (`ray` для розгортань кластера) |
| `--enforce-eager` | Вимикає компіляцію CUDA graph для сумісності |
| `--language-model-only` | Пропускає завантаження допоміжних компонентів моделі (наприклад, енкодера зображень) |
| `--reasoning-parser` | Вмикає структурований розбір виводу міркувань для моделі |

Повний опис використання параметрів наведено в [документації vLLM](https://docs.vllm.ai/en/latest/configuration/engine_args/).

## Доступ до моделі

vLLM надає API, сумісний з OpenAI, тож ви можете підключити до вашого кластера будь-який сумісний клієнт або інтерфейс. Одним із популярних варіантів є [Open WebUI](https://github.com/open-webui/open-webui), який надає інтерфейс чату на основі браузера.

Щоб підключити Open WebUI до вашої кінцевої точки vLLM:

1. Відкрийте **Settings** > **Admin Panel** > **Connections**
2. Натисніть **+** біля **Manage OpenAI API Connections**
3. Встановіть **Connection Type** на **External**
4. Встановіть **URL** на `http://<MACHINE_1_IP>:7000/v1`
5. У розділі **Auth** виберіть **None** зі спадного списку
6. Залиште поле **Model IDs** порожнім, щоб автоматично виявити всі моделі з кінцевої точки

> **Пошук `<MACHINE_1_IP>`**: на Машині 1 виконайте `hostname -I | awk '{print $1}'`, щоб знайти її локальну IP-адресу. Якщо ви заходите в Open WebUI з самої Машини 1, можна використати `http://localhost:7000/v1`.

![Налаштування підключення Open WebUI для кінцевої точки vLLM](assets/openwebui-connection.png)

Після підключення виберіть модель зі спадного списку моделей в Open WebUI та почніть спілкування. Модель тепер працює на обох ваших вузлах Ryzen AI Halo:

![Спілкування з Qwen3.5-397B в Open WebUI](assets/openwebui-chat.png)

## Наступні кроки

- **Досліджуйте інші моделі**: знайдіть нові моделі на [Hugging Face](https://huggingface.co/models?&sort=trending), які вписуються в сукупну пам'ять GPU вашого кластера
- **Масштабування до чотирьох вузлів**: додайте ще дві системи Ryzen AI Halo як додаткові робочі вузли Ray, щоб розподіляти моделі на ще більшу кількість GPU. Для цього потрібен Ethernet-комутатор щонайменше з чотирма портами, по одному на кожен вузол. Виконайте [Крок 2: Приєднання до кластера](#step-2-join-the-cluster-machine-2) на кожному додатковому робочому вузлі та відповідно збільшіть `--tensor-parallel-size`
- **Спробуйте інші стратегії паралелізму**: vLLM підтримує [паралелізм експертів](https://docs.vllm.ai/en/latest/serving/expert_parallel_deployment/) для моделей типу mixture-of-experts та [паралелізм даних](https://docs.vllm.ai/en/latest/serving/data_parallel_deployment/) для вищої пропускної здатності. Поекспериментуйте з `--enable-expert-parallel` та `--data-parallel-size`, щоб знайти найкращу конфігурацію для вашого навантаження
