# Кластеризація двох Ryzen™ AI Halo за допомогою RCCL

## Огляд

Ваш Ryzen™ AI Halo вже здатен локально запускати великі мовні моделі. Кластеризація йде ще далі, об'єднуючи пам'ять GPU кількох систем через локальну мережу, надаючи вам доступ до ще більших моделей із потужнішими можливостями міркування, кращою генерацією коду та глибшим розумінням багатьох мов, і все це повністю на вашому власному обладнанні.

Цей посібник навчить вас кластеризувати дві системи Ryzen AI Halo за допомогою RCCL (ROCm Communication Collectives Library) разом із vLLM та запускати Qwen3.5-397B, модель із 397 мільярдами параметрів, на обох машинах з апаратним прискоренням ROCm.

## Що ви дізнаєтеся

- Як розширити виділення VRAM на системах Ryzen AI Halo
- Запуск vLLM з підтримкою ROCm
- Налаштування RCCL для тензорно-паралельного інференсу з кількома вузлами на двох системах Ryzen AI Halo
- Запуск моделі з 397 мільярдами параметрів на двох системах Ryzen AI Halo, з'єднаних у мережу

## Передумови

### Обладнання

Цей посібник вимагає два блоки Ryzen AI Halo та один Ethernet-комутатор, з'єднані у топології «зірка», де кожен блок підключено безпосередньо до комутатора.

| Компонент | Кількість | Опис |
|-----------|----------|-------------|
| Ryzen AI Halo | 2 | Обчислювальні вузли, що формують кластер |
| Ethernet-комутатор 10 Гбіт/с | 1 | Центральний комутатор для забезпечення зв'язку між кількома вузлами Ryzen AI Halo (принаймні 2 порти) |
| Ethernet-кабель | 2 | З'єднує кожен блок Halo з комутатором (рекомендується Cat 7 або вище) |

> **Примітка**: Для з'єднання двох блоків Ryzen AI Halo потрібні два порти Ethernet-комутатора. Третій порт потрібен, якщо ви звертаєтеся до моделі з окремої клієнтської машини, а не з одного з блоків Halo.

## Налаштування фізичного обладнання

> **Примітка**: Виконайте цей крок на Машині 1 та Машині 2.

Підключіть кожен блок Ryzen AI Halo до Ethernet-комутатора за допомогою кабелю Cat 7 (або вище). Це встановлює канал зв'язку 10 Гбіт/с, який використовується для високошвидкісного обміну даними між вузлами.

### 1. Визначення мережевих інтерфейсів

На кожній машині знайдіть назву її мережевого інтерфейсу та занотуйте її (у подальших інструкціях вона позначатиметься як `IFNAME`). Виконайте:

```bash
ip route get 1.1.1.1 | grep -oP 'dev \K\S+'
```

Це виведе назву інтерфейсу безпосередньо, наприклад:

```bash
enp191s0
```

### 2. Перевірка швидкості мережевого з'єднання

Переконайтеся, що з'єднання активне та працює на повній швидкості, перевіривши швидкість вашого інтерфейсу:

```bash
sudo ethtool <IFNAME> | grep Speed
```

> **Примітка**: Замініть `<IFNAME>` на назву вихідного інтерфейсу з [1. Визначення мережевих інтерфейсів](#1-determine-network-interfaces)

Ви маєте побачити швидкість `10000Mb/s`:

```bash
	Speed: 10000Mb/s
```

> **Примітка**: Якщо швидкість нижча за `10000Mb/s` або з'єднання не встановлюється, перевірте підключення кабелю та переконайтеся, що порт комутатора налаштований на 10 Гбіт/с. Деякі комутатори вимагають вимкнення авто-узгодження та ручного встановлення швидкості з'єднання; зверніться до документації вашого комутатора.

## Розширення виділення VRAM

> **Примітка**: Виконайте цей крок на Машині 1 та Машині 2.

### Налаштування пам'яті для запуску великих моделей

У Linux ROCm використовує спільний пул системної пам'яті, і за замовчуванням цей пул налаштований на половину системної пам'яті.

Цей обсяг можна збільшити, змінивши налаштування сторінок Translation Table Manager (TTM) ядра, дотримуючись наведених нижче інструкцій. AMD рекомендує встановити мінімальний виділений обсяг VRAM у BIOS (0.5 ГБ).

* Встановіть утиліту pipx та додайте шлях для встановлених через pipx wheel-пакетів до системного шляху пошуку.

  ```bash
  sudo apt install pipx
  pipx ensurepath
  ```

* Встановіть wheel-пакет amd-debug-tools з PyPI.
  ```bash
  pipx install amd-debug-tools
  ```

* Запустіть інструмент amd-ttm, щоб запитати поточні налаштування спільної пам'яті.
  ```bash
  amd-ttm
  ```

* Перенастройте параметри спільної пам'яті на **120 ГБ**:
  ```bash
  amd-ttm --set 120
  ```

* Перезавантажте систему, щоб зміни набули чинності.

## Ініціалізація контейнера vLLM

> **Примітка**: Виконайте цей крок на Машині 1 та Машині 2.

Ваш Ryzen AI Halo постачається з vLLM, упакованим у попередньо зібраний образ контейнера, який ви запускаєте за допомогою Podman, безкоштовного та відкритого інструменту для контейнерів.

### 1. Створення каталогу для завантаження моделі

Коли ви обслуговуєте модель Qwen3.5-397B у цьому посібнику, vLLM автоматично завантажить ваги моделі у вашу систему. Щоб переконатися, що ці ваги доступні зсередини контейнера, спочатку створіть каталог models, який контейнер зможе змонтувати:

```bash
mkdir -p ~/.local/share/vLLM/models
```

### 2. Запуск контейнера vLLM

Наведена нижче команда запускає контейнер і переводить вас в інтерактивну оболонку. Вона монтує щойно створений каталог models і передає ваш `IFNAME` до `NCCL_SOCKET_IFNAME` та `GLOO_SOCKET_IFNAME`, повідомляючи RCCL (бібліотеці, яку vLLM використовує для координації GPU у кластері), який інтерфейс використовувати.

Запустіть контейнер за допомогою:

```bash
sudo podman run -it --name vllm_cluster --replace --pull missing --network=host --device /dev/kfd --device /dev/dri -v ~/.local/share/vLLM/models:/opt/vLLM/models --env HF_HOME=/opt/vLLM/models --entrypoint="bin/bash" --shm-size=64g --pids-limit=-1 -e NCCL_SOCKET_IFNAME=<IFNAME> -e GLOO_SOCKET_IFNAME=<IFNAME> oci-registry.ryai.dev/ryai-vllm:latest
```

> **Примітка**: Замініть `<IFNAME>` на назву вихідного інтерфейсу з [1. Визначення мережевих інтерфейсів](#1-determine-network-interfaces)

## Запуск моделі на кластері

vLLM використовує Ray для оркестрації кластера та RCCL для обробки зв'язку GPU-GPU між вузлами. Одна машина виступає як **головний вузол** (Машина 1), координуючи інференс. Інша приєднується як **робочий вузол** (Машина 2), надаючи свою пам'ять GPU та обчислювальні ресурси.

> **Примітка**: Ray є опціональною залежністю для vLLM і доступний лише зсередини попередньо налаштованого контейнера Podman. 

Під час запуску vLLM розбиває модель на частини між обома вузлами, використовуючи тензорний паралелізм. Після завантаження інференс відбувається так, ніби він виконується на одному прискорювачі.

#### Запобігання помилкам Ray OOM

За замовчуванням Ray відстежує використання пам'яті хоста на кожному вузлі та завершує найбільший процес, коли використання пам'яті перевищує 95%. На вашому Ryzen™ AI Halo GPU та хост використовують один спільний пул пам'яті, тому завантаження моделі може спричинити помилку `ray.exceptions.OutOfMemoryError` та завершити робочий процес.

Щоб запобігти цьому, ми експортуємо `RAY_memory_monitor_refresh_ms=0` на кожній машині перед запуском та приєднанням до кластера.
### Крок 1: Запуск головного вузла Ray (Machine 1)

На Machine 1 запустіть головний вузол Ray, щоб ініціалізувати кластер:

```bash
export RAY_memory_monitor_refresh_ms=0
ray start --head --port=6379 --node-ip-address=<MACHINE_1_IP> --num-gpus=1
```

> **Пошук `<MACHINE_1_IP>`**: на Machine 1 виконайте `hostname -I | awk '{print $1}'`, щоб дізнатися його локальну IP-адресу.

### Крок 2: Приєднання до кластера (Machine 2)

На Machine 2 підключіться до головного вузла, щоб сформувати кластер:

```bash
export RAY_memory_monitor_refresh_ms=0
ray start --address=<MACHINE_1_IP>:6379 --node-ip-address=<MACHINE_2_IP> --num-gpus=1
```

> **Пошук `<MACHINE_2_IP>`**: на Machine 2 виконайте `hostname -I | awk '{print $1}'`, щоб дізнатися його локальну IP-адресу.

### Крок 3: Запуск моделі (Machine 1)

На Machine 1 запустіть сервер vLLM. Він автоматично завантажить модель і почне обслуговувати її на обох вузлах:

```bash
vllm serve Qwen/Qwen3.5-397B-A17B-GPTQ-Int4 \
  --port 7000 \
  --host 0.0.0.0 \
  --max-model-len 32768 \
  --gpu-memory-utilization 0.9 \
  --dtype float16 \
  --tensor-parallel-size 2 \
  --distributed-executor-backend ray \
  --enforce-eager \
  --language-model-only \
  --reasoning-parser qwen3
```

#### Довідник параметрів

| Прапорець | Призначення |
|------|---------|
| `--port` | Порт, на якому обслуговується HTTP API |
| `--host` | IP-адреса, до якої прив’язується сервер (`0.0.0.0` для всіх інтерфейсів) |
| `--max-model-len` | Максимальна довжина контексту в токенах |
| `--gpu-memory-utilization` | Частка пам’яті GPU для виділення (0.0–1.0) |
| `--dtype` | Тип даних для ваг моделі |
| `--tensor-parallel-size` | Кількість GPU для розподілу моделі (встановіть загальну кількість GPU у кластері) |
| `--distributed-executor-backend` | Бекенд для багатовузлового виконання (`ray` для розгортань кластера) |
| `--enforce-eager` | Вимикає компіляцію CUDA graph для сумісності |
| `--language-model-only` | Пропускає завантаження допоміжних компонентів моделі (наприклад, енкодера зображень) |
| `--reasoning-parser` | Вмикає розбір структурованого виводу міркувань для моделі |

Повний опис параметрів дивіться в [документації vLLM](https://docs.vllm.ai/en/latest/configuration/engine_args/).

## Доступ до моделі

vLLM надає API, сумісний з OpenAI, тому ви можете підключити будь-який сумісний клієнт або інтерфейс до свого кластера. Одним із популярних варіантів є [Open WebUI](https://github.com/open-webui/open-webui), який надає чат-інтерфейс на основі браузера.

Щоб підключити Open WebUI до вашої кінцевої точки vLLM:

1. Відкрийте **Settings** > **Admin Panel** > **Connections**
2. Натисніть **+** біля **Manage OpenAI API Connections**
3. Встановіть **Connection Type** значення **External**
4. Встановіть **URL** значення `http://<MACHINE_1_IP>:7000/v1`
5. У розділі **Auth** виберіть **None** зі спадного списку
6. Залиште поле **Model IDs** порожнім, щоб автоматично виявити всі моделі з кінцевої точки

> **Пошук `<MACHINE_1_IP>`**: на Machine 1 виконайте `hostname -I | awk '{print $1}'`, щоб дізнатися його локальну IP-адресу. Якщо ви заходите в Open WebUI безпосередньо з Machine 1, можна використати `http://localhost:7000/v1`.

![Налаштування підключення Open WebUI до кінцевої точки vLLM](assets/openwebui-connection.png)

Після підключення виберіть модель зі спадного списку моделей в Open WebUI та почніть спілкування. Тепер модель працює на обох ваших вузлах Ryzen AI Halo:

![Спілкування з Qwen3.5-397B в Open WebUI](assets/openwebui-chat.png)

## Наступні кроки

- **Дослідіть інші моделі**: знайдіть нові моделі на [Hugging Face](https://huggingface.co/models?&sort=trending), які вміщуються в сукупну пам’ять GPU вашого кластера
- **Масштабування до чотирьох вузлів**: додайте ще дві системи Ryzen AI Halo як додаткові воркери Ray, щоб розподіляти моделі на ще більшу кількість GPU. Для цього потрібен Ethernet-комутатор щонайменше з чотирма портами — по одному на кожен вузол. Виконайте [Крок 2: Приєднання до кластера](#step-2-join-the-cluster-machine-2) на кожному додатковому воркері та відповідно збільшуйте `--tensor-parallel-size`
- **Спробуйте інші стратегії паралелізму**: vLLM підтримує [expert parallel](https://docs.vllm.ai/en/latest/serving/expert_parallel_deployment/) для моделей типу mixture-of-experts та [data parallel](https://docs.vllm.ai/en/latest/serving/data_parallel_deployment/) для вищої пропускної здатності. Поекспериментуйте з `--enable-expert-parallel` і `--data-parallel-size`, щоб знайти найкращу конфігурацію для вашого навантаження
