# Кластеризація двох Ryzen™ AI Halo за допомогою RCCL

## Огляд

Ваш Ryzen™ AI Halo вже здатен локально запускати великі мовні моделі. Кластеризація йде ще далі, об'єднуючи пам'ять GPU кількох систем через локальну мережу, надаючи вам доступ до ще більших моделей із потужнішим міркуванням, кращою генерацією коду та глибшим розумінням багатьох мов — і все це повністю на вашому власному обладнанні.

Цей практичний посібник навчить вас кластеризувати дві системи Ryzen AI Halo за допомогою RCCL (ROCm Communication Collectives Library) разом із vLLM та запускати Qwen3.5-397B, модель із 397 млрд параметрів, на обох машинах з апаратним прискоренням ROCm.

## Що ви дізнаєтеся

- Як розширити виділення VRAM на системах Ryzen AI Halo
- Запуск vLLM з підтримкою ROCm
- Налаштування RCCL для тензорно-паралельного інференсу на кількох вузлах на двох системах Ryzen AI Halo
- Запуск моделі з 397 млрд параметрів на двох з'єднаних мережею системах Ryzen AI Halo

## Передумови

### Обладнання

Для цього практичного посібника потрібні два блоки Ryzen AI Halo та один Ethernet-комутатор, з'єднані за топологією "зірка", де кожен блок підключено безпосередньо до комутатора.

| Компонент | Кількість | Опис |
|-----------|----------|-------------|
| Ryzen AI Halo | 2 | Обчислювальні вузли, що формують кластер |
| Ethernet-комутатор 10 Гбіт/с | 1 | Центральний комутатор для забезпечення зв'язку між кількома вузлами Ryzen AI Halo (щонайменше 2 порти) |
| Ethernet-кабель | 2 | З'єднує кожен блок Halo з комутатором (рекомендовано Cat 7 або вище) |

> **Примітка**: для з'єднання двох блоків Ryzen AI Halo потрібні два порти Ethernet-комутатора. Третій порт потрібен, якщо ви звертаєтесь до моделі з окремого клієнтського пристрою, а не з одного з блоків Halo.

## Фізичне налаштування обладнання

> **Примітка**: Виконайте цей крок як на Машині 1, так і на Машині 2.

Підключіть кожен пристрій Ryzen AI Halo до мережевого комутатора за допомогою кабелю Cat 7 (або вищої категорії). Це забезпечить 10-гігабітне з'єднання, яке використовується для високошвидкісного зв'язку між вузлами.

### 1. Визначення мережевих інтерфейсів

На кожній машині знайдіть назву її мережевого інтерфейсу та запишіть її (надалі в інструкціях вона позначатиметься як `IFNAME`). Виконайте:

```bash
ip route get 1.1.1.1 | grep -oP 'dev \K\S+'
```

`Це виводить назву інтерфейсу безпосередньо, наприклад:`

```bash
enp191s0
```

### 2. Перевірте швидкість мережевого з'єднання

Переконайтеся, що з'єднання активне та працює на повній швидкості, перевіривши швидкість вашого інтерфейсу:

```bash
sudo ethtool <IFNAME> | grep Speed
```

> **Примітка**: Замініть `<IFNAME>` на назву вихідного інтерфейсу з [1. Визначення мережевих інтерфейсів](#1-determine-network-interfaces)

Ви маєте побачити швидкість `10000Mb/s`:

```bash
	Speed: 10000Mb/s
```

**Примітка**: якщо швидкість нижча за `10000Mb/s` або з'єднання не встановлюється, перевірте підключення кабелю та переконайтеся, що порт комутатора налаштовано на 10 Гбіт/с. Для деяких комутаторів потрібно вимкнути автоузгодження та встановити швидкість з'єднання вручну; зверніться до документації свого комутатора.

## Розширення виділення VRAM

> **Примітка**: виконайте цей крок як на Machine 1, так і на Machine 2.

### Налаштування пам'яті для запуску великих моделей

У Linux ROCm використовує спільний пул системної пам'яті, і за замовчуванням цей пул налаштований на половину обсягу системної пам'яті.

Цей обсяг можна збільшити, змінивши налаштування сторінок Translation Table Manager (TTM) ядра за наведеними нижче інструкціями. AMD рекомендує встановити мінімальний обсяг виділеної VRAM у BIOS (0.5 ГБ).

* Встановіть утиліту pipx та додайте шлях до встановлених за допомогою pipx wheel-пакетів у системний шлях пошуку.

  ```bash
  sudo apt install pipx
  pipx ensurepath
  ```

* Встановіть wheel-пакет amd-debug-tools із PyPI.
  ```bash
  pipx install amd-debug-tools
  ```

* Запустіть інструмент amd-ttm, щоб дізнатися поточні налаштування спільної пам'яті.
  ```bash
  amd-ttm
  ```

* Перенастройте параметри спільної пам'яті на **120 ГБ**:
  ```bash
  amd-ttm --set 120
  ```

* Перезавантажте систему, щоб зміни набули чинності.

## Ініціалізація контейнера vLLM

> **Примітка**: виконайте цей крок як на Machine 1, так і на Machine 2.

Ваш Ryzen AI Halo постачається з vLLM, упакованим у готовий образ контейнера, який ви запускаєте за допомогою Podman — безкоштовного інструменту з відкритим кодом для роботи з контейнерами.

### 1. Створення каталогу для завантаження моделі

Коли ви запускаєте модель Qwen3.5-397B у цьому посібнику, vLLM автоматично завантажить ваги моделі у вашу систему. Щоб забезпечити доступ до цих ваг зсередини контейнера, спочатку створіть каталог models, який контейнер зможе монтувати:

```bash
mkdir -p ~/.local/share/vLLM/models
```

### 2. Запустіть контейнер vLLM

Наведена нижче команда запускає контейнер і переносить вас в інтерактивну оболонку. Вона монтує щойно створений каталог моделей і передає ваш `IFNAME` у `NCCL_SOCKET_IFNAME` та `GLOO_SOCKET_IFNAME`, повідомляючи RCCL (бібліотеці, яку vLLM використовує для координації GPU в кластері), який інтерфейс використовувати.

Запустіть контейнер за допомогою:

```bash
sudo podman run -it --name vllm_cluster --replace --pull missing --network=host --device /dev/kfd --device /dev/dri -v ~/.local/share/vLLM/models:/opt/vLLM/models --env HF_HOME=/opt/vLLM/models --entrypoint="bin/bash" --shm-size=64g --pids-limit=-1 -e NCCL_SOCKET_IFNAME=<IFNAME> -e GLOO_SOCKET_IFNAME=<IFNAME> oci-registry.ryai.dev/ryai-vllm:latest
```

**Примітка**: Замініть `<IFNAME>` на назву вихідного мережевого інтерфейсу з розділу [1. Визначення мережевих інтерфейсів](#1-determine-network-interfaces)

## Запуск моделі на кластері

vLLM використовує Ray для оркестрації кластера та RCCL для обробки взаємодії GPU-GPU між вузлами. Одна машина виступає як **головний вузол** (Machine 1), координуючи інференс. Інша приєднується як **робочий вузол** (Machine 2), надаючи свою пам'ять GPU та обчислювальні ресурси.

> **Примітка**: Ray є опціональною залежністю для vLLM і доступний лише з попередньо налаштованого контейнера Podman.

Під час запуску vLLM розподіляє модель між обома вузлами за допомогою тензорного паралелізму. Після завантаження інференс виконується так, ніби він працює на одному прискорювачі.

### Крок 1: Запуск головного вузла Ray (Machine 1)

На Machine 1 запустіть головний вузол Ray, щоб ініціалізувати кластер:

```bash
ray start --head --port=6379 --node-ip-address=<MACHINE_1_IP> --num-gpus=1
```

**Знаходження `<MACHINE_1_IP>`**: На Машині 1 виконайте `hostname -I | awk '{print $1}'`, щоб дізнатися її локальну IP-адресу.
### Крок 2: Приєднання до кластера (Машина 2)

На Машині 2 підключіться до головного вузла, щоб сформувати кластер:

```bash
ray start --address=<MACHINE_1_IP>:6379 --node-ip-address=<MACHINE_2_IP> --num-gpus=1
```

> **Пошук `<MACHINE_2_IP>`**: на Машині 2 виконайте `hostname -I | awk '{print $1}'`, щоб знайти її локальну IP-адресу.

### Крок 3: Обслуговування моделі (Машина 1)

На Машині 1 запустіть сервер vLLM. Це автоматично завантажить модель і почне обслуговувати її на обох вузлах:

```bash
vllm serve Qwen/Qwen3.5-397B-A17B-GPTQ-Int4 \
  --port 7000 \
  --host 0.0.0.0 \
  --max-model-len 32768 \
  --gpu-memory-utilization 0.9 \
  --dtype float16 \
  --tensor-parallel-size 2 \
  --distributed-executor-backend ray \
  --enforce-eager \
  --language-model-only \
  --reasoning-parser qwen3
```

#### Довідник параметрів

| Прапорець | Призначення |
|------|---------|
| `--port` | Порт для обслуговування HTTP API |
| `--host` | IP-адреса для прив’язки сервера (`0.0.0.0` для всіх інтерфейсів) |
| `--max-model-len` | Максимальна довжина контексту в токенах |
| `--gpu-memory-utilization` | Частка пам’яті GPU для виділення (0.0–1.0) |
| `--dtype` | Тип даних для ваг моделі |
| `--tensor-parallel-size` | Кількість GPU для розподілу моделі (встановіть загальну кількість GPU у кластері) |
| `--distributed-executor-backend` | Бекенд для виконання на кількох вузлах (`ray` для кластерних розгортань) |
| `--enforce-eager` | Вимикає компіляцію CUDA graph для сумісності |
| `--language-model-only` | Пропускає завантаження допоміжних компонентів моделі (наприклад, енкодера зображень) |
| `--reasoning-parser` | Увімкнює структурований парсинг виводу міркувань для моделі |

Повний опис параметрів дивіться в [документації vLLM](https://docs.vllm.ai/en/latest/configuration/engine_args/).

## Доступ до моделі

vLLM надає API, сумісний з OpenAI, тож ви можете підключити будь-який сумісний клієнт або інтерфейс до вашого кластера. Одним із популярних варіантів є [Open WebUI](https://github.com/open-webui/open-webui), який надає інтерфейс чату на основі браузера.

Щоб підключити Open WebUI до вашої кінцевої точки vLLM:

1. Відкрийте **Settings** > **Admin Panel** > **Connections**
2. Натисніть **+** біля **Manage OpenAI API Connections**
3. Встановіть **Connection Type** на **External**
4. Встановіть **URL** на `http://<MACHINE_1_IP>:7000/v1`
5. У розділі **Auth** виберіть **None** зі спадного списку
6. Залиште поле **Model IDs** порожнім, щоб автоматично виявити всі моделі з кінцевої точки

> **Пошук `<MACHINE_1_IP>`**: на Машині 1 виконайте `hostname -I | awk '{print $1}'`, щоб знайти її локальну IP-адресу. Якщо ви заходите в Open WebUI з самої Машини 1, можна використовувати `http://localhost:7000/v1`.

![Налаштування підключення Open WebUI до кінцевої точки vLLM](assets/openwebui-connection.png)

Після підключення виберіть модель зі спадного списку моделей в Open WebUI та почніть спілкування. Тепер модель працює на обох ваших вузлах Ryzen AI Halo:

![Спілкування з Qwen3.5-397B в Open WebUI](assets/openwebui-chat.png)

## Наступні кроки

- **Дослідіть інші моделі**: знайдіть нові моделі на [Hugging Face](https://huggingface.co/models?&sort=trending), які вміщуються в загальну пам’ять GPU вашого кластера
- **Масштабуйте до чотирьох вузлів**: додайте ще дві системи Ryzen AI Halo як додаткові воркери Ray, щоб розподіляти моделі на ще більшу кількість GPU. Для цього потрібен Ethernet-комутатор щонайменше з чотирма портами, по одному на кожен вузол. Виконайте [Крок 2: Приєднання до кластера](#step-2-join-the-cluster-machine-2) на кожному додатковому воркері та відповідно збільшіть `--tensor-parallel-size`
- **Спробуйте інші стратегії паралелізму**: vLLM підтримує [expert parallel](https://docs.vllm.ai/en/latest/serving/expert_parallel_deployment/) для моделей типу mixture-of-experts і [data parallel](https://docs.vllm.ai/en/latest/serving/data_parallel_deployment/) для вищої пропускної здатності. Поекспериментуйте з `--enable-expert-parallel` та `--data-parallel-size`, щоб знайти найкращу конфігурацію для вашого навантаження
