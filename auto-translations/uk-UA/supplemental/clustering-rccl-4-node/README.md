# Кластеризація чотирьох Ryzen™ AI Halo за допомогою RCCL

## Огляд

Ваш Ryzen™ AI Halo вже здатен локально запускати великі мовні моделі. Кластеризація розширює ці можливості, об'єднуючи обсяг GPU-пам'яті кількох систем через локальну мережу, що надає доступ до ще більших моделей з потужнішими можливостями міркування, кращою генерацією коду та глибшим розумінням багатьох мов — і все це повністю на вашому власному обладнанні.

Цей посібник навчить вас кластеризувати чотири системи Ryzen AI Halo за допомогою RCCL (ROCm Communication Collectives Library) разом із vLLM і запускати Qwen3.5-397B — модель із 397 млрд параметрів — на всіх чотирьох машинах з прискоренням ROCm.

## Що ви дізнаєтесь

- Як розширити виділення VRAM на системах Ryzen AI Halo
- Запуск vLLM з підтримкою ROCm
- Налаштування RCCL для багатовузлового тензорно-паралельного інференсу на чотирьох системах Ryzen AI Halo
- Запуск моделі з 397 млрд параметрів на чотирьох системах Ryzen AI Halo, об'єднаних у мережу

## Передумови

### Обладнання

Цей посібник вимагає чотирьох пристроїв Ryzen AI Halo та одного Ethernet-комутатора, з'єднаних за топологією "зірка", де кожен пристрій підключений безпосередньо до комутатора.

| Компонент | Кількість | Опис |
|-----------|----------|-------------|
| Ryzen AI Halo | 4 | Обчислювальні вузли, що формують кластер |
| Ethernet-комутатор 10Gbps | 1 | Центральний комутатор для забезпечення зв'язку між вузлами Ryzen AI Halo (щонайменше 4 порти) |
| Ethernet-кабель | 4 | З'єднує кожен пристрій Halo з комутатором (рекомендовано Cat 7 або вище) |

> **Примітка**: Для підключення чотирьох пристроїв Ryzen AI Halo потрібні чотири порти Ethernet-комутатора. П'ятий порт потрібен, якщо ви звертаєтесь до моделі з окремої клієнтської машини, а не з одного з пристроїв Halo.

## Налаштування фізичного обладнання

> **Примітка**: Виконайте цей крок на всіх чотирьох машинах (Machine 1 – Machine 4).

Підключіть кожен пристрій Ryzen AI Halo до Ethernet-комутатора за допомогою кабелю Cat 7 (або вище). Це встановить з'єднання 10Gbps, яке використовується для високошвидкісного зв'язку між вузлами.

### 1. Визначення мережевих інтерфейсів

На кожній машині визначте назву її мережевого інтерфейсу та запишіть її (далі в інструкціях вона позначатиметься як `IFNAME`). Виконайте:

```bash
ip route get 1.1.1.1 | grep -oP 'dev \K\S+'
```

Це виведе назву інтерфейсу безпосередньо, наприклад:

```bash
enp191s0
```

### 2. Перевірка швидкості мережевого з'єднання

Переконайтеся, що з'єднання активне і працює на повній швидкості, перевіривши швидкість вашого інтерфейсу:

```bash
sudo ethtool <IFNAME> | grep Speed
```

> **Примітка**: Замініть `<IFNAME>` на назву вихідного інтерфейсу з [1. Визначення мережевих інтерфейсів](#1-determine-network-interfaces)

Ви маєте побачити швидкість `10000Mb/s`:

```bash
	Speed: 10000Mb/s
```

> **Примітка**: Якщо швидкість нижча за `10000Mb/s` або з'єднання не встановлюється, перевірте з'єднання кабелю та переконайтеся, що порт комутатора налаштований на 10Gbps. Деякі комутатори вимагають вимкнення автоузгодження та ручного встановлення швидкості з'єднання; зверніться до документації вашого комутатора.

## Розширення виділення VRAM

> **Примітка**: Виконайте цей крок на всіх чотирьох машинах (Machine 1 – Machine 4).

### Налаштування пам'яті для запуску великих моделей

У Linux ROCm використовує спільний пул системної пам'яті, і за замовчуванням цей пул налаштований на половину обсягу системної пам'яті.

Цей обсяг можна збільшити, змінивши налаштування сторінок Translation Table Manager (TTM) ядра, виконавши наведені нижче інструкції. AMD рекомендує встановити мінімальний обсяг виділеної VRAM у BIOS (0.5 GB).

* Встановіть утиліту pipx і додайте шлях до встановлених нею колес (wheels) у системний шлях пошуку.

  ```bash
  sudo apt install pipx
  pipx ensurepath
  ```

* Встановіть колесо amd-debug-tools з PyPI.
  ```bash
  pipx install amd-debug-tools
  ```

* Запустіть інструмент amd-ttm, щоб переглянути поточні налаштування спільної пам'яті.
  ```bash
  amd-ttm
  ```

* Змініть налаштування спільної пам'яті на **120 GB**:
  ```bash
  amd-ttm --set 120
  ```

* Перезавантажте систему, щоб зміни набули чинності.

## Ініціалізація контейнера vLLM

> **Примітка**: Виконайте цей крок на всіх чотирьох машинах (Machine 1 – Machine 4).

Ваш Ryzen AI Halo постачається з vLLM, упакованим у готовий образ контейнера, який ви запускаєте за допомогою Podman — безкоштовного інструменту для роботи з контейнерами з відкритим кодом.

### 1. Створення каталогу для завантаження моделі

Коли ви розгортатимете модель Qwen3.5-397B у цьому посібнику, vLLM автоматично завантажить ваги моделі у вашу систему. Щоб переконатися, що ці ваги доступні з середини контейнера, спершу створіть каталог моделей, який контейнер зможе змонтувати:

```bash
mkdir -p ~/.local/share/vLLM/models
```

### 2. Запуск контейнера vLLM

Наведена нижче команда запускає контейнер і переводить вас в інтерактивну оболонку. Вона монтує щойно створений каталог моделей і передає ваш `IFNAME` у `NCCL_SOCKET_IFNAME` та `GLOO_SOCKET_IFNAME`, повідомляючи RCCL (бібліотеку, яку vLLM використовує для координації GPU в кластері) про те, який інтерфейс використовувати.

Запустіть контейнер за допомогою:

```bash
sudo podman run -it --name vllm_cluster --replace --pull missing --network=host --device /dev/kfd --device /dev/dri -v ~/.local/share/vLLM/models:/opt/vLLM/models --env HF_HOME=/opt/vLLM/models --entrypoint="bin/bash" --shm-size=64g --pids-limit=-1 -e NCCL_SOCKET_IFNAME=<IFNAME> -e GLOO_SOCKET_IFNAME=<IFNAME> oci-registry.ryai.dev/ryai-vllm:latest
```

> **Примітка**: Замініть `<IFNAME>` на назву вихідного інтерфейсу з [1. Визначення мережевих інтерфейсів](#1-determine-network-interfaces)

## Запуск моделі на кластері

vLLM використовує Ray для оркестрації кластера та RCCL для обробки зв'язку GPU-GPU між вузлами. Одна машина виступає головним вузлом (Machine 1), координуючи інференс. Інші три приєднуються як вузли-воркери (Machine 2, 3 та 4), надаючи свою GPU-пам'ять і обчислювальні ресурси.

> **Примітка**: Ray є опціональною залежністю для vLLM і доступний лише всередині попередньо налаштованого контейнера Podman.

При запуску vLLM розподіляє модель на всі чотири вузли за допомогою тензорного паралелізму. Після завантаження інференс виконується так, ніби все працює на одному прискорювачі.

#### Запобігання помилкам OOM у Ray

За замовчуванням Ray відстежує використання пам'яті хоста на кожному вузлі та завершує найбільший процес, коли використання пам'яті перевищує 95%. На вашому Ryzen™ AI Halo GPU та хост спільно використовують один пул пам'яті, тому завантаження моделі може спричинити `ray.exceptions.OutOfMemoryError` і завершення процесу-воркера.

Щоб запобігти цьому, ми експортуємо `RAY_memory_monitor_refresh_ms=0` на кожній машині перед запуском та приєднанням до кластера.
### Крок 1: Запустіть головний вузол Ray (Machine 1)

На Machine 1 запустіть головний вузол Ray, щоб ініціалізувати кластер:

```bash
export RAY_memory_monitor_refresh_ms=0
ray start --head --port=6379 --node-ip-address=<MACHINE_1_IP> --num-gpus=1
```

> **Пошук `<MACHINE_1_IP>`**: на Machine 1 виконайте `hostname -I | awk '{print $1}'`, щоб знайти її локальну IP-адресу.

### Крок 2: Приєднайтеся до кластера (Machines 2, 3 і 4)

На кожній з машин Machine 2, 3 і 4 підключіться до головного вузла, щоб сформувати кластер:

```bash
export RAY_memory_monitor_refresh_ms=0
ray start --address=<MACHINE_1_IP>:6379 --node-ip-address=<MACHINE_N_IP> --num-gpus=1
```

> **Пошук `<MACHINE_N_IP>`**: на кожній робочій машині виконайте `hostname -I | awk '{print $1}'`, щоб знайти її локальну IP-адресу.

### Крок 3: Запустіть обслуговування моделі (Machine 1)

На Machine 1 запустіть сервер vLLM. Він автоматично завантажить модель і почне обслуговувати її на всіх чотирьох вузлах:

```bash
vllm serve Qwen/Qwen3.5-397B-A17B-GPTQ-Int4 \
  --port 7000 \
  --host 0.0.0.0 \
  --max-model-len 131072 \
  --gpu-memory-utilization 0.8 \
  --dtype float16 \
  --tensor-parallel-size 4 \
  --distributed-executor-backend ray \
  --enforce-eager \
  --language-model-only \
  --reasoning-parser qwen3
```

#### Довідка з параметрів

| Прапорець | Призначення |
|------|---------|
| `--port` | Порт, на якому обслуговується HTTP API |
| `--host` | IP-адреса для прив’язки сервера (`0.0.0.0` для всіх інтерфейсів) |
| `--max-model-len` | Максимальна довжина контексту в токенах |
| `--gpu-memory-utilization` | Частка пам’яті GPU для виділення (0.0–1.0) |
| `--dtype` | Тип даних для ваг моделі |
| `--tensor-parallel-size` | Кількість GPU для розподілу моделі (встановіть рівним загальній кількості GPU в кластері) |
| `--distributed-executor-backend` | Бекенд для виконання на кількох вузлах (`ray` для розгортань на кластерах) |
| `--enforce-eager` | Вимикає компіляцію CUDA graph для сумісності |
| `--language-model-only` | Пропускає завантаження допоміжних компонентів моделі (наприклад, кодувальника зображень) |
| `--reasoning-parser` | Вмикає структурований розбір виводу міркувань для моделі |

Повний опис параметрів наведено в [документації vLLM](https://docs.vllm.ai/en/latest/configuration/engine_args/).

## Доступ до моделі

vLLM надає сумісний з OpenAI API, тож ви можете підключити будь-який сумісний клієнт або інтерфейс до вашого кластера. Одним із популярних варіантів є [Open WebUI](https://github.com/open-webui/open-webui), який надає чат-інтерфейс на базі браузера.

Щоб підключити Open WebUI до вашої кінцевої точки vLLM:

1. Відкрийте **Settings** > **Admin Panel** > **Connections**
2. Натисніть **+** біля **Manage OpenAI API Connections**
3. Встановіть **Connection Type** на **External**
4. Встановіть **URL** на `http://<MACHINE_1_IP>:7000/v1`
5. У розділі **Auth** виберіть **None** зі спадного списку
6. Залиште поле **Model IDs** порожнім, щоб автоматично виявити всі моделі з кінцевої точки

> **Пошук `<MACHINE_1_IP>`**: на Machine 1 виконайте `hostname -I | awk '{print $1}'`, щоб знайти її локальну IP-адресу. Якщо ви заходите в Open WebUI з самої Machine 1, можна використати `http://localhost:7000/v1`.

![Налаштування підключення Open WebUI до кінцевої точки vLLM](assets/openwebui-connection.png)

Після підключення виберіть модель зі спадного списку моделей в Open WebUI та почніть спілкування. Тепер модель працює на всіх чотирьох ваших вузлах Ryzen AI Halo:

![Спілкування з Qwen3.5-397B в Open WebUI](assets/openwebui-chat.png)

Поекспериментуйте з `--enable-expert-parallel` та `--data-parallel-size`, щоб знайти найкращу конфігурацію для вашого робочого навантаження
