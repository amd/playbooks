## نظرة عامة

يُعد vLLM محرك استدلال عالي الأداء مصمم لنماذج اللغة الكبيرة (LLMs). يوفر خدمة محسّنة مع تجميع دفعات مستمر (continuous batching) لتحقيق إنتاجية عالية وواجهة برمجة تطبيقات متوافقة مع OpenAI لتكامل سلس مع التطبيقات. هذا يجعل vLLM مناسبًا بشكل كبير لعمليات النشر الإنتاجية حيث تكون السرعة وكفاءة الموارد أمرًا بالغ الأهمية.

يعلّمك هذا الدليل كيفية خدمة نماذج اللغة الكبيرة باستخدام vLLM المُحتوى (containerized) على وحدة معالجة الرسومات المدمجة (iGPU) والتفاعل مع النماذج عبر واجهة برمجة تطبيقات OpenAI Python.

## ما ستتعلمه

- كيفية إعداد وتشغيل خادم vLLM مع دعم AMD ROCm™
- كيفية التفاعل مع النماذج عبر نقاط نهاية واجهة برمجة تطبيقات متوافقة مع OpenAI
- كيفية إرسال المطالبات (prompts) إلى الخادم المحلي باستخدام `vllm-prompt`

## تثبيت متطلبات البرامج الأساسية

يعمل vLLM داخل حاوية مُعدّة مسبقًا تحتوي على ROCm وتبعياته المتوافقة مسبقًا. لا حاجة لأي تثبيت إضافي.

لا توجد خطوة تثبيت لـ vLLM على الجهاز المضيف. ابدأ تشغيل vLLM باستخدام:

```bash
vllm-launch
```

يقوم المشغّل (launcher) بتشغيل الحاوية، واستهداف وحدة معالجة الرسومات المدمجة، وكشف خادم vLLM محلي متوافق مع OpenAI. بدلاً من ذلك، انقر على أيقونة vLLM في شريط المهام.

## البدء السريع

### 1. تأكد من أن خادم vLLM قيد التشغيل

قد يستغرق `vllm-launch` بضع دقائق لتهيئة كل شيء. بمجرد أن يبدأ، يصبح الخادم متاحًا على `http://localhost:8001`. أبقِ طرفية التشغيل مفتوحة لأن الخادم يعمل في المقدمة، ثم افتح طرفية منفصلة للخطوات المتبقية. تستخدم الأمثلة أدناه `Qwen/Qwen3-1.7B`؛ إذا كان المشغّل لديك معدًا لنموذج مختلف، استبدل معرّف ذلك النموذج في الطلبات.

### 2. إرسال مطالبة (Prompt)

استخدم السكربت المتوفر `vllm-prompt` لإرسال طلب إلى خادم vLLM المحلي المتوافق مع OpenAI:

```bash
vllm-prompt "Tell me a story"
```

### 3. التحدث مع النموذج باستخدام واجهة برمجة تطبيقات OpenAI Python

نظرًا لأن vLLM يكشف واجهة برمجة تطبيقات متوافقة مع OpenAI، يمكنك استخدام حزمة `openai` الخاصة بـ Python للتفاعل معها.

أولاً، أنشئ بيئة افتراضية لـ Python:

<!-- @os:linux -->
<!-- @device:halo_box -->
```bash
sudo apt install -y python3-venv
python3 -m venv vllm-env
source vllm-env/bin/activate
```
<!-- @device:end -->
<!-- @os:end -->

ثبّت حزمة OpenAI
```bash
pip install openai
```

أنشئ عميل `OpenAI` موجّهًا نحو خادم vLLM المحلي بدلاً من خوادم OpenAI. يتطلب العميل `api_key` لكن vLLM لا يتحقق منه، لذا تصلح أي سلسلة نصية:

```python
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:8001/v1",
    api_key="EMPTY",
)
```

بعد ذلك، أرسل طلب إكمال محادثة (chat completion). يستخدم هذا نفس تنسيق الرسائل الخاص بواجهة برمجة تطبيقات OpenAI — قائمة من الرسائل مع أدوار مثل `"user"` و`"assistant"`. يعني ضبط `stream=True` أن الاستجابة ستصل تدريجيًا بدلاً من دفعة واحدة:

```python
response = client.chat.completions.create(
    model="Qwen/Qwen3-1.7B",
    messages=[
        {"role": "user", "content": "Tell me a short story"},
    ],
    max_tokens=2048,  # Maximum number of tokens the model will generate in its response
    stream=True,
)
```

أخيرًا، كرر العملية عبر الأجزاء المتدفقة واطبع كل جزء من النص فور وصوله:

```python
for chunk in response:
    content = chunk.choices[0].delta.content
    if content:
        print(content, end="", flush=True)
```

يحتوي السكربت المرفق [chat_with_model.py](assets/chat_with_model.py) على المثال الكامل ويمكن تنزيله.


## اختيار وتهيئة النموذج

بشكل افتراضي، يخدم `vllm-launch` نموذج `Qwen/Qwen3-1.7B` كنموذج اختباري على المنفذ `8001`. يمكنك تغيير النموذج والمنفذ ومعاملات خدمة vLLM دون إعادة بناء الحاوية أو تعديلها.

### النماذج التي اختبرتها AMD

النماذج التالية معدة مسبقًا ومتحقق من صحتها بواسطة AMD:

| النموذج | ملاحظات |
|-------|-------|
| `Qwen/Qwen3-1.7B` | النموذج الافتراضي. خفيف وسريع التحميل. |
| `openai/gpt-oss-20b` | نموذج أكبر للحصول على استجابات ذات جودة أعلى. |

### تشغيل نموذج مختلف

مرّر معرّف النموذج باستخدام `--model` (أو `-m`):

```bash
vllm-launch --model openai/gpt-oss-20b
```

### تغيير المنفذ

مرّر منفذًا أعلى من 1024 باستخدام `--port` (أو `-p`)؛ الافتراضي هو `8001`:

```bash
vllm-launch --port 8080 --model openai/gpt-oss-20b
```

إذا غيّرت المنفذ، وجّه `base_url` الخاص بالعميل إلى نفس المنفذ (على سبيل المثال `http://localhost:8080/v1`).

### تمرير معاملات vLLM إضافية

يتم تمرير أي وسائط إضافية مباشرة إلى vLLM، لذا يمكنك ضبط سلوك الخدمة مثل طول السياق أو نوع البيانات. هناك طريقتان لتوفيرها.

**مضمنة (Inline)**، بعد خيارات المشغّل:

```bash
vllm-launch --model openai/gpt-oss-20b --max-model-len 8192
```

**دائمة**، في ملف تهيئة على المسار `~/.local/share/vLLM/vllm-launch.conf`. هذا الملف غير موجود افتراضيًا — أنشئه وأضف وسائطك كمصفوفة Bash:

```bash
VLLM_EXTRA_ARGS=(--max-model-len 8192 --dtype float16)
```

استخدم `+=` لإلحاق الوسائط بالوسائط الافتراضية بدلاً من استبدالها:

```bash
VLLM_EXTRA_ARGS+=(--max-model-len 8192)
```

لمشاهدة جميع خيارات المشغّل في أي وقت، نفّذ:

```bash
vllm-launch --help
```

### أين تُخزَّن النماذج

يبحث `vllm-launch` عن النماذج في موقعين:

| الموقع | المسار |
|----------|------|
| نماذج النظام | `/var/cache/models` |
| نماذج المستخدم | `~/.local/share/vLLM/models` |

يمكنك وضع نموذج تم تنزيله في أي من الدليلين وتشغيله بتمرير مساره أو معرّفه إلى `--model`:

```bash
vllm-launch --model /var/cache/models/my-model
```

> **ملاحظة**: من المتوقع أن يعمل تشغيل نموذجك الخاص الذي قمت بتنزيله بهذه الطريقة بمجرد وضع النموذج في أحد الدليلين أعلاه، إلا أن سير العمل هذا لم يتم التحقق من صحته رسميًا بعد من قِبل AMD.

## الملخص

في هذا الدليل، تعلّمت كيفية:

- تشغيل vLLM المُحتوى مع دعم ROCm على وحدة معالجة الرسومات المدمجة
- تشغيل خادم vLLM مع نقاط نهاية واجهة برمجة تطبيقات متوافقة مع OpenAI على المنفذ 8001
- إرسال المطالبات باستخدام `vllm-prompt`
- إجراء استدعاءات واجهة برمجة التطبيقات إلى خادم vLLM باستخدام كل من الطلبات المتدفقة وغير المتدفقة
- استكشاف المشكلات الشائعة المتعلقة ببدء تشغيل الخادم والذاكرة واتصالات العميل وإصلاحها

لديك الآن نشر vLLM مُحتوى لخدمة نماذج اللغة الكبيرة بأداء محسّن على وحدة معالجة الرسومات المدمجة.

## الخطوات التالية

- **جرّب نماذج مختلفة** — استخدم `vllm-launch --model <model>` لتجربة نماذج لغة كبيرة مختلفة ومقارنة الأداء (راجع [اختيار وتهيئة النموذج](#choosing-and-configuring-a-model)).
- **ابنِ تطبيقًا** — استخدم واجهة برمجة التطبيقات المتوافقة مع OpenAI لدمج vLLM في تطبيق Python أو روبوت محادثة أو سير عمل آلي.
- **الضبط الدقيق والخدمة** — اضبط نموذجًا بدقة باستخدام LoRA أو QLoRA، ثم انشره باستخدام vLLM للحصول على استدلال محسّن.
