# การรวมคลัสเตอร์ Ryzen™ AI Halo สี่เครื่องด้วย RCCL

## ภาพรวม

Ryzen™ AI Halo ของคุณมีความสามารถในการรันโมเดลภาษาขนาดใหญ่ในเครื่องได้อยู่แล้ว การรวมคลัสเตอร์จะยกระดับความสามารถนี้ไปอีกขั้น ด้วยการผสานหน่วยความจำ GPU ของหลายระบบเข้าด้วยกันผ่านเครือข่ายท้องถิ่น ทำให้คุณสามารถเข้าถึงโมเดลที่ใหญ่ขึ้น มีความสามารถในการให้เหตุผลที่แข็งแกร่งขึ้น สร้างโค้ดได้ดีขึ้น และเข้าใจภาษาต่าง ๆ ได้ลึกซึ้งยิ่งขึ้น ทั้งหมดนี้ทำงานบนฮาร์ดแวร์ของคุณเองโดยสมบูรณ์

คู่มือนี้จะสอนวิธีการรวมคลัสเตอร์ของระบบ Ryzen AI Halo จำนวนสี่เครื่องโดยใช้ RCCL (ROCm Communication Collectives Library) ร่วมกับ vLLM และรัน Qwen3.5-397B ซึ่งเป็นโมเดลขนาด 397 พันล้านพารามิเตอร์ บนเครื่องทั้งสี่พร้อมกัน ด้วยการเร่งความเร็วของ ROCm

## สิ่งที่คุณจะได้เรียนรู้

- วิธีการขยายการจัดสรร VRAM บนระบบ Ryzen AI Halo
- การเปิดใช้งาน vLLM พร้อมการรองรับ ROCm
- การกำหนดค่า RCCL สำหรับการอนุมานแบบขนานตามเทนเซอร์ (tensor-parallel) ข้ามหลายโหนดบนระบบ Ryzen AI Halo สี่เครื่อง
- การรันโมเดลขนาด 397 พันล้านพารามิเตอร์บนระบบ Ryzen AI Halo สี่เครื่องที่เชื่อมต่อผ่านเครือข่าย

## ข้อกำหนดเบื้องต้น

### ฮาร์ดแวร์

คู่มือนี้ต้องใช้ Ryzen AI Halo จำนวนสี่เครื่อง และสวิตช์อีเทอร์เน็ตหนึ่งตัว โดยเชื่อมต่อในรูปแบบโทโพโลยีดาว (star topology) ซึ่งแต่ละเครื่องเชื่อมต่อโดยตรงกับสวิตช์

| ส่วนประกอบ | จำนวน | รายละเอียด |
|-----------|----------|-------------|
| Ryzen AI Halo | 4 | โหนดประมวลผลที่ประกอบเป็นคลัสเตอร์ |
| สวิตช์อีเทอร์เน็ต 10Gbps | 1 | สวิตช์ส่วนกลางที่ช่วยให้ Ryzen AI Halo หลายโหนดสื่อสารกันได้ (อย่างน้อย 4 พอร์ต) |
| สายอีเทอร์เน็ต | 4 | เชื่อมต่อแต่ละเครื่อง Halo เข้ากับสวิตช์ (แนะนำให้ใช้ Cat 7 หรือสูงกว่า) |

> **หมายเหตุ**: ต้องใช้พอร์ตสวิตช์อีเทอร์เน็ตสี่พอร์ตเพื่อเชื่อมต่อเครื่อง Ryzen AI Halo ทั้งสี่เครื่อง และจำเป็นต้องมีพอร์ตที่ห้าหากคุณเข้าถึงโมเดลจากเครื่องไคลเอนต์แยกต่างหากแทนที่จะเข้าถึงจากเครื่อง Halo เครื่องใดเครื่องหนึ่ง

## การตั้งค่าฮาร์ดแวร์ทางกายภาพ

> **หมายเหตุ**: ดำเนินการขั้นตอนนี้บนเครื่องทั้งสี่เครื่อง (เครื่องที่ 1 ถึงเครื่องที่ 4)

เชื่อมต่อเครื่อง Ryzen AI Halo แต่ละเครื่องเข้ากับสวิตช์อีเทอร์เน็ตโดยใช้สาย Cat 7 (หรือสูงกว่า) การทำเช่นนี้จะสร้างลิงก์ความเร็ว 10Gbps ที่ใช้สำหรับการสื่อสารความเร็วสูงระหว่างโหนด

### 1. กำหนดอินเทอร์เฟซเครือข่าย

บนแต่ละเครื่อง ให้ค้นหาชื่ออินเทอร์เฟซเครือข่ายของเครื่องและจดบันทึกไว้ (จะเรียกว่า `IFNAME` ในคำแนะนำส่วนที่เหลือ) รันคำสั่ง:

```bash
ip route get 1.1.1.1 | grep -oP 'dev \K\S+'
```

คำสั่งนี้จะแสดงชื่ออินเทอร์เฟซโดยตรง ตัวอย่างเช่น:

```bash
enp191s0
```

### 2. ตรวจสอบความเร็วของลิงก์เครือข่าย

ยืนยันว่าลิงก์ทำงานอยู่และทำงานที่ความเร็วเต็มรูปแบบ โดยตรวจสอบความเร็วของอินเทอร์เฟซของคุณ:

```bash
sudo ethtool <IFNAME> | grep Speed
```

> **หมายเหตุ**: แทนที่ `<IFNAME>` ด้วยชื่ออินเทอร์เฟซผลลัพธ์จาก [1. กำหนดอินเทอร์เฟซเครือข่าย](#1-determine-network-interfaces)

คุณควรเห็นความเร็วที่ `10000Mb/s`:

```bash
	Speed: 10000Mb/s
```

> **หมายเหตุ**: หากความเร็วต่ำกว่า `10000Mb/s` หรือลิงก์ไม่ขึ้น ให้ตรวจสอบการเชื่อมต่อสายเคเบิลและยืนยันว่าพอร์ตสวิตช์ถูกตั้งค่าเป็น 10Gbps สวิตช์บางรุ่นจำเป็นต้องปิดการเจรจาอัตโนมัติ (auto-negotiation) และตั้งค่าความเร็วลิงก์ด้วยตนเอง โปรดดูเอกสารของสวิตช์ของคุณ

## การขยายการจัดสรร VRAM

> **หมายเหตุ**: ดำเนินการขั้นตอนนี้บนเครื่องทั้งสี่เครื่อง (เครื่องที่ 1 ถึงเครื่องที่ 4)

### การกำหนดค่าหน่วยความจำสำหรับการรันโมเดลขนาดใหญ่

บน Linux ROCm ใช้พูลหน่วยความจำระบบร่วมกัน (shared system memory pool) และพูลนี้ถูกกำหนดค่าเริ่มต้นไว้ที่ครึ่งหนึ่งของหน่วยความจำระบบ

ปริมาณนี้สามารถเพิ่มได้โดยการเปลี่ยนการตั้งค่าหน้า Translation Table Manager (TTM) ของเคอร์เนล ตามคำแนะนำต่อไปนี้ AMD แนะนำให้ตั้งค่า VRAM เฉพาะขั้นต่ำใน BIOS (0.5 GB)

* ติดตั้งยูทิลิตี pipx และเพิ่มพาธสำหรับ wheel ที่ติดตั้งโดย pipx เข้าสู่พาธการค้นหาของระบบ

  ```bash
  sudo apt install pipx
  pipx ensurepath
  ```

* ติดตั้ง wheel amd-debug-tools จาก PyPI
  ```bash
  pipx install amd-debug-tools
  ```

* รันเครื่องมือ amd-ttm เพื่อสอบถามการตั้งค่าปัจจุบันสำหรับหน่วยความจำที่ใช้ร่วมกัน
  ```bash
  amd-ttm
  ```

* กำหนดค่าการตั้งค่าหน่วยความจำร่วมใหม่เป็น **120 GB**:
  ```bash
  amd-ttm --set 120
  ```

* รีบูตระบบเพื่อให้การเปลี่ยนแปลงมีผล

## การเริ่มต้นคอนเทนเนอร์ vLLM

> **หมายเหตุ**: ดำเนินการขั้นตอนนี้บนเครื่องทั้งสี่เครื่อง (เครื่องที่ 1 ถึงเครื่องที่ 4)

Ryzen AI Halo ของคุณมาพร้อมกับ vLLM ที่บรรจุอยู่ภายในอิมเมจคอนเทนเนอร์ที่สร้างไว้ล่วงหน้า ซึ่งคุณสามารถรันได้โดยใช้ Podman ซึ่งเป็นเครื่องมือคอนเทนเนอร์แบบฟรีและโอเพนซอร์ส

### 1. สร้างไดเรกทอรีดาวน์โหลดโมเดล

เมื่อคุณให้บริการโมเดล Qwen3.5-397B ในคู่มือนี้ vLLM จะดาวน์โหลดน้ำหนักโมเดล (model weights) ไปยังระบบของคุณโดยอัตโนมัติ เพื่อให้แน่ใจว่าน้ำหนักเหล่านั้นสามารถเข้าถึงได้จากภายในคอนเทนเนอร์ ก่อนอื่นให้สร้างไดเรกทอรีโมเดลที่คอนเทนเนอร์สามารถเมาท์ได้:

```bash
mkdir -p ~/.local/share/vLLM/models
```

### 2. เปิดใช้งานคอนเทนเนอร์ vLLM

คำสั่งด้านล่างจะเปิดใช้งานคอนเทนเนอร์และนำคุณเข้าสู่เชลล์แบบโต้ตอบ (interactive shell) โดยจะเมาท์ไดเรกทอรีโมเดลที่คุณเพิ่งสร้างขึ้น และส่งค่า `IFNAME` ของคุณไปยัง `NCCL_SOCKET_IFNAME` และ `GLOO_SOCKET_IFNAME` เพื่อบอกให้ RCCL (ไลบรารีที่ vLLM ใช้ในการประสานงาน GPU ข้ามคลัสเตอร์) ทราบว่าควรใช้อินเทอร์เฟซใด

เริ่มต้นคอนเทนเนอร์ด้วย:

```bash
sudo podman run -it --name vllm_cluster --replace --pull missing --network=host --device /dev/kfd --device /dev/dri -v ~/.local/share/vLLM/models:/opt/vLLM/models --env HF_HOME=/opt/vLLM/models --entrypoint="bin/bash" --shm-size=64g --pids-limit=-1 -e NCCL_SOCKET_IFNAME=<IFNAME> -e GLOO_SOCKET_IFNAME=<IFNAME> oci-registry.ryai.dev/ryai-vllm:latest
```

> **หมายเหตุ**: แทนที่ `<IFNAME>` ด้วยชื่ออินเทอร์เฟซผลลัพธ์จาก [1. กำหนดอินเทอร์เฟซเครือข่าย](#1-determine-network-interfaces)

## การรันโมเดลบนคลัสเตอร์

vLLM ใช้ Ray ในการจัดการคลัสเตอร์ และใช้ RCCL ในการจัดการการสื่อสารระหว่าง GPU ต่อ GPU ข้ามโหนด เครื่องหนึ่งทำหน้าที่เป็นโหนดหลัก (head node) (เครื่องที่ 1) ซึ่งประสานงานการอนุมาน ส่วนอีกสามเครื่องจะเข้าร่วมเป็นโหนดผู้ปฏิบัติงาน (worker nodes) (เครื่องที่ 2, 3 และ 4) โดยสมทบหน่วยความจำ GPU และพลังการประมวลผลของตนเข้ามา

> **หมายเหตุ**: Ray เป็นดีเพนเดนซีทางเลือกสำหรับ vLLM และสามารถใช้งานได้จากภายในคอนเทนเนอร์ Podman ที่กำหนดค่าไว้ล่วงหน้าเท่านั้น

เมื่อเริ่มทำงาน vLLM จะแบ่งโมเดลออกเป็นส่วน ๆ (shard) ไปยังทั้งสี่โหนดโดยใช้ tensor parallelism เมื่อโหลดเสร็จแล้ว การอนุมานจะดำเนินไปราวกับว่ากำลังทำงานบันตัวเร่งความเร็วเพียงตัวเดียว

#### การป้องกันข้อผิดพลาด Ray OOM

โดยค่าเริ่มต้น Ray จะตรวจสอบหน่วยความจำของโฮสต์ (host memory) บนแต่ละโหนด และจะหยุดการทำงานของโพรเซสที่ใหญ่ที่สุดเมื่อการใช้งานหน่วยความจำเกิน 95% บน Ryzen™ AI Halo ของคุณ GPU และโฮสต์ใช้พูลหน่วยความจำร่วมกัน ดังนั้นการโหลดโมเดลอาจก่อให้เกิด `ray.exceptions.OutOfMemoryError` และหยุดการทำงานของโพรเซสผู้ปฏิบัติงาน (worker process)

เพื่อป้องกันปัญหานี้ เราจะทำการ export `RAY_memory_monitor_refresh_ms=0` บนแต่ละเครื่องก่อนเริ่มต้นและเข้าร่วมคลัสเตอร์
### ขั้นตอนที่ 1: เริ่มต้น Ray Head Node (เครื่องที่ 1)

บนเครื่องที่ 1 ให้เริ่มต้น Ray head node เพื่อเริ่มต้นคลัสเตอร์:

```bash
export RAY_memory_monitor_refresh_ms=0
ray start --head --port=6379 --node-ip-address=<MACHINE_1_IP> --num-gpus=1
```

> **การหา `<MACHINE_1_IP>`**: บนเครื่องที่ 1 ให้รันคำสั่ง `hostname -I | awk '{print $1}'` เพื่อหาที่อยู่ IP ของเครื่องนั้น

### ขั้นตอนที่ 2: เข้าร่วมคลัสเตอร์ (เครื่องที่ 2, 3 และ 4)

บนเครื่องที่ 2, 3 และ 4 แต่ละเครื่อง ให้เชื่อมต่อกับ head node เพื่อสร้างคลัสเตอร์:

```bash
export RAY_memory_monitor_refresh_ms=0
ray start --address=<MACHINE_1_IP>:6379 --node-ip-address=<MACHINE_N_IP> --num-gpus=1
```

> **การหา `<MACHINE_N_IP>`**: บนเครื่อง worker แต่ละเครื่อง ให้รันคำสั่ง `hostname -I | awk '{print $1}'` เพื่อหาที่อยู่ IP ของเครื่องนั้น

### ขั้นตอนที่ 3: เสิร์ฟโมเดล (เครื่องที่ 1)

บนเครื่องที่ 1 ให้เปิดใช้งานเซิร์ฟเวอร์ vLLM ซึ่งจะดาวน์โหลดโมเดลโดยอัตโนมัติและเริ่มเสิร์ฟโมเดลนั้นบนทั้งสี่โหนด:

```bash
vllm serve Qwen/Qwen3.5-397B-A17B-GPTQ-Int4 \
  --port 7000 \
  --host 0.0.0.0 \
  --max-model-len 131072 \
  --gpu-memory-utilization 0.8 \
  --dtype float16 \
  --tensor-parallel-size 4 \
  --distributed-executor-backend ray \
  --enforce-eager \
  --language-model-only \
  --reasoning-parser qwen3
```

#### ข้อมูลอ้างอิงพารามิเตอร์

| แฟล็ก | วัตถุประสงค์ |
|------|---------|
| `--port` | พอร์ตที่ใช้เสิร์ฟ HTTP API |
| `--host` | ที่อยู่ IP ที่จะผูกเซิร์ฟเวอร์ไว้ (`0.0.0.0` สำหรับทุกอินเทอร์เฟซ) |
| `--max-model-len` | ความยาวบริบทสูงสุดในหน่วยโทเค็น |
| `--gpu-memory-utilization` | สัดส่วนของหน่วยความจำ GPU ที่จะจัดสรร (0.0–1.0) |
| `--dtype` | ชนิดข้อมูลสำหรับน้ำหนักของโมเดล |
| `--tensor-parallel-size` | จำนวน GPU ที่จะใช้แบ่งโมเดล (ตั้งค่าเป็นจำนวน GPU ทั้งหมดในคลัสเตอร์) |
| `--distributed-executor-backend` | แบ็กเอนด์สำหรับการประมวลผลแบบหลายโหนด (`ray` สำหรับการปรับใช้แบบคลัสเตอร์) |
| `--enforce-eager` | ปิดใช้งานการคอมไพล์ CUDA graph เพื่อความเข้ากันได้ |
| `--language-model-only` | ข้ามการโหลดส่วนประกอบเสริมของโมเดล (เช่น vision encoder) |
| `--reasoning-parser` | เปิดใช้งานการแยกวิเคราะห์เอาต์พุตการให้เหตุผลแบบมีโครงสร้างสำหรับโมเดล |

สำหรับการใช้งานพารามิเตอร์ทั้งหมด โปรดดู[เอกสาร vLLM](https://docs.vllm.ai/en/latest/configuration/engine_args/)

## การเข้าถึงโมเดล

vLLM เปิดเผย API ที่เข้ากันได้กับ OpenAI ดังนั้นคุณสามารถเชื่อมต่อไคลเอนต์หรืออินเทอร์เฟซที่เข้ากันได้ใด ๆ เข้ากับคลัสเตอร์ของคุณได้ ตัวเลือกยอดนิยมอย่างหนึ่งคือ [Open WebUI](https://github.com/open-webui/open-webui) ซึ่งมอบอินเทอร์เฟซแชทแบบเบราว์เซอร์

ในการเชื่อมต่อ Open WebUI เข้ากับเอนด์พอยต์ vLLM ของคุณ:

1. เปิด **Settings** > **Admin Panel** > **Connections**
2. คลิก **+** ที่ **Manage OpenAI API Connections**
3. ตั้งค่า **Connection Type** เป็น **External**
4. ตั้งค่า **URL** เป็น `http://<MACHINE_1_IP>:7000/v1`
5. ที่ **Auth** ให้เลือก **None** จากเมนูแบบเลื่อนลง
6. เว้น **Model IDs** ให้ว่างไว้เพื่อค้นหาโมเดลทั้งหมดจากเอนด์พอยต์โดยอัตโนมัติ

> **การหา `<MACHINE_1_IP>`**: บนเครื่องที่ 1 ให้รันคำสั่ง `hostname -I | awk '{print $1}'` เพื่อหาที่อยู่ IP ของเครื่องนั้น หากเข้าถึง Open WebUI จากเครื่องที่ 1 เอง คุณสามารถใช้ `http://localhost:7000/v1` ได้

![การตั้งค่าการเชื่อมต่อ Open WebUI สำหรับเอนด์พอยต์ vLLM](assets/openwebui-connection.png)

เมื่อเชื่อมต่อแล้ว ให้เลือกโมเดลจากเมนูแบบเลื่อนลงของโมเดลใน Open WebUI แล้วเริ่มแชทได้เลย ตอนนี้โมเดลกำลังทำงานอยู่บนโหนด Ryzen AI Halo ทั้งสี่ของคุณแล้ว:

![การแชทกับ Qwen3.5-397B ใน Open WebUI](assets/openwebui-chat.png)

## ขั้นตอนถัดไป

- **สำรวจโมเดลอื่น ๆ**: ค้นพบโมเดลใหม่ ๆ บน [Hugging Face](https://huggingface.co/models?&sort=trending) ที่เหมาะสมกับหน่วยความจำ GPU รวมของคลัสเตอร์ของคุณ
- **ขยายขนาดเกินสี่โหนด**: เพิ่มระบบ Ryzen AI Halo เพิ่มเติมในฐานะ Ray worker เพิ่มเติม เพื่อแบ่งโมเดลให้กระจายไปยัง GPU ได้มากยิ่งขึ้น ทำตาม[ขั้นตอนที่ 2: เข้าร่วมคลัสเตอร์](#step-2-join-the-cluster-machines-2-3-and-4) บน worker เพิ่มเติมแต่ละเครื่อง และเพิ่มค่า `--tensor-parallel-size` ให้สอดคล้องกัน
- **ลองใช้กลยุทธ์การประมวลผลแบบขนานอื่น ๆ**: vLLM รองรับ[การประมวลผลแบบขนานสำหรับผู้เชี่ยวชาญ](https://docs.vllm.ai/en/latest/serving/expert_parallel_deployment/) สำหรับโมเดลแบบ mixture-of-experts และ[การประมวลผลแบบขนานสำหรับข้อมูล](https://docs.vllm.ai/en/latest/serving/data_parallel_deployment/) เพื่อเพิ่มปริมาณงาน ลองทดลองใช้ `--enable-expert-parallel` และ `--data-parallel-size` เพื่อหาการกำหนดค่าที่เหมาะสมที่สุดสำหรับงานของคุณ
