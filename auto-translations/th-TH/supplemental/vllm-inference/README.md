## ภาพรวม

vLLM คือเอนจินสำหรับการอนุมาน (inference) ประสิทธิภาพสูงที่ออกแบบมาสำหรับโมเดลภาษาขนาดใหญ่ (LLM) โดยมีการให้บริการที่ปรับให้เหมาะสมด้วย continuous batching เพื่อให้ได้ปริมาณงานสูง และมี API ที่เข้ากันได้กับ OpenAI เพื่อการผสานรวมกับแอปพลิเคชันได้อย่างราบรื่น สิ่งนี้ทำให้ vLLM เหมาะอย่างยิ่งสำหรับการใช้งานจริงในระบบผลิตที่ความเร็วและประสิทธิภาพการใช้ทรัพยากรเป็นสิ่งสำคัญ

เพลย์บุ๊กนี้จะสอนวิธีการให้บริการ LLM โดยใช้ vLLM ที่ทำงานในคอนเทนเนอร์บน GPU แบบรวม (integrated GPU) และวิธีการโต้ตอบกับโมเดลผ่าน OpenAI Python API

## สิ่งที่คุณจะได้เรียนรู้

- วิธีตั้งค่าและเริ่มต้นเซิร์ฟเวอร์ vLLM ที่รองรับ AMD ROCm™
- วิธีโต้ตอบกับโมเดลผ่านปลายทาง API ที่เข้ากันได้กับ OpenAI
- วิธีส่งพรอมป์ไปยังเซิร์ฟเวอร์ภายในเครื่องด้วย `vllm-prompt`

## การติดตั้งซอฟต์แวร์ที่จำเป็น

vLLM ทำงานในคอนเทนเนอร์ที่สร้างไว้ล่วงหน้าพร้อม ROCm และไลบรารีที่เกี่ยวข้องซึ่งจับคู่กันไว้แล้ว ไม่จำเป็นต้องติดตั้งเพิ่มเติม

ไม่มีขั้นตอนการติดตั้ง vLLM บนเครื่องโฮสต์ ให้เริ่มต้น vLLM ด้วย:

```bash
vllm-launch
```

ตัวเรียกใช้งาน (launcher) นี้จะเริ่มคอนเทนเนอร์ กำหนดเป้าหมายไปที่ GPU แบบรวม และเปิดใช้งานเซิร์ฟเวอร์ vLLM ที่เข้ากันได้กับ OpenAI ในเครื่องภายใน หรือคุณสามารถคลิกไอคอน vLLM ในแถบงาน (taskbar) แทนได้

## เริ่มต้นใช้งานอย่างรวดเร็ว

### 1. ยืนยันว่าเซิร์ฟเวอร์ vLLM กำลังทำงานอยู่

`vllm-launch` อาจใช้เวลาสักครู่ในการเริ่มต้นทุกอย่าง เมื่อเริ่มทำงานแล้ว เซิร์ฟเวอร์จะพร้อมใช้งานที่ `http://localhost:8001` ให้เปิดเทอร์มินัลที่ใช้เรียกใช้งานค้างไว้ เนื่องจากเซิร์ฟเวอร์ทำงานอยู่เบื้องหน้า (foreground) จากนั้นเปิดเทอร์มินัลแยกต่างหากสำหรับขั้นตอนที่เหลือ ตัวอย่างด้านล่างใช้ `Qwen/Qwen3-1.7B` หากตัวเรียกใช้งานของคุณถูกกำหนดค่าให้ใช้โมเดลอื่น ให้แทนที่ด้วยรหัสโมเดล (model ID) นั้นในคำขอ

### 2. ส่งพรอมป์

ใช้สคริปต์ `vllm-prompt` ที่ให้มาเพื่อส่งคำขอไปยังเซิร์ฟเวอร์ vLLM ที่เข้ากันได้กับ OpenAI ในเครื่องภายใน:

```bash
vllm-prompt "Tell me a story"
```

### 3. สนทนากับโมเดลโดยใช้ OpenAI Python API

เนื่องจาก vLLM เปิดให้ใช้งาน API ที่เข้ากันได้กับ OpenAI คุณจึงสามารถใช้แพ็กเกจ Python ชื่อ `openai` เพื่อโต้ตอบกับมันได้

ก่อนอื่น ให้สร้าง virtual environment ของ Python:

<!-- @os:linux -->
<!-- @device:halo_box -->
```bash
sudo apt install -y python3-venv
python3 -m venv vllm-env
source vllm-env/bin/activate
```
<!-- @device:end -->

ติดตั้งแพ็กเกจ OpenAI
```bash
pip install openai
```

สร้างไคลเอนต์ `OpenAI` ที่ชี้ไปยังเซิร์ฟเวอร์ vLLM ในเครื่องภายในแทนที่จะเป็นเซิร์ฟเวอร์ของ OpenAI ไคลเอนต์จำเป็นต้องมี `api_key` แต่ vLLM จะไม่ตรวจสอบความถูกต้อง ดังนั้นจึงใช้สตริงอะไรก็ได้:

```python
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:8001/v1",
    api_key="EMPTY",
)
```

จากนั้นส่งคำขอ chat completion โดยใช้รูปแบบข้อความเดียวกันกับ OpenAI API — รายการข้อความที่มีบทบาท (role) เช่น `"user"` และ `"assistant"` การตั้งค่า `stream=True` หมายความว่าการตอบกลับจะทยอยมาเรื่อย ๆ แทนที่จะมาทีเดียวทั้งหมด:

```python
response = client.chat.completions.create(
    model="Qwen/Qwen3-1.7B",
    messages=[
        {"role": "user", "content": "Tell me a short story"},
    ],
    max_tokens=2048,  # Maximum number of tokens the model will generate in its response
    stream=True,
)
```

สุดท้าย ให้วนซ้ำ (iterate) ผ่านชิ้นส่วนของข้อมูลที่สตรีมเข้ามา และพิมพ์ข้อความแต่ละส่วนออกมาทันทีที่ได้รับ:

```python
for chunk in response:
    content = chunk.choices[0].delta.content
    if content:
        print(content, end="", flush=True)
```

สคริปต์ [chat_with_model.py](assets/chat_with_model.py) ที่แนบมาด้วยมีตัวอย่างทั้งหมดนี้และสามารถดาวน์โหลดได้


## การเลือกและกำหนดค่าโมเดล

โดยค่าเริ่มต้น `vllm-launch` จะให้บริการ `Qwen/Qwen3-1.7B` เป็นโมเดลทดสอบบนพอร์ต `8001` คุณสามารถเปลี่ยนโมเดล พอร์ต และพารามิเตอร์การให้บริการของ vLLM ได้โดยไม่ต้องสร้างคอนเทนเนอร์ใหม่หรือแก้ไขคอนเทนเนอร์

### โมเดลที่ AMD ทดสอบแล้ว

โมเดลต่อไปนี้ถูกกำหนดค่าไว้ล่วงหน้าและได้รับการตรวจสอบยืนยันโดย AMD:

| โมเดล | หมายเหตุ |
|-------|-------|
| `Qwen/Qwen3-1.7B` | โมเดลเริ่มต้น มีขนาดเบาและโหลดได้รวดเร็ว |
| `openai/gpt-oss-20b` | โมเดลขนาดใหญ่กว่าสำหรับการตอบสนองที่มีคุณภาพสูงขึ้น |

### การเรียกใช้งานโมเดลอื่น

ระบุรหัสโมเดลด้วย `--model` (หรือ `-m`):

```bash
vllm-launch --model openai/gpt-oss-20b
```

### การเปลี่ยนพอร์ต

ระบุพอร์ตที่สูงกว่า 1024 ด้วย `--port` (หรือ `-p`); ค่าเริ่มต้นคือ `8001`:

```bash
vllm-launch --port 8080 --model openai/gpt-oss-20b
```

หากคุณเปลี่ยนพอร์ต ให้ชี้ `base_url` ของไคลเอนต์ไปยังพอร์ตเดียวกัน (ตัวอย่างเช่น `http://localhost:8080/v1`)

### การส่งพารามิเตอร์ vLLM เพิ่มเติม

อาร์กิวเมนต์เพิ่มเติมใด ๆ จะถูกส่งต่อไปยัง vLLM โดยตรง ทำให้คุณสามารถปรับแต่งพฤติกรรมการให้บริการ เช่น ความยาวบริบท (context length) หรือชนิดข้อมูล (data type) มีสองวิธีในการระบุพารามิเตอร์เหล่านี้

**แบบ Inline** ต่อท้ายตัวเลือกของตัวเรียกใช้งาน:

```bash
vllm-launch --model openai/gpt-oss-20b --max-model-len 8192
```

**แบบถาวร** ในไฟล์ตั้งค่าที่ `~/.local/share/vLLM/vllm-launch.conf` ไฟล์นี้ไม่มีอยู่โดยค่าเริ่มต้น — ให้สร้างไฟล์นี้ขึ้นมาและเพิ่มอาร์กิวเมนต์ของคุณเป็นอาร์เรย์ Bash:

```bash
VLLM_EXTRA_ARGS=(--max-model-len 8192 --dtype float16)
```

ใช้ `+=` เพื่อเพิ่มต่อท้ายอาร์กิวเมนต์เริ่มต้นแทนการแทนที่:

```bash
VLLM_EXTRA_ARGS+=(--max-model-len 8192)
```

หากต้องการดูตัวเลือกทั้งหมดของตัวเรียกใช้งานได้ตลอดเวลา ให้รัน:

```bash
vllm-launch --help
```

### ตำแหน่งที่เก็บโมเดล

`vllm-launch` จะค้นหาโมเดลในสองตำแหน่ง:

| ตำแหน่ง | เส้นทาง |
|----------|------|
| โมเดลของระบบ | `/var/cache/models` |
| โมเดลของผู้ใช้ | `~/.local/share/vLLM/models` |

คุณสามารถวางโมเดลที่ดาวน์โหลดไว้ในไดเรกทอรีใดไดเรกทอรีหนึ่ง และเรียกใช้งานโดยระบุเส้นทางหรือรหัสของโมเดลไปยัง `--model`:

```bash
vllm-launch --model /var/cache/models/my-model
```

> **หมายเหตุ**: การเรียกใช้งานโมเดลที่ดาวน์โหลดเองด้วยวิธีนี้คาดว่าจะทำงานได้เมื่อวางโมเดลไว้ในไดเรกทอรีใดไดเรกทอรีหนึ่งข้างต้น แต่ขั้นตอนการทำงานนี้ยังไม่ได้รับการตรวจสอบยืนยันอย่างเป็นทางการโดย AMD

## สรุป

ในเพลย์บุ๊กนี้ คุณได้เรียนรู้วิธีการ:

- เริ่มต้น vLLM แบบคอนเทนเนอร์พร้อมการรองรับ ROCm บน GPU แบบรวม
- เริ่มต้นเซิร์ฟเวอร์ vLLM พร้อมปลายทาง API ที่เข้ากันได้กับ OpenAI บนพอร์ต 8001
- ส่งพรอมป์ด้วย `vllm-prompt`
- เรียก API ไปยังเซิร์ฟเวอร์ vLLM โดยใช้ทั้งคำขอแบบสตรีมและไม่สตรีม
- แก้ไขปัญหาทั่วไปเกี่ยวกับการเริ่มต้นเซิร์ฟเวอร์ หน่วยความจำ และการเชื่อมต่อของไคลเอนต์

ตอนนี้คุณมีระบบ vLLM แบบคอนเทนเนอร์สำหรับให้บริการโมเดลภาษาขนาดใหญ่ที่ทำงานได้อย่างมีประสิทธิภาพบน GPU แบบรวมแล้ว

## ขั้นตอนถัดไป

- **ลองใช้โมเดลต่าง ๆ** — ใช้ `vllm-launch --model <model>` เพื่อทดลองใช้ LLM ต่าง ๆ และเปรียบเทียบประสิทธิภาพ (ดู [การเลือกและกำหนดค่าโมเดล](#choosing-and-configuring-a-model))
- **สร้างแอปพลิเคชัน** — ใช้ API ที่เข้ากันได้กับ OpenAI เพื่อผสานรวม vLLM เข้ากับแอป Python, แชทบอท หรือเวิร์กโฟลว์อัตโนมัติ
- **ปรับแต่งและให้บริการ** — ปรับแต่งโมเดลด้วย LoRA หรือ QLoRA จากนั้นนำไปให้บริการด้วย vLLM เพื่อการอนุมานที่ปรับให้เหมาะสม
