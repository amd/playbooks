## ภาพรวม

[OpenHands](https://github.com/All-Hands-AI/OpenHands) คือเอเจนต์ซอฟต์แวร์ AI
ที่สามารถเขียนโค้ด รันคำสั่ง เรียกดูเว็บ และแก้ไขไฟล์ในพื้นที่ทำงานจริงได้
แทนที่จะคัดลอกคำแนะนำออกจากหน้าต่างแชท คุณสามารถชี้ให้เอเจนต์ทำงาน
กับโฟลเดอร์โปรเจกต์และปล่อยให้มันทำงานให้: ใช้งานฟีเจอร์ แก้ไขบั๊ก
เขียนเทสต์ หรืออธิบายโค้ดเบส

[Agent Canvas](https://github.com/OpenHands/agent-canvas) คือ UI บนเบราว์เซอร์ที่แนะนำ
สำหรับการรัน OpenHands คำสั่ง `agent-canvas` เพียงคำสั่งเดียวจะเริ่มต้นเซิร์ฟเวอร์เอเจนต์
แบ็กเอนด์การทำงานอัตโนมัติ และเว็บฟรอนต์เอนด์พร้อมกัน ทำให้คุณสามารถ
สนทนากับเอเจนต์จากเบราว์เซอร์ของคุณได้

เพื่อให้ทุกอย่างอยู่บนระบบ AMD ของคุณ เอเจนต์จะสื่อสารกับโมเดลภายในเครื่องที่ให้บริการ
โดย Lemonade Server Lemonade เปิดให้ใช้งานโมเดลนั้นผ่าน API ที่เข้ากันได้กับ OpenAI
ทำให้ Agent Canvas สามารถกำหนดค่าได้เหมือนกับ endpoint สไตล์ OpenAI ทั่วไป
ในขณะที่โมเดล โค้ดของคุณ และบริบทการสนทนาทั้งหมดยังคงอยู่บนเครื่องของคุณ

ในเพลย์บุ๊กนี้ คุณจะเริ่มต้นโมเดลภายในเครื่อง เปิดใช้งาน Agent Canvas ชี้ไปที่
โมเดลนั้น และรันงานเขียนโค้ดครั้งแรกกับโฟลเดอร์โปรเจกต์จริง

## สิ่งที่คุณจะได้เรียนรู้

- วิธีเริ่มต้น Lemonade Server และยืนยันว่าโมเดลภายในเครื่องตอบสนองต่อคำขอแชทได้
- วิธีติดตั้งและเปิดใช้งาน Agent Canvas จากแพ็กเกจ npm
- วิธีกำหนดค่า Agent Canvas ให้ใช้โมเดล Lemonade ภายในเครื่องเป็น LLM
- วิธีเริ่มการสนทนา OpenHands และดูเอเจนต์แก้ไขไฟล์และรันคำสั่ง
  ในพื้นที่ทำงาน
- วิธีตรวจสอบสิ่งที่เอเจนต์เปลี่ยนแปลงและควบคุมทิศทางด้วยข้อความติดตามผล

## 1. เริ่มต้น Lemonade Server

เริ่มต้นโมเดลจาก Lemonade CLI:

```bash
lemonade config set llamacpp.backend=vulkan
lemonade config set ctx_size=65536
lemonade run "Qwen3.6-35B-A3B-GGUF"
```

Lemonade เปิดให้ใช้งาน API ที่เข้ากันได้กับ OpenAI ที่:

```text
http://127.0.0.1:13305/api/v1
```



## 2. ตรวจสอบโมเดลภายในเครื่อง

ยืนยันว่า Lemonade สามารถให้บริการโมเดลที่เลือกได้:

```bash
curl -s "http://127.0.0.1:13305/api/v1/models" | python3 -m json.tool
```

จากนั้นส่งคำขอแชทเล็กๆ:

```bash
curl -sS "http://127.0.0.1:13305/api/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "Qwen3.6-35B-A3B-GGUF",
    "messages": [
      {"role": "user", "content": "Reply with exactly: OK"}
    ],
    "temperature": 0,
    "max_tokens": 64
  }' | python3 -m json.tool
```

หากผลลัพธ์ที่ได้มี array `choices` แสดงว่า Lemonade พร้อมสำหรับ Agent Canvas แล้ว

## 3. ติดตั้งและเปิดใช้งาน Agent Canvas

ติดตั้งแพ็กเกจ Agent Canvas ที่เผยแพร่แล้วแบบ global:

```bash
npm install -g @openhands/agent-canvas
```

จากนั้นเริ่มสแต็กทั้งหมดจากเทอร์มินัล:

```bash
agent-canvas
```

โดยค่าเริ่มต้น Agent Canvas จะเริ่มทำงานที่ `http://localhost:8000` เปิด URL นั้น
ในเบราว์เซอร์ของคุณ หากพอร์ต 8000 ถูกใช้งานอยู่แล้ว ให้ส่งพารามิเตอร์ `--port` (หรือ `-p`) เมื่อคุณ
เปิดใช้งาน Agent Canvas:

```bash
agent-canvas --port 3000
```

คำสั่งเดียวกันนี้ใช้ได้กับ PowerShell บน Windows เช่นกัน จากนั้นให้เปิด
`http://localhost:3000` แทน แบ็กเอนด์ภายในเครื่องเริ่มต้นควรแสดงสถานะปกติ (healthy)
บนหน้าจอหลัก

คำสั่ง `agent-canvas` จะเริ่มต้นเซิร์ฟเวอร์เอเจนต์ แบ็กเอนด์การทำงานอัตโนมัติ และ
เว็บฟรอนต์เอนด์พร้อมกัน คุณต้องการเพียงคำสั่งเดียวนี้เพื่อรัน OpenHands
ภายในเครื่อง

## 4. กำหนดค่า LLM ภายในเครื่อง

เมื่อเปิดใช้งานครั้งแรก Agent Canvas จะเปิดขั้นตอนการเริ่มต้นใช้งาน (onboarding flow) ในขั้นตอนนั้น:

1. คงค่า **OpenHands** ไว้เป็นเอเจนต์ที่เลือกไว้และคลิก **Next**
2. บนหน้า **Set up your LLM** เลือก **Advanced**
3. คงค่า **Authentication** ไว้ที่ **API key**
4. ตั้งค่า **Custom Model** เป็น `openai/Qwen3.6-35B-A3B-GGUF`
5. ตั้งค่า **Base URL** เป็น `http://127.0.0.1:13305/api/v1`
6. สำหรับ **API Key** ให้ป้อนค่าตัวยึดตำแหน่งใดๆ ที่ไม่ว่างเปล่า เช่น `lemonade-local`
   Lemonade ไม่ต้องการคีย์จริง แต่ไคลเอนต์ OpenHands ต้องการค่าใดค่าหนึ่ง
   เพื่อส่งไป
7. คลิก **Next**

การตั้งค่า Advanced ที่เสร็จสมบูรณ์ควรมีลักษณะดังนี้ ช่องคีย์ API จะถูกปิดบัง
โดย UI

![การตั้งค่า LLM Advanced ครั้งแรกของ Agent Canvas พร้อมโมเดล Lemonade และ base URL ภายในเครื่อง](assets/01-llm-advanced-settings.png)

Agent Canvas จะบันทึกค่าเหล่านี้เป็นโปรไฟล์ LLM หากเวอร์ชันของคุณขอให้คุณ
ตั้งชื่อโปรไฟล์นั้น ให้ใช้ชื่อที่ไม่มีช่องว่าง เช่น `lemonade-local` หากคุณเปลี่ยน
โมเดลในภายหลัง ให้เปิด **Settings > LLM** และอัปเดตฟิลด์ Advanced เดียวกัน คุณ
สามารถสลับโปรไฟล์ที่บันทึกไว้จากช่องป้อนข้อความแชทด้วยคำสั่ง `/model`

## 5. เปิดพื้นที่ทำงาน (Workspace)

เอเจนต์สามารถอ่านและแก้ไขไฟล์ได้เฉพาะภายในพื้นที่ทำงานที่คุณเลือกเท่านั้น ก่อนเริ่ม
งาน ให้ชี้ Agent Canvas ไปที่โฟลเดอร์โปรเจกต์ของคุณ:

1. จากหน้าจอหลัก เลือก **Open Workspace**
2. เลือกโฟลเดอร์ที่มีโปรเจกต์ของคุณ (ตัวอย่างเช่น git repository
   ที่คุณต้องการให้เอเจนต์ทำงานด้วย)
3. เริ่มการสนทนาใหม่ในพื้นที่ทำงานนั้น

ทุกสิ่งที่เอเจนต์ทำ ไม่ว่าจะเป็นการอ่านไฟล์ รันคำสั่ง แก้ไขโค้ด จะถูกจำกัดขอบเขต
ให้อยู่ในพื้นที่ทำงานนั้นเท่านั้น

![หน้าหลักของ Agent Canvas หลังจากขั้นตอนการเริ่มต้นใช้งาน](assets/02-agent-canvas-home.png)
## 6. เรียกใช้งานงานเขียนโค้ดชิ้นแรกของคุณ

เมื่อเปิดพื้นที่ทำงานและเลือก LLM ในเครื่องแล้ว ให้พิมพ์งานที่ชัดเจนลงในแชท งานแรกที่ดีควรมีขนาดเล็กและตรวจสอบผลลัพธ์ได้ ตัวอย่างเช่น:

```text
Create a new file called hello.py that defines a function greet(name) that
returns "Hello, {name}!", and add a small test that prints greet("World")
when run as a script.
```

สังเกตไทม์ไลน์ของบทสนทนา OpenHands จะ:

- อ่านพื้นที่ทำงานเพื่อทำความเข้าใจโครงสร้าง
- สร้าง `hello.py` พร้อมฟังก์ชันและบล็อกทดสอบตามที่ร้องขอ
- อาจรัน `python3 hello.py` เพื่อยืนยันผลลัพธ์
- รายงานสิ่งที่ทำและผลลัพธ์ของคำสั่งใด ๆ ในแชท

คุณควรเห็นไฟล์ใหม่ปรากฏขึ้นในพื้นที่ทำงาน และข้อความสุดท้ายของเอเจนต์ควรอธิบายการเปลี่ยนแปลงที่ได้ทำไป นี่คือช่วงเวลาแห่งความสำเร็จ เพราะเอเจนต์ได้เขียนและรันโค้ดจริงในโฟลเดอร์โปรเจกต์ของคุณ

## 7. ตรวจสอบและกำกับทิศทางเอเจนต์

หลังจากเอเจนต์ทำขั้นตอนหนึ่งเสร็จแล้ว ให้ตรวจสอบผลงานก่อนยอมรับขั้นตอนถัดไป:

- **การเปลี่ยนแปลงไฟล์**: ใช้ตัวเรียกดูไฟล์ในพื้นที่ทำงานหรือมุมมองความแตกต่าง (diff) ของเอเจนต์ เพื่อดูว่ามีการเพิ่ม เปลี่ยนแปลง หรือลบสิ่งใดบ้างอย่างชัดเจน
- **ผลลัพธ์ของคำสั่ง**: ขยายดูคำสั่งใด ๆ ที่เอเจนต์รัน เพื่อดู stdout, stderr และรหัสออก (exit code)
- **การติดตามผล**: หากผลลัพธ์ไม่ตรงกับที่คุณต้องการ ให้ตอบกลับในบทสนทนาเดิมพร้อมคำแก้ไข เอเจนต์จะเก็บบริบทก่อนหน้าไว้และดำเนินการต่อกับไฟล์เดิม

ตัวอย่างเช่น หากการทดสอบไม่พิมพ์ข้อความทักทายตามที่คาดไว้ ให้ตอบกลับว่า:

```text
The script did not print anything. Run python3 hello.py and fix it so the
greet("World") test prints to stdout.
```

เอเจนต์จะอ่านไฟล์อีกครั้ง รันคำสั่ง วินิจฉัยปัญหา และแก้ไขไฟล์อีกครั้ง—ทั้งหมดในบทสนทนาเดียวกัน

## การแก้ไขปัญหา

- **`agent-canvas` ไม่อยู่ใน PATH:** ติดตั้งใหม่ด้วยคำสั่ง
  `npm install -g @openhands/agent-canvas` และตรวจสอบว่าไดเรกทอรีไบนารีส่วนกลางของ npm
  อยู่ใน PATH ของคุณ บน Windows ให้รัน `npm config get prefix` ไดเรกทอรีที่ได้
  ซึ่งมักเป็น `%APPDATA%\npm` หรือ `%USERPROFILE%\.npm-global`
  จะต้องอยู่ใน PATH ของผู้ใช้ ก่อนที่จะสามารถเรียกใช้ `agent-canvas` จากเทอร์มินัลใหม่ได้
- **`npm install -g` ล้มเหลวเนื่องจากข้อผิดพลาดด้านสิทธิ์การเข้าถึง:** กำหนดค่าไดเรกทอรี npm ส่วนกลาง
  ที่เป็นของผู้ใช้เอง จากนั้นเปิดเทอร์มินัลใหม่และติดตั้ง Agent Canvas อีกครั้ง

  <!-- @os:linux -->
  ```bash
  mkdir -p ~/.npm-global
  npm config set prefix ~/.npm-global
  echo 'export PATH="$HOME/.npm-global/bin:$PATH"' >> ~/.profile
  . ~/.profile
  npm install -g @openhands/agent-canvas
  ```
  <!-- @os:end -->

  <!-- @os:windows -->
  ```powershell
  New-Item -ItemType Directory -Force "$env:USERPROFILE\.npm-global"
  npm config set prefix "$env:USERPROFILE\.npm-global"
  $env:Path = "$env:USERPROFILE\.npm-global;$env:Path"
  npm install -g @openhands/agent-canvas
  ```

  หากต้องการให้การเปลี่ยนแปลง PATH บน Windows มีผลถาวร ให้เพิ่ม `%USERPROFILE%\.npm-global` ไปยัง
  PATH ของผู้ใช้ผ่านทาง **Settings > System > About > Advanced system settings >
  Environment Variables** แล้วเปิดเทอร์มินัลใหม่
  <!-- @os:end -->
- **UI โหลดขึ้นมาแต่แบ็กเอนด์แสดงสถานะไม่ปกติ (unhealthy):** รอสักครู่ให้
  agent server เริ่มทำงานเสร็จสิ้น จากนั้นรีเฟรช หากยังคงแสดงสถานะไม่ปกติ ให้รีสตาร์ท
  `agent-canvas` และตรวจสอบผลลัพธ์ในเทอร์มินัลเพื่อดูข้อผิดพลาด
- **คำขอแชทของ Lemonade ล้มเหลวด้วยข้อผิดพลาดการเชื่อมต่อ:** ตรวจสอบว่า
  `curl -fsS "http://127.0.0.1:13305/api/v1/health"` สำเร็จ และ
  Lemonade ยังคงให้บริการโมเดลอยู่ด้วยคำสั่ง `lemonade status`
- **เอเจนต์แสดงข้อผิดพลาดเกี่ยวกับความยาวบริบทหรือขีดจำกัดโทเคน:** รีสตาร์ท
  Lemonade ด้วยค่า `ctx_size` ที่ใหญ่ขึ้น (เช่น `ctx_size=65536`) และเริ่มบทสนทนา
  ใหม่เพื่อไม่ให้เอเจนต์แบกรับประวัติบทสนทนาที่ใหญ่เกินไป
- **เอเจนต์สร้างการแก้ไขที่มีคุณภาพต่ำหรือไม่สมบูรณ์:** เปลี่ยนไปใช้โมเดลที่ใหญ่ขึ้นใน
  Lemonade หรือมอบหมายงานที่มีขนาดเล็กลงและชัดเจนขึ้นให้เอเจนต์ และปล่อยให้ทำงาน
  จนเสร็จก่อนที่จะขอการเปลี่ยนแปลงถัดไป
- **ไม่มี `uv`:** ติดตั้งได้จาก
  [คู่มือการติดตั้ง uv](https://docs.astral.sh/uv/getting-started/installation/)
  Agent Canvas ใช้ `uv` เพื่อจัดการสภาพแวดล้อม Python ของ agent server

## ขั้นตอนถัดไป

- ลองทำงานที่ใหญ่ขึ้นในพื้นที่ทำงานเดียวกัน เช่น การเพิ่มไฟล์ทดสอบหน่วย (unit test) หรือ
  การแก้ไขบั๊กที่ทราบอยู่แล้ว และตรวจสอบ diff ของเอเจนต์ก่อนที่จะเก็บการเปลี่ยนแปลงไว้
- เชื่อมต่อ MCP server เช่น GitHub หรือ Slack ภายใต้ **Customize** เพื่อให้
  เอเจนต์สามารถอ่าน issue หรือโพสต์อัปเดตได้ในขณะทำงาน
- บันทึกโปรไฟล์ LLM หลายชุด (โมเดลขนาดเล็กที่รวดเร็วและโมเดลขนาดใหญ่ที่ทรงพลังกว่า) และ
  สลับใช้งานระหว่างโปรไฟล์เหล่านั้นด้วย `/model` ระหว่างการสนทนา
- ไปยังขั้นตอนถัดไปที่ [ระบบอัตโนมัติของ OpenHands](https://docs.openhands.dev/openhands/usage/automations/overview) เพื่อ
  เปลี่ยนวงจรการพัฒนาที่เกิดขึ้นซ้ำ ๆ ให้เป็นการรันเอเจนต์ตามตารางเวลาหรือเมื่อมีเหตุการณ์กระตุ้น
