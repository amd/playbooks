# การรวมคลัสเตอร์ Ryzen™ AI Halo สองเครื่องด้วย RCCL

## ภาพรวม

Ryzen™ AI Halo ของคุณสามารถรันโมเดลภาษาขนาดใหญ่ในเครื่องได้อยู่แล้ว การทำคลัสเตอร์จะขยายขีดความสามารถนี้ไปอีกขั้นด้วยการรวมหน่วยความจำ GPU ของหลายระบบเข้าด้วยกันผ่านเครือข่ายภายใน ทำให้คุณเข้าถึงโมเดลที่ใหญ่ขึ้นซึ่งมีความสามารถในการให้เหตุผลที่แข็งแกร่งขึ้น การสร้างโค้ดที่ดีขึ้น และความเข้าใจหลายภาษาที่ลึกซึ้งยิ่งขึ้น ทั้งหมดนี้อยู่บนฮาร์ดแวร์ของคุณเองอย่างสมบูรณ์

เพลย์บุ๊กนี้จะสอนวิธีการรวมคลัสเตอร์ระบบ Ryzen AI Halo สองเครื่องโดยใช้ RCCL (ROCm Communication Collectives Library) ร่วมกับ vLLM และรัน Qwen3.5-397B ซึ่งเป็นโมเดลขนาด 397 พันล้านพารามิเตอร์ บนเครื่องทั้งสองพร้อมการเร่งความเร็วด้วย ROCm

## สิ่งที่คุณจะได้เรียนรู้

- วิธีขยายการจัดสรร VRAM บนระบบ Ryzen AI Halo
- การเปิดใช้งาน vLLM พร้อมการรองรับ ROCm
- การกำหนดค่า RCCL สำหรับการอนุมานแบบ tensor-parallel หลายโหนดบนระบบ Ryzen AI Halo สองเครื่อง
- การรันโมเดลขนาด 397 พันล้านพารามิเตอร์บนระบบ Ryzen AI Halo สองเครื่องที่เชื่อมต่อผ่านเครือข่าย

## ข้อกำหนดเบื้องต้น

### ฮาร์ดแวร์

เพลย์บุ๊กนี้ต้องใช้ Ryzen AI Halo สองเครื่องและสวิตช์อีเทอร์เน็ตหนึ่งตัว โดยเชื่อมต่อในรูปแบบโทโพโลยีดาว (star topology) โดยแต่ละเครื่องเชื่อมต่อโดยตรงกับสวิตช์

| ส่วนประกอบ | จำนวน | คำอธิบาย |
|-----------|----------|-------------|
| Ryzen AI Halo | 2 | โหนดประมวลผลที่ประกอบกันเป็นคลัสเตอร์ |
| สวิตช์อีเทอร์เน็ต 10Gbps | 1 | สวิตช์ศูนย์กลางเพื่อให้ Ryzen AI Halo หลายโหนดสามารถสื่อสารกันได้ (อย่างน้อย 2 พอร์ต) |
| สายเคเบิลอีเทอร์เน็ต | 2 | เชื่อมต่อแต่ละเครื่อง Halo เข้ากับสวิตช์ (แนะนำ Cat 7 หรือสูงกว่า) |

> **หมายเหตุ**: ต้องใช้พอร์ตสวิตช์อีเทอร์เน็ตสองพอร์ตเพื่อเชื่อมต่อเครื่อง Ryzen AI Halo ทั้งสอง หากคุณเข้าถึงโมเดลจากเครื่องไคลเอนต์แยกต่างหากแทนที่จะเป็นจากเครื่อง Halo เครื่องใดเครื่องหนึ่ง จำเป็นต้องใช้พอร์ตที่สาม

## การตั้งค่าฮาร์ดแวร์ทางกายภาพ

> **หมายเหตุ**: ทำขั้นตอนนี้ให้ครบทั้งบน Machine 1 และ Machine 2

เชื่อมต่อเครื่อง Ryzen AI Halo แต่ละเครื่องเข้ากับสวิตช์อีเทอร์เน็ตโดยใช้สาย Cat 7 (หรือสูงกว่า) วิธีนี้จะสร้างลิงก์ 10Gbps ที่ใช้สำหรับการสื่อสารความเร็วสูงระหว่างโหนด

### 1. ระบุอินเทอร์เฟซเครือข่าย

บนแต่ละเครื่อง ให้ค้นหาชื่ออินเทอร์เฟซเครือข่ายและจดบันทึกไว้ (จะเรียกในคำแนะนำส่วนที่เหลือว่า `IFNAME`) รันคำสั่ง:

```bash
ip route get 1.1.1.1 | grep -oP 'dev \K\S+'
```

คำสั่งนี้จะแสดงชื่ออินเทอร์เฟซโดยตรง ตัวอย่างเช่น:

```bash
enp191s0
```

### 2. ตรวจสอบความเร็วลิงก์เครือข่าย

ยืนยันว่าลิงก์ทำงานอยู่และรันด้วยความเร็วเต็มที่โดยตรวจสอบความเร็วของอินเทอร์เฟซของคุณ:

```bash
sudo ethtool <IFNAME> | grep Speed
```

> **หมายเหตุ**: แทนที่ `<IFNAME>` ด้วยชื่ออินเทอร์เฟซที่ได้จาก [1. ระบุอินเทอร์เฟซเครือข่าย](#1-determine-network-interfaces)

คุณควรเห็นความเร็ว `10000Mb/s`:

```bash
	Speed: 10000Mb/s
```

> **หมายเหตุ**: หากความเร็วต่ำกว่า `10000Mb/s` หรือลิงก์ไม่ขึ้น ให้ตรวจสอบการเชื่อมต่อสายเคเบิลและยืนยันว่าพอร์ตสวิตช์ถูกตั้งค่าเป็น 10Gbps สวิตช์บางรุ่นต้องปิดการทำงานของ auto-negotiation และตั้งค่าความเร็วลิงก์ด้วยตนเอง โปรดดูเอกสารประกอบของสวิตช์ของคุณ

## การขยายการจัดสรร VRAM

> **หมายเหตุ**: ทำขั้นตอนนี้ให้ครบทั้งบน Machine 1 และ Machine 2

### การกำหนดค่าหน่วยความจำสำหรับการรันโมเดลขนาดใหญ่

บน Linux, ROCm จะใช้พูลหน่วยความจำระบบร่วมกัน และพูลนี้ถูกกำหนดค่าเริ่มต้นให้เป็นครึ่งหนึ่งของหน่วยความจำระบบ

ปริมาณนี้สามารถเพิ่มได้โดยเปลี่ยนการตั้งค่าเพจของ Translation Table Manager (TTM) ของเคอร์เนล ตามคำแนะนำต่อไปนี้ AMD แนะนำให้ตั้งค่า VRAM เฉพาะขั้นต่ำใน BIOS (0.5 GB)

* ติดตั้งยูทิลิตี pipx และเพิ่มพาธสำหรับ wheel ที่ติดตั้งโดย pipx ลงในพาธค้นหาของระบบ

  ```bash
  sudo apt install pipx
  pipx ensurepath
  ```

* ติดตั้ง wheel amd-debug-tools จาก PyPI
  ```bash
  pipx install amd-debug-tools
  ```

* รันเครื่องมือ amd-ttm เพื่อสอบถามการตั้งค่าปัจจุบันสำหรับหน่วยความจำร่วม
  ```bash
  amd-ttm
  ```

* กำหนดค่าหน่วยความจำร่วมใหม่เป็น **120 GB**:
  ```bash
  amd-ttm --set 120
  ```

* รีบูตระบบเพื่อให้การเปลี่ยนแปลงมีผล

## การเริ่มต้นคอนเทนเนอร์ vLLM

> **หมายเหตุ**: ทำขั้นตอนนี้ให้ครบทั้งบน Machine 1 และ Machine 2

Ryzen AI Halo ของคุณมาพร้อมกับ vLLM ที่บรรจุอยู่ในอิมเมจคอนเทนเนอร์ที่สร้างไว้ล่วงหน้า ซึ่งคุณสามารถรันได้โดยใช้ Podman ซึ่งเป็นเครื่องมือคอนเทนเนอร์แบบฟรีและโอเพนซอร์ส

### 1. สร้างไดเรกทอรีดาวน์โหลดโมเดล

เมื่อคุณเสิร์ฟโมเดล Qwen3.5-397B ในเพลย์บุ๊กนี้ vLLM จะดาวน์โหลดน้ำหนักของโมเดลไปยังระบบของคุณโดยอัตโนมัติ เพื่อให้แน่ใจว่าน้ำหนักเหล่านั้นสามารถเข้าถึงได้จากภายในคอนเทนเนอร์ ก่อนอื่นให้สร้างไดเรกทอรีโมเดลที่คอนเทนเนอร์สามารถ mount ได้:

```bash
mkdir -p ~/.local/share/vLLM/models
```

### 2. เปิดใช้งานคอนเทนเนอร์ vLLM

คำสั่งด้านล่างจะเปิดใช้งานคอนเทนเนอร์และนำคุณเข้าสู่เชลล์แบบโต้ตอบ โดยจะ mount ไดเรกทอรีโมเดลที่คุณเพิ่งสร้างขึ้นและส่งค่า `IFNAME` ของคุณไปยัง `NCCL_SOCKET_IFNAME` และ `GLOO_SOCKET_IFNAME` เพื่อบอก RCCL (ไลบรารีที่ vLLM ใช้ในการประสานงาน GPU ต่างๆ ทั่วทั้งคลัสเตอร์) ว่าจะใช้อินเทอร์เฟซใด

เริ่มต้นคอนเทนเนอร์ด้วย:

```bash
sudo podman run -it --name vllm_cluster --replace --pull missing --network=host --device /dev/kfd --device /dev/dri -v ~/.local/share/vLLM/models:/opt/vLLM/models --env HF_HOME=/opt/vLLM/models --entrypoint="bin/bash" --shm-size=64g --pids-limit=-1 -e NCCL_SOCKET_IFNAME=<IFNAME> -e GLOO_SOCKET_IFNAME=<IFNAME> oci-registry.ryai.dev/ryai-vllm:latest
```

> **หมายเหตุ**: แทนที่ `<IFNAME>` ด้วยชื่ออินเทอร์เฟซที่ได้จาก [1. ระบุอินเทอร์เฟซเครือข่าย](#1-determine-network-interfaces)

## การรันโมเดลบนคลัสเตอร์

vLLM ใช้ Ray ในการจัดการคลัสเตอร์และ RCCL ในการจัดการการสื่อสารระหว่าง GPU กับ GPU ข้ามโหนด เครื่องหนึ่งทำหน้าที่เป็น **head node** (Machine 1) ทำหน้าที่ประสานงานการอนุมาน อีกเครื่องหนึ่งเข้าร่วมเป็น **worker node** (Machine 2) โดยมีส่วนช่วยด้านหน่วยความจำ GPU และการประมวลผล

> **หมายเหตุ**: Ray เป็นดีเพนเดนซีทางเลือกสำหรับ vLLM และใช้งานได้เฉพาะจากภายในคอนเทนเนอร์ Podman ที่กำหนดค่าไว้ล่วงหน้าเท่านั้น

เมื่อเริ่มต้นทำงาน vLLM จะแบ่งโมเดลออกเป็นส่วนๆ ข้ามโหนดทั้งสองโดยใช้ tensor parallelism เมื่อโหลดเสร็จแล้ว การอนุมานจะดำเนินไปราวกับว่ากำลังรันอยู่บนตัวเร่งความเร็วเพียงตัวเดียว

### ขั้นตอนที่ 1: เริ่มต้น Ray Head Node (Machine 1)

บน Machine 1 ให้เริ่มต้น Ray head node เพื่อเริ่มต้นคลัสเตอร์:

```bash
ray start --head --port=6379 --node-ip-address=<MACHINE_1_IP> --num-gpus=1
```

> **การหา `<MACHINE_1_IP>`**: บน Machine 1 ให้รัน `hostname -I | awk '{print $1}'` เพื่อหาที่อยู่ IP ภายในของเครื่อง
### ขั้นตอนที่ 2: เข้าร่วมคลัสเตอร์ (Machine 2)

บน Machine 2 ให้เชื่อมต่อกับโหนดหลักเพื่อสร้างคลัสเตอร์:

```bash
ray start --address=<MACHINE_1_IP>:6379 --node-ip-address=<MACHINE_2_IP> --num-gpus=1
```

> **การหา `<MACHINE_2_IP>`**: บน Machine 2 ให้รันคำสั่ง `hostname -I | awk '{print $1}'` เพื่อหาที่อยู่ IP ภายในของเครื่อง

### ขั้นตอนที่ 3: เสิร์ฟโมเดล (Machine 1)

บน Machine 1 ให้เปิดใช้งานเซิร์ฟเวอร์ vLLM ซึ่งจะดาวน์โหลดโมเดลโดยอัตโนมัติและเริ่มเสิร์ฟโมเดลข้ามทั้งสองโหนด:

```bash
vllm serve Qwen/Qwen3.5-397B-A17B-GPTQ-Int4 \
  --port 7000 \
  --host 0.0.0.0 \
  --max-model-len 32768 \
  --gpu-memory-utilization 0.9 \
  --dtype float16 \
  --tensor-parallel-size 2 \
  --distributed-executor-backend ray \
  --enforce-eager \
  --language-model-only \
  --reasoning-parser qwen3
```

#### ตารางอ้างอิงพารามิเตอร์

| แฟล็ก | วัตถุประสงค์ |
|------|---------|
| `--port` | พอร์ตสำหรับเสิร์ฟ HTTP API |
| `--host` | ที่อยู่ IP ที่จะผูกเซิร์ฟเวอร์เข้าไว้ด้วย (`0.0.0.0` สำหรับทุกอินเทอร์เฟซ) |
| `--max-model-len` | ความยาวบริบทสูงสุดในหน่วยโทเคน |
| `--gpu-memory-utilization` | สัดส่วนหน่วยความจำ GPU ที่จะจัดสรร (0.0–1.0) |
| `--dtype` | ชนิดข้อมูลสำหรับน้ำหนักของโมเดล |
| `--tensor-parallel-size` | จำนวน GPU ที่จะใช้แบ่งโมเดล (ตั้งค่าเป็นจำนวน GPU ทั้งหมดในคลัสเตอร์) |
| `--distributed-executor-backend` | แบ็กเอนด์สำหรับการทำงานแบบหลายโหนด (`ray` สำหรับการปรับใช้แบบคลัสเตอร์) |
| `--enforce-eager` | ปิดการคอมไพล์ CUDA graph เพื่อความเข้ากันได้ |
| `--language-model-only` | ข้ามการโหลดคอมโพเนนต์เสริมของโมเดล (เช่น ตัวเข้ารหัสภาพ) |
| `--reasoning-parser` | เปิดใช้งานการแยกวิเคราะห์ผลลัพธ์การให้เหตุผลแบบมีโครงสร้างสำหรับโมเดล |

สำหรับรายละเอียดการใช้พารามิเตอร์ทั้งหมด โปรดดู [เอกสารประกอบของ vLLM](https://docs.vllm.ai/en/latest/configuration/engine_args/)

## การเข้าถึงโมเดล

vLLM เปิดให้ใช้งาน API ที่เข้ากันได้กับ OpenAI ดังนั้นคุณจึงสามารถเชื่อมต่อไคลเอนต์หรืออินเทอร์เฟซที่รองรับใดๆ เข้ากับคลัสเตอร์ของคุณได้ หนึ่งในตัวเลือกยอดนิยมคือ [Open WebUI](https://github.com/open-webui/open-webui) ซึ่งมอบอินเทอร์เฟซแชทแบบเบราว์เซอร์

ในการเชื่อมต่อ Open WebUI เข้ากับ endpoint ของ vLLM:

1. เปิด **Settings** > **Admin Panel** > **Connections**
2. คลิก **+** ที่ **Manage OpenAI API Connections**
3. ตั้งค่า **Connection Type** เป็น **External**
4. ตั้งค่า **URL** เป็น `http://<MACHINE_1_IP>:7000/v1`
5. ในส่วน **Auth** ให้เลือก **None** จากเมนูแบบดรอปดาวน์
6. เว้น **Model IDs** ว่างไว้เพื่อค้นหาโมเดลทั้งหมดจาก endpoint โดยอัตโนมัติ

> **การหา `<MACHINE_1_IP>`**: บน Machine 1 ให้รันคำสั่ง `hostname -I | awk '{print $1}'` เพื่อหาที่อยู่ IP ภายในของเครื่อง หากเข้าถึง Open WebUI จาก Machine 1 เอง คุณสามารถใช้ `http://localhost:7000/v1` ได้

## ขั้นตอนถัดไป

- **สำรวจโมเดลอื่นๆ**: ค้นหาโมเดลใหม่ๆ บน [Hugging Face](https://huggingface.co/models?&sort=trending) ที่พอดีกับหน่วยความจำ GPU รวมของคลัสเตอร์ของคุณ
- **ขยายเป็นสี่โหนด**: เพิ่มระบบ Ryzen AI Halo อีกสองเครื่องเป็น Ray worker เพิ่มเติมเพื่อแบ่งโมเดลข้าม GPU ได้มากยิ่งขึ้น ซึ่งต้องใช้สวิตช์ Ethernet ที่มีอย่างน้อยสี่พอร์ต หนึ่งพอร์ตต่อหนึ่งโหนด ทำตาม [ขั้นตอนที่ 2: เข้าร่วมคลัสเตอร์](#step-2-join-the-cluster-machine-2) บน worker เพิ่มเติมแต่ละเครื่อง และเพิ่มค่า `--tensor-parallel-size` ให้เหมาะสม
- **ลองใช้กลยุทธ์การประมวลผลแบบขนานอื่นๆ**: vLLM รองรับ [expert parallel](https://docs.vllm.ai/en/latest/serving/expert_parallel_deployment/) สำหรับโมเดลแบบ mixture-of-experts และ [data parallel](https://docs.vllm.ai/en/latest/serving/data_parallel_deployment/) เพื่อเพิ่ม throughput ลองทดลองใช้ `--enable-expert-parallel` และ `--data-parallel-size` เพื่อหาค่าคอนฟิกที่เหมาะสมที่สุดสำหรับงานของคุณ
