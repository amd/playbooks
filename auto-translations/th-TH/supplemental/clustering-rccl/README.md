# การจัดคลัสเตอร์ Ryzen™ AI Halo สองเครื่องด้วย RCCL

## ภาพรวม

Ryzen™ AI Halo ของคุณสามารถรันโมเดลภาษาขนาดใหญ่ในเครื่องได้อยู่แล้ว การจัดคลัสเตอร์จะขยายความสามารถนี้ไปอีกขั้น ด้วยการรวมหน่วยความจำ GPU ของหลายระบบเข้าด้วยกันผ่านเครือข่ายท้องถิ่น ทำให้คุณสามารถเข้าถึงโมเดลที่ใหญ่ขึ้น ซึ่งมีความสามารถในการให้เหตุผลที่ดีขึ้น สร้างโค้ดได้ดีขึ้น และเข้าใจภาษาหลายภาษาได้ลึกซึ้งยิ่งขึ้น ทั้งหมดนี้รันบนฮาร์ดแวร์ของคุณเองโดยสมบูรณ์

คู่มือนี้จะสอนวิธีการจัดคลัสเตอร์ระบบ Ryzen AI Halo สองเครื่องโดยใช้ RCCL (ROCm Communication Collectives Library) ร่วมกับ vLLM และรันโมเดล Qwen3.5-397B ซึ่งเป็นโมเดลขนาด 397 พันล้านพารามิเตอร์ ข้ามทั้งสองเครื่อง โดยใช้การเร่งความเร็วด้วย ROCm

## สิ่งที่คุณจะได้เรียนรู้

- วิธีขยายการจัดสรร VRAM บนระบบ Ryzen AI Halo
- การเปิดใช้งาน vLLM ด้วยการรองรับ ROCm
- การกำหนดค่า RCCL สำหรับการอนุมานแบบ tensor-parallel ข้ามหลายโหนดบนระบบ Ryzen AI Halo สองเครื่อง
- การรันโมเดลขนาด 397 พันล้านพารามิเตอร์ข้ามระบบ Ryzen AI Halo สองเครื่องที่เชื่อมต่อผ่านเครือข่าย

## ข้อกำหนดเบื้องต้น

### ฮาร์ดแวร์

คู่มือนี้ต้องใช้ Ryzen AI Halo สองเครื่องและสวิตช์อีเทอร์เน็ตหนึ่งตัว โดยเชื่อมต่อในรูปแบบโทโพโลยีแบบดาว (star topology) ซึ่งแต่ละเครื่องเชื่อมต่อโดยตรงกับสวิตช์

| ส่วนประกอบ | จำนวน | คำอธิบาย |
|-----------|----------|-------------|
| Ryzen AI Halo | 2 | โหนดประมวลผลที่ประกอบกันเป็นคลัสเตอร์ |
| สวิตช์อีเทอร์เน็ต 10Gbps | 1 | สวิตช์ศูนย์กลางเพื่อให้ Ryzen AI Halo หลายโหนดสื่อสารกันได้ (อย่างน้อย 2 พอร์ต) |
| สายอีเทอร์เน็ต | 2 | เชื่อมต่อแต่ละเครื่อง Halo เข้ากับสวิตช์ (แนะนำสาย Cat 7 หรือสูงกว่า) |

> **หมายเหตุ**: จำเป็นต้องใช้พอร์ตสวิตช์อีเทอร์เน็ตสองพอร์ตในการเชื่อมต่อ Ryzen AI Halo สองเครื่อง จำเป็นต้องมีพอร์ตที่สามหากคุณต้องการเข้าถึงโมเดลจากเครื่องไคลเอนต์แยกต่างหาก แทนที่จะเข้าถึงจากเครื่อง Halo เครื่องใดเครื่องหนึ่ง

## การตั้งค่าฮาร์ดแวร์ทางกายภาพ

> **หมายเหตุ**: ทำขั้นตอนนี้ให้เสร็จสิ้นทั้งบนเครื่อง 1 และเครื่อง 2

เชื่อมต่อแต่ละเครื่อง Ryzen AI Halo เข้ากับสวิตช์อีเทอร์เน็ตโดยใช้สาย Cat 7 (หรือสูงกว่า) การเชื่อมต่อนี้จะสร้างลิงก์ความเร็ว 10Gbps ที่ใช้สำหรับการสื่อสารความเร็วสูงระหว่างโหนด

### 1. ระบุอินเทอร์เฟซเครือข่าย

บนแต่ละเครื่อง ให้ค้นหาชื่ออินเทอร์เฟซเครือข่ายและจดบันทึกไว้ (จะเรียกว่า `IFNAME` ในคำแนะนำส่วนที่เหลือ) รันคำสั่ง:

```bash
ip route get 1.1.1.1 | grep -oP 'dev \K\S+'
```

คำสั่งนี้จะแสดงชื่ออินเทอร์เฟซโดยตรง เช่น:

```bash
enp191s0
```

### 2. ตรวจสอบความเร็วลิงก์เครือข่าย

ยืนยันว่าลิงก์ทำงานอยู่และรันด้วยความเร็วเต็มที่ โดยตรวจสอบความเร็วของอินเทอร์เฟซของคุณ:

```bash
sudo ethtool <IFNAME> | grep Speed
```

> **หมายเหตุ**: แทนที่ `<IFNAME>` ด้วยชื่ออินเทอร์เฟซที่ได้จาก [1. ระบุอินเทอร์เฟซเครือข่าย](#1-determine-network-interfaces)

คุณควรเห็นความเร็ว `10000Mb/s`:

```bash
	Speed: 10000Mb/s
```

> **หมายเหตุ**: หากความเร็วต่ำกว่า `10000Mb/s` หรือลิงก์ไม่ทำงาน ให้ตรวจสอบการเชื่อมต่อสายและยืนยันว่าพอร์ตสวิตช์ถูกตั้งค่าเป็น 10Gbps สวิตช์บางรุ่นต้องปิดใช้งานการเจรจาความเร็วอัตโนมัติ (auto-negotiation) และตั้งค่าความเร็วลิงก์ด้วยตนเอง โปรดดูเอกสารประกอบของสวิตช์ของคุณ

## การขยายการจัดสรร VRAM

> **หมายเหตุ**: ทำขั้นตอนนี้ให้เสร็จสิ้นทั้งบนเครื่อง 1 และเครื่อง 2

### การกำหนดค่าหน่วยความจำสำหรับการรันโมเดลขนาดใหญ่

บน Linux, ROCm ใช้พูลหน่วยความจำระบบร่วมกัน และพูลนี้ถูกกำหนดค่าเริ่มต้นไว้ที่ครึ่งหนึ่งของหน่วยความจำระบบ

ปริมาณนี้สามารถเพิ่มได้โดยการเปลี่ยนการตั้งค่า Translation Table Manager (TTM) page ของเคอร์เนล ด้วยคำแนะนำต่อไปนี้ AMD แนะนำให้ตั้งค่า VRAM เฉพาะขั้นต่ำใน BIOS (0.5 GB)

* ติดตั้งยูทิลิตี pipx และเพิ่มพาธสำหรับ wheels ที่ติดตั้งด้วย pipx เข้าไปในพาธการค้นหาของระบบ

  ```bash
  sudo apt install pipx
  pipx ensurepath
  ```

* ติดตั้ง wheel ของ amd-debug-tools จาก PyPI
  ```bash
  pipx install amd-debug-tools
  ```

* รันเครื่องมือ amd-ttm เพื่อสอบถามการตั้งค่าปัจจุบันสำหรับหน่วยความจำร่วม
  ```bash
  amd-ttm
  ```

* กำหนดค่าการตั้งค่าหน่วยความจำร่วมใหม่เป็น **120 GB**:
  ```bash
  amd-ttm --set 120
  ```

* รีบูตระบบเพื่อให้การเปลี่ยนแปลงมีผล

## การเริ่มต้นคอนเทนเนอร์ vLLM

> **หมายเหตุ**: ทำขั้นตอนนี้ให้เสร็จสิ้นทั้งบนเครื่อง 1 และเครื่อง 2

Ryzen AI Halo ของคุณมาพร้อมกับ vLLM ที่บรรจุอยู่ในอิมเมจคอนเทนเนอร์ที่สร้างไว้ล่วงหน้า ซึ่งคุณสามารถรันได้โดยใช้ Podman ซึ่งเป็นเครื่องมือคอนเทนเนอร์ที่เป็นซอฟต์แวร์เสรีและโอเพนซอร์ส

### 1. สร้างไดเรกทอรีสำหรับดาวน์โหลดโมเดล

เมื่อคุณให้บริการโมเดล Qwen3.5-397B ในคู่มือนี้ vLLM จะดาวน์โหลดน้ำหนักโมเดล (model weights) ไปยังระบบของคุณโดยอัตโนมัติ เพื่อให้แน่ใจว่าน้ำหนักเหล่านั้นสามารถเข้าถึงได้จากภายในคอนเทนเนอร์ ให้สร้างไดเรกทอรีโมเดลที่คอนเทนเนอร์สามารถ mount ได้ก่อน:

```bash
mkdir -p ~/.local/share/vLLM/models
```

### 2. เปิดใช้งานคอนเทนเนอร์ vLLM

คำสั่งด้านล่างจะเปิดใช้งานคอนเทนเนอร์และนำคุณเข้าสู่เชลล์แบบโต้ตอบ (interactive shell) โดยจะ mount ไดเรกทอรีโมเดลที่คุณเพิ่งสร้าง และส่งค่า `IFNAME` ของคุณไปยัง `NCCL_SOCKET_IFNAME` และ `GLOO_SOCKET_IFNAME` เพื่อบอก RCCL (ไลบรารีที่ vLLM ใช้ในการประสานงาน GPU ข้ามคลัสเตอร์) ว่าให้ใช้อินเทอร์เฟซใด

เริ่มต้นคอนเทนเนอร์ด้วย:

```bash
sudo podman run -it --name vllm_cluster --replace --pull missing --network=host --device /dev/kfd --device /dev/dri -v ~/.local/share/vLLM/models:/opt/vLLM/models --env HF_HOME=/opt/vLLM/models --entrypoint="bin/bash" --shm-size=64g --pids-limit=-1 -e NCCL_SOCKET_IFNAME=<IFNAME> -e GLOO_SOCKET_IFNAME=<IFNAME> oci-registry.ryai.dev/ryai-vllm:latest
```

> **หมายเหตุ**: แทนที่ `<IFNAME>` ด้วยชื่ออินเทอร์เฟซที่ได้จาก [1. ระบุอินเทอร์เฟซเครือข่าย](#1-determine-network-interfaces)

## การรันโมเดลบนคลัสเตอร์

vLLM ใช้ Ray ในการจัดการคลัสเตอร์และใช้ RCCL ในการจัดการการสื่อสารระหว่าง GPU ข้ามโหนด เครื่องหนึ่งทำหน้าที่เป็น **head node** (เครื่อง 1) ซึ่งประสานงานการอนุมาน อีกเครื่องหนึ่งเข้าร่วมในฐานะ **worker node** (เครื่อง 2) โดยให้หน่วยความจำ GPU และการประมวลผลของตน

> **หมายเหตุ**: Ray เป็นดีเพนเดนซีเสริมสำหรับ vLLM และใช้ได้เฉพาะภายในคอนเทนเนอร์ Podman ที่กำหนดค่าไว้ล่วงหน้าเท่านั้น

เมื่อเริ่มต้น vLLM จะแบ่งโมเดลข้ามทั้งสองโหนดโดยใช้ tensor parallelism เมื่อโหลดเสร็จแล้ว การอนุมานจะดำเนินไปราวกับว่ารันอยู่บนตัวเร่งความเร็วเดียว

#### การป้องกันข้อผิดพลาด Ray OOM

โดยค่าเริ่มต้น Ray จะตรวจสอบหน่วยความจำโฮสต์บนแต่ละโหนด และจะยุติ (kill) โปรเซสที่ใหญ่ที่สุดเมื่อการใช้งานหน่วยความจำเกิน 95% บน Ryzen™ AI Halo ของคุณ GPU และโฮสต์ใช้พูลหน่วยความจำร่วมกัน ดังนั้นการโหลดโมเดลอาจทำให้เกิด `ray.exceptions.OutOfMemoryError` และยุติโปรเซส worker

เพื่อป้องกันปัญหานี้ เราจะ export `RAY_memory_monitor_refresh_ms=0` บนแต่ละเครื่องก่อนเริ่มต้นและเข้าร่วมคลัสเตอร์
### ขั้นตอนที่ 1: เริ่มต้น Ray Head Node (Machine 1)

บน Machine 1 ให้เริ่มต้น Ray head node เพื่อสร้างคลัสเตอร์:

```bash
export RAY_memory_monitor_refresh_ms=0
ray start --head --port=6379 --node-ip-address=<MACHINE_1_IP> --num-gpus=1
```

> **การหา `<MACHINE_1_IP>`**: บน Machine 1 ให้รัน `hostname -I | awk '{print $1}'` เพื่อหาที่อยู่ IP ในเครือข่ายภายใน (local IP address)

### ขั้นตอนที่ 2: เข้าร่วมคลัสเตอร์ (Machine 2)

บน Machine 2 ให้เชื่อมต่อกับ head node เพื่อสร้างคลัสเตอร์:

```bash
export RAY_memory_monitor_refresh_ms=0
ray start --address=<MACHINE_1_IP>:6379 --node-ip-address=<MACHINE_2_IP> --num-gpus=1
```

> **การหา `<MACHINE_2_IP>`**: บน Machine 2 ให้รัน `hostname -I | awk '{print $1}'` เพื่อหาที่อยู่ IP ในเครือข่ายภายใน (local IP address)

### ขั้นตอนที่ 3: ให้บริการโมเดล (Machine 1)

บน Machine 1 ให้เปิดใช้งาน vLLM server ซึ่งจะดาวน์โหลดโมเดลโดยอัตโนมัติและเริ่มให้บริการโมเดลบนทั้งสองโหนด:

```bash
vllm serve Qwen/Qwen3.5-397B-A17B-GPTQ-Int4 \
  --port 7000 \
  --host 0.0.0.0 \
  --max-model-len 32768 \
  --gpu-memory-utilization 0.9 \
  --dtype float16 \
  --tensor-parallel-size 2 \
  --distributed-executor-backend ray \
  --enforce-eager \
  --language-model-only \
  --reasoning-parser qwen3
```

#### การอ้างอิงพารามิเตอร์

| แฟล็ก | วัตถุประสงค์ |
|------|---------|
| `--port` | พอร์ตสำหรับให้บริการ HTTP API |
| `--host` | ที่อยู่ IP ที่จะผูกเซิร์ฟเวอร์ (`0.0.0.0` สำหรับทุกอินเทอร์เฟซ) |
| `--max-model-len` | ความยาวบริบทสูงสุดในหน่วยโทเคน |
| `--gpu-memory-utilization` | สัดส่วนของหน่วยความจำ GPU ที่จะจัดสรร (0.0–1.0) |
| `--dtype` | ชนิดข้อมูลสำหรับน้ำหนักของโมเดล |
| `--tensor-parallel-size` | จำนวน GPU ที่จะใช้แบ่งแยกโมเดล (ตั้งค่าให้เท่ากับจำนวน GPU ทั้งหมดในคลัสเตอร์) |
| `--distributed-executor-backend` | แบ็กเอนด์สำหรับการทำงานแบบหลายโหนด (`ray` สำหรับการปรับใช้แบบคลัสเตอร์) |
| `--enforce-eager` | ปิดใช้งานการคอมไพล์ CUDA graph เพื่อความเข้ากันได้ |
| `--language-model-only` | ข้ามการโหลดส่วนประกอบเสริมของโมเดล (เช่น vision encoder) |
| `--reasoning-parser` | เปิดใช้งานการแยกวิเคราะห์ผลลัพธ์การให้เหตุผลแบบมีโครงสร้างสำหรับโมเดล |

สำหรับการใช้งานพารามิเตอร์ทั้งหมด โปรดดู [เอกสารประกอบของ vLLM](https://docs.vllm.ai/en/latest/configuration/engine_args/)

## การเข้าถึงโมเดล

vLLM เปิดให้ใช้งาน API ที่เข้ากันได้กับ OpenAI ดังนั้นคุณสามารถเชื่อมต่อไคลเอนต์หรืออินเทอร์เฟซที่รองรับใดๆ เข้ากับคลัสเตอร์ของคุณได้ ตัวเลือกที่ได้รับความนิยมตัวหนึ่งคือ [Open WebUI](https://github.com/open-webui/open-webui) ซึ่งมีอินเทอร์เฟซแชทแบบเบราว์เซอร์

หากต้องการเชื่อมต่อ Open WebUI เข้ากับ vLLM endpoint ของคุณ:

1. เปิด **Settings** > **Admin Panel** > **Connections**
2. คลิก **+** ที่ **Manage OpenAI API Connections**
3. ตั้งค่า **Connection Type** เป็น **External**
4. ตั้งค่า **URL** เป็น `http://<MACHINE_1_IP>:7000/v1`
5. ภายใต้ **Auth** ให้เลือก **None** จากเมนูแบบเลื่อนลง
6. เว้น **Model IDs** ไว้ว่างเพื่อค้นหาโมเดลทั้งหมดจาก endpoint โดยอัตโนมัติ

> **การหา `<MACHINE_1_IP>`**: บน Machine 1 ให้รัน `hostname -I | awk '{print $1}'` เพื่อหาที่อยู่ IP ในเครือข่ายภายใน (local IP address) หากเข้าถึง Open WebUI จาก Machine 1 เอง คุณสามารถใช้ `http://localhost:7000/v1` ได้

![การตั้งค่าการเชื่อมต่อ Open WebUI สำหรับ vLLM endpoint](assets/openwebui-connection.png)

เมื่อเชื่อมต่อแล้ว ให้เลือกโมเดลจากเมนูแบบเลื่อนลงของโมเดลใน Open WebUI แล้วเริ่มแชทได้เลย ขณะนี้โมเดลกำลังทำงานอยู่บนทั้งสองโหนด Ryzen AI Halo ของคุณ:

![การแชทกับ Qwen3.5-397B ใน Open WebUI](assets/openwebui-chat.png)

## ขั้นตอนถัดไป

- **สำรวจโมเดลอื่นๆ**: ค้นพบโมเดลใหม่ๆ บน [Hugging Face](https://huggingface.co/models?&sort=trending) ที่เหมาะสมกับหน่วยความจำ GPU รวมของคลัสเตอร์ของคุณ
- **ขยายเป็นสี่โหนด**: เพิ่มระบบ Ryzen AI Halo อีกสองระบบเป็น Ray worker เพิ่มเติม เพื่อแบ่งแยกโมเดลไปยัง GPU จำนวนมากขึ้น การดำเนินการนี้ต้องใช้สวิตช์อีเทอร์เน็ตที่มีอย่างน้อยสี่พอร์ต หนึ่งพอร์ตต่อหนึ่งโหนด ทำตาม [ขั้นตอนที่ 2: เข้าร่วมคลัสเตอร์](#step-2-join-the-cluster-machine-2) บน worker เพิ่มเติมแต่ละตัว และเพิ่มค่า `--tensor-parallel-size` ตามความเหมาะสม
- **ลองใช้กลยุทธ์การประมวลผลแบบขนานอื่นๆ**: vLLM รองรับ [expert parallel](https://docs.vllm.ai/en/latest/serving/expert_parallel_deployment/) สำหรับโมเดลแบบ mixture-of-experts และ [data parallel](https://docs.vllm.ai/en/latest/serving/data_parallel_deployment/) เพื่อเพิ่มปริมาณงาน ลองทดลองใช้ `--enable-expert-parallel` และ `--data-parallel-size` เพื่อหาค่าคอนฟิกูเรชันที่ดีที่สุดสำหรับงานของคุณ
