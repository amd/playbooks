# การรวมคลัสเตอร์ Ryzen™ AI Halo สองเครื่องด้วย RCCL

## ภาพรวม

Ryzen™ AI Halo ของคุณสามารถรันโมเดลภาษาขนาดใหญ่ในเครื่องได้อยู่แล้ว การรวมคลัสเตอร์จะช่วยต่อยอดความสามารถนี้ไปอีกขั้น ด้วยการรวมหน่วยความจำ GPU ของหลายระบบเข้าด้วยกันผ่านเครือข่ายท้องถิ่น ทำให้คุณสามารถเข้าถึงโมเดลที่ใหญ่ขึ้นได้ พร้อมความสามารถในการให้เหตุผลที่แข็งแกร่งขึ้น การสร้างโค้ดที่ดีขึ้น และความเข้าใจหลายภาษาที่ลึกซึ้งยิ่งขึ้น ทั้งหมดนี้ทำงานบนฮาร์ดแวร์ของคุณเองอย่างสมบูรณ์

playbook นี้จะสอนวิธีการรวมคลัสเตอร์ระบบ Ryzen AI Halo สองเครื่องโดยใช้ RCCL (ROCm Communication Collectives Library) ร่วมกับ vLLM และรัน Qwen3.5-397B ซึ่งเป็นโมเดลที่มีพารามิเตอร์ 397B ข้ามทั้งสองเครื่องโดยใช้การเร่งความเร็วด้วย ROCm

## สิ่งที่คุณจะได้เรียนรู้

- วิธีการขยายการจัดสรร VRAM บนระบบ Ryzen AI Halo
- การเปิดใช้งาน vLLM พร้อมรองรับ ROCm
- การกำหนดค่า RCCL สำหรับการอนุมานแบบ tensor-parallel หลายโหนดข้ามระบบ Ryzen AI Halo สองเครื่อง
- การรันโมเดลที่มีพารามิเตอร์ 397B ข้ามระบบ Ryzen AI Halo สองเครื่องที่เชื่อมต่อผ่านเครือข่าย

## ข้อกำหนดเบื้องต้น

### ฮาร์ดแวร์

playbook นี้ต้องการหน่วย Ryzen AI Halo สองเครื่องและสวิตช์อีเทอร์เน็ตหนึ่งตัว เชื่อมต่อในโทโพโลยีแบบดาว (star topology) โดยแต่ละหน่วยเชื่อมต่อโดยตรงกับสวิตช์

| ส่วนประกอบ | จำนวน | คำอธิบาย |
|-----------|----------|-------------|
| Ryzen AI Halo | 2 | โหนดประมวลผลที่ประกอบกันเป็นคลัสเตอร์ |
| สวิตช์อีเทอร์เน็ต 10Gbps | 1 | สวิตช์ส่วนกลางที่ช่วยให้ Ryzen AI Halo หลายโหนดสื่อสารกันได้ (อย่างน้อย 2 พอร์ต) |
| สายอีเทอร์เน็ต | 2 | เชื่อมต่อแต่ละหน่วย Halo เข้ากับสวิตช์ (แนะนำสาย Cat 7 ขึ้นไป) |

> **หมายเหตุ**: จำเป็นต้องใช้พอร์ตสวิตช์อีเทอร์เน็ตสองพอร์ตเพื่อเชื่อมต่อหน่วย Ryzen AI Halo ทั้งสองเครื่อง และจำเป็นต้องมีพอร์ตที่สามหากคุณต้องการเข้าถึงโมเดลจากเครื่องไคลเอนต์แยกต่างหากแทนที่จะเข้าถึงจากหนึ่งในหน่วย Halo โดยตรง

## การตั้งค่าฮาร์ดแวร์ทางกายภาพ

> **หมายเหตุ**: ทำขั้นตอนนี้ให้เสร็จสิ้นทั้งบนเครื่องที่ 1 และเครื่องที่ 2

เชื่อมต่อหน่วย Ryzen AI Halo แต่ละหน่วยเข้ากับสวิตช์อีเทอร์เน็ตโดยใช้สาย Cat 7 (หรือสูงกว่า) การทำเช่นนี้จะสร้างลิงก์ความเร็ว 10Gbps ที่ใช้สำหรับการสื่อสารความเร็วสูงระหว่างโหนด

### 1. ระบุอินเทอร์เฟซเครือข่าย

บนแต่ละเครื่อง ให้ค้นหาชื่ออินเทอร์เฟซเครือข่ายและจดบันทึกไว้ (จะถูกอ้างอิงในคำแนะนำที่เหลือว่า `IFNAME`) รันคำสั่ง:

```bash
ip route get 1.1.1.1 | grep -oP 'dev \K\S+'
```

คำสั่งนี้จะแสดงชื่ออินเทอร์เฟซโดยตรง เช่น:

```bash
enp191s0
```

### 2. ตรวจสอบความเร็วลิงก์เครือข่าย

ยืนยันว่าลิงก์ทำงานและวิ่งด้วยความเร็วเต็มที่ โดยตรวจสอบความเร็วของอินเทอร์เฟซของคุณ:

```bash
sudo ethtool <IFNAME> | grep Speed
```

> **หมายเหตุ**: แทนที่ `<IFNAME>` ด้วยชื่ออินเทอร์เฟซที่ได้จาก [1. ระบุอินเทอร์เฟซเครือข่าย](#1-determine-network-interfaces)

คุณควรเห็นความเร็วเป็น `10000Mb/s`:

```bash
	Speed: 10000Mb/s
```

> **หมายเหตุ**: หากความเร็วต่ำกว่า `10000Mb/s` หรือลิงก์ไม่ขึ้น ให้ตรวจสอบการเชื่อมต่อสายเคเบิลและยืนยันว่าพอร์ตสวิตช์ตั้งค่าเป็น 10Gbps สวิตช์บางรุ่นจำเป็นต้องปิดใช้งานการเจรจาอัตโนมัติ (auto-negotiation) และตั้งค่าความเร็วลิงก์ด้วยตนเอง โปรดดูเอกสารประกอบของสวิตช์ของคุณ

## การขยายการจัดสรร VRAM

> **หมายเหตุ**: ทำขั้นตอนนี้ให้เสร็จสิ้นทั้งบนเครื่องที่ 1 และเครื่องที่ 2

### การกำหนดค่าหน่วยความจำสำหรับการรันโมเดลขนาดใหญ่

บน Linux, ROCm ใช้พูลหน่วยความจำระบบร่วมกัน และพูลนี้ถูกกำหนดค่าเริ่มต้นให้เป็นครึ่งหนึ่งของหน่วยความจำระบบ

ปริมาณนี้สามารถเพิ่มได้โดยการเปลี่ยนการตั้งค่าเพจของ Translation Table Manager (TTM) ของเคอร์เนล ตามคำแนะนำต่อไปนี้ AMD แนะนำให้ตั้งค่า VRAM แบบเฉพาะขั้นต่ำใน BIOS (0.5 GB)

* ติดตั้งยูทิลิตี pipx และเพิ่มพาธสำหรับวีลที่ติดตั้งโดย pipx ลงในพาธค้นหาของระบบ

  ```bash
  sudo apt install pipx
  pipx ensurepath
  ```

* ติดตั้งวีล amd-debug-tools จาก PyPI
  ```bash
  pipx install amd-debug-tools
  ```

* รันเครื่องมือ amd-ttm เพื่อดูการตั้งค่าปัจจุบันสำหรับหน่วยความจำที่ใช้ร่วมกัน
  ```bash
  amd-ttm
  ```

* กำหนดค่าการตั้งค่าหน่วยความจำที่ใช้ร่วมกันใหม่เป็น **120 GB**:
  ```bash
  amd-ttm --set 120
  ```

* รีบูตระบบเพื่อให้การเปลี่ยนแปลงมีผล

## การเริ่มต้นคอนเทนเนอร์ vLLM

> **หมายเหตุ**: ทำขั้นตอนนี้ให้เสร็จสิ้นทั้งบนเครื่องที่ 1 และเครื่องที่ 2

Ryzen AI Halo ของคุณมาพร้อมกับ vLLM ที่บรรจุอยู่ในอิมเมจคอนเทนเนอร์ที่สร้างไว้ล่วงหน้า ซึ่งคุณรันโดยใช้ Podman ซึ่งเป็นเครื่องมือคอนเทนเนอร์ฟรีและโอเพนซอร์ส

### 1. สร้างไดเรกทอรีสำหรับดาวน์โหลดโมเดล

เมื่อคุณให้บริการโมเดล Qwen3.5-397B ใน playbook นี้ vLLM จะดาวน์โหลดน้ำหนักของโมเดลลงในระบบของคุณโดยอัตโนมัติ เพื่อให้แน่ใจว่าน้ำหนักเหล่านั้นสามารถเข้าถึงได้จากภายในคอนเทนเนอร์ ก่อนอื่นให้สร้างไดเรกทอรีโมเดลที่คอนเทนเนอร์สามารถเมาต์ได้:

```bash
mkdir -p ~/.local/share/vLLM/models
```

### 2. เปิดใช้งานคอนเทนเนอร์ vLLM

คำสั่งด้านล่างจะเปิดใช้งานคอนเทนเนอร์และนำคุณเข้าสู่เชลล์แบบโต้ตอบ โดยจะเมาต์ไดเรกทอรีโมเดลที่คุณเพิ่งสร้างขึ้น และส่งค่า `IFNAME` ของคุณไปยัง `NCCL_SOCKET_IFNAME` และ `GLOO_SOCKET_IFNAME` ซึ่งจะบอก RCCL (ไลบรารีที่ vLLM ใช้ในการประสานงาน GPU ข้ามคลัสเตอร์) ว่าจะใช้อินเทอร์เฟซใด

เริ่มต้นคอนเทนเนอร์ด้วย:

```bash
sudo podman run -it --name vllm_cluster --replace --pull missing --network=host --device /dev/kfd --device /dev/dri -v ~/.local/share/vLLM/models:/opt/vLLM/models --env HF_HOME=/opt/vLLM/models --entrypoint="bin/bash" --shm-size=64g --pids-limit=-1 -e NCCL_SOCKET_IFNAME=<IFNAME> -e GLOO_SOCKET_IFNAME=<IFNAME> oci-registry.ryai.dev/ryai-vllm:latest
```

> **หมายเหตุ**: แทนที่ `<IFNAME>` ด้วยชื่ออินเทอร์เฟซที่ได้จาก [1. ระบุอินเทอร์เฟซเครือข่าย](#1-determine-network-interfaces)

## การรันโมเดลบนคลัสเตอร์

vLLM ใช้ Ray ในการจัดการคลัสเตอร์ และใช้ RCCL ในการจัดการการสื่อสารระหว่าง GPU ข้ามโหนด เครื่องหนึ่งทำหน้าที่เป็น **โหนดหลัก** (head node) (เครื่องที่ 1) ประสานงานการอนุมาน ส่วนอีกเครื่องเข้าร่วมเป็น **โหนดผู้ปฏิบัติงาน** (worker node) (เครื่องที่ 2) โดยมีส่วนร่วมด้วยหน่วยความจำ GPU และการประมวลผลของตน

> **หมายเหตุ**: Ray เป็นดีเพนเดนซีทางเลือกสำหรับ vLLM และมีให้ใช้งานได้เฉพาะภายในคอนเทนเนอร์ Podman ที่กำหนดค่าไว้ล่วงหน้าเท่านั้น

เมื่อเริ่มต้น vLLM จะแบ่งส่วนโมเดลข้ามทั้งสองโหนดโดยใช้ tensor parallelism เมื่อโหลดเสร็จแล้ว การอนุมานจะดำเนินไปราวกับว่ากำลังรันอยู่บนตัวเร่งความเร็วเพียงตัวเดียว

#### การป้องกันข้อผิดพลาด Ray OOM

โดยค่าเริ่มต้น Ray จะตรวจสอบหน่วยความจำโฮสต์บนแต่ละโหนด และจะหยุดกระบวนการที่ใหญ่ที่สุดเมื่อการใช้งานหน่วยความจำเกิน 95% บน Ryzen™ AI Halo ของคุณ GPU และโฮสต์ใช้พูลหน่วยความจำร่วมกัน ดังนั้นการโหลดโมเดลอาจกระตุ้นให้เกิด `ray.exceptions.OutOfMemoryError` และหยุดกระบวนการผู้ปฏิบัติงาน (worker)

เพื่อป้องกันปัญหานี้ เราจะทำการ export `RAY_memory_monitor_refresh_ms=0` บนแต่ละเครื่องก่อนที่จะเริ่มต้นและเข้าร่วมคลัสเตอร์
### ขั้นตอนที่ 1: เริ่มต้น Ray Head Node (เครื่องที่ 1)

บนเครื่องที่ 1 ให้เริ่มต้น Ray head node เพื่อสร้างคลัสเตอร์:

```bash
export RAY_memory_monitor_refresh_ms=0
ray start --head --port=6379 --node-ip-address=<MACHINE_1_IP> --num-gpus=1
```

> **การหา `<MACHINE_1_IP>`**: บนเครื่องที่ 1 ให้รันคำสั่ง `hostname -I | awk '{print $1}'` เพื่อค้นหาที่อยู่ IP ภายในเครื่อง

### ขั้นตอนที่ 2: เข้าร่วมคลัสเตอร์ (เครื่องที่ 2)

บนเครื่องที่ 2 ให้เชื่อมต่อกับ head node เพื่อสร้างคลัสเตอร์:

```bash
export RAY_memory_monitor_refresh_ms=0
ray start --address=<MACHINE_1_IP>:6379 --node-ip-address=<MACHINE_2_IP> --num-gpus=1
```

> **การหา `<MACHINE_2_IP>`**: บนเครื่องที่ 2 ให้รันคำสั่ง `hostname -I | awk '{print $1}'` เพื่อค้นหาที่อยู่ IP ภายในเครื่อง

### ขั้นตอนที่ 3: เสิร์ฟโมเดล (เครื่องที่ 1)

บนเครื่องที่ 1 ให้เปิดใช้งานเซิร์ฟเวอร์ vLLM ซึ่งจะดาวน์โหลดโมเดลโดยอัตโนมัติและเริ่มเสิร์ฟโมเดลนั้นข้ามทั้งสองโหนด:

```bash
vllm serve Qwen/Qwen3.5-397B-A17B-GPTQ-Int4 \
  --port 7000 \
  --host 0.0.0.0 \
  --max-model-len 32768 \
  --gpu-memory-utilization 0.9 \
  --dtype float16 \
  --tensor-parallel-size 2 \
  --distributed-executor-backend ray \
  --enforce-eager \
  --language-model-only \
  --reasoning-parser qwen3
```

#### ข้อมูลอ้างอิงพารามิเตอร์

| แฟล็ก | จุดประสงค์ |
|------|---------|
| `--port` | พอร์ตที่ใช้เสิร์ฟ HTTP API |
| `--host` | ที่อยู่ IP ที่ใช้ผูกกับเซิร์ฟเวอร์ (`0.0.0.0` สำหรับทุกอินเทอร์เฟซ) |
| `--max-model-len` | ความยาวบริบทสูงสุดในหน่วยโทเคน |
| `--gpu-memory-utilization` | สัดส่วนของหน่วยความจำ GPU ที่จะจัดสรร (0.0–1.0) |
| `--dtype` | ชนิดข้อมูลสำหรับน้ำหนักของโมเดล |
| `--tensor-parallel-size` | จำนวน GPU ที่จะใช้แบ่งโมเดล (กำหนดเป็นจำนวน GPU ทั้งหมดในคลัสเตอร์) |
| `--distributed-executor-backend` | แบ็กเอนด์สำหรับการรันแบบหลายโหนด (`ray` สำหรับการปรับใช้แบบคลัสเตอร์) |
| `--enforce-eager` | ปิดใช้งานการคอมไพล์ CUDA graph เพื่อความเข้ากันได้ |
| `--language-model-only` | ข้ามการโหลดส่วนประกอบเสริมของโมเดล (เช่น ตัวเข้ารหัสภาพ) |
| `--reasoning-parser` | เปิดใช้งานการแยกวิเคราะห์ผลลัพธ์การให้เหตุผลแบบมีโครงสร้างสำหรับโมเดล |

สำหรับการใช้งานพารามิเตอร์ทั้งหมด โปรดดูที่ [เอกสาร vLLM](https://docs.vllm.ai/en/latest/configuration/engine_args/)

## การเข้าถึงโมเดล

vLLM เปิดให้ใช้งาน API ที่เข้ากันได้กับ OpenAI ดังนั้นคุณจึงสามารถเชื่อมต่อไคลเอนต์หรืออินเทอร์เฟซที่รองรับใดๆ เข้ากับคลัสเตอร์ของคุณได้ ตัวเลือกที่ได้รับความนิยมตัวหนึ่งคือ [Open WebUI](https://github.com/open-webui/open-webui) ซึ่งมอบอินเทอร์เฟซแชทแบบเบราว์เซอร์

หากต้องการเชื่อมต่อ Open WebUI เข้ากับ endpoint ของ vLLM:

1. เปิด **Settings** > **Admin Panel** > **Connections**
2. คลิก **+** ที่ **Manage OpenAI API Connections**
3. ตั้งค่า **Connection Type** เป็น **External**
4. ตั้งค่า **URL** เป็น `http://<MACHINE_1_IP>:7000/v1`
5. ที่ **Auth** ให้เลือก **None** จากเมนูแบบดรอปดาวน์
6. เว้น **Model IDs** ให้ว่างไว้เพื่อค้นหาโมเดลทั้งหมดจาก endpoint โดยอัตโนมัติ

> **การหา `<MACHINE_1_IP>`**: บนเครื่องที่ 1 ให้รันคำสั่ง `hostname -I | awk '{print $1}'` เพื่อค้นหาที่อยู่ IP ภายในเครื่อง หากเข้าถึง Open WebUI จากเครื่องที่ 1 เอง คุณสามารถใช้ `http://localhost:7000/v1` ได้

![การตั้งค่าการเชื่อมต่อ Open WebUI สำหรับ endpoint ของ vLLM](assets/openwebui-connection.png)

เมื่อเชื่อมต่อแล้ว ให้เลือกโมเดลจากเมนูดรอปดาวน์ในโมเดลของ Open WebUI แล้วเริ่มแชท ตอนนี้โมเดลกำลังทำงานข้ามทั้งสองโหนด Ryzen AI Halo ของคุณแล้ว:

![การแชทกับ Qwen3.5-397B ใน Open WebUI](assets/openwebui-chat.png)

## ขั้นตอนถัดไป

- **สำรวจโมเดลอื่นๆ**: ค้นพบโมเดลใหม่ๆ บน [Hugging Face](https://huggingface.co/models?&sort=trending) ที่เหมาะสมกับหน่วยความจำ GPU รวมของคลัสเตอร์ของคุณ
- **ขยายเป็นสี่โหนด**: เพิ่มระบบ Ryzen AI Halo อีกสองเครื่องเป็น Ray workers เพิ่มเติมเพื่อแบ่งโมเดลข้าม GPU ได้มากขึ้น ซึ่งต้องใช้สวิตช์ Ethernet ที่มีอย่างน้อยสี่พอร์ต หนึ่งพอร์ตต่อหนึ่งโหนด ให้ทำตาม [ขั้นตอนที่ 2: เข้าร่วมคลัสเตอร์](#step-2-join-the-cluster-machine-2) บนแต่ละ worker เพิ่มเติม และเพิ่มค่า `--tensor-parallel-size` ตามความเหมาะสม
- **ลองกลยุทธ์การแบ่งประมวลผลแบบอื่นๆ**: vLLM รองรับ [expert parallel](https://docs.vllm.ai/en/latest/serving/expert_parallel_deployment/) สำหรับโมเดลแบบ mixture-of-experts และ [data parallel](https://docs.vllm.ai/en/latest/serving/data_parallel_deployment/) เพื่อเพิ่มปริมาณงาน ลองทดสอบด้วย `--enable-expert-parallel` และ `--data-parallel-size` เพื่อค้นหาการตั้งค่าที่เหมาะสมที่สุดสำหรับงานของคุณ
