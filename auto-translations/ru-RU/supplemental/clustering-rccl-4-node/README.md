# Кластеризация четырёх Ryzen™ AI Halo с помощью RCCL

## Обзор

Ваш Ryzen™ AI Halo уже способен локально запускать большие языковые модели. Кластеризация выводит это на новый уровень, объединяя память GPU нескольких систем по локальной сети, что открывает доступ к ещё более крупным моделям с более сильным рассуждением, лучшей генерацией кода и более глубоким пониманием множества языков — и всё это полностью на вашем собственном оборудовании.

В этом руководстве показано, как объединить в кластер четыре системы Ryzen AI Halo с помощью RCCL (ROCm Communication Collectives Library) вместе с vLLM и запустить Qwen3.5-397B, модель с 397 млрд параметров, на всех четырёх машинах с ускорением ROCm.

## Чему вы научитесь

- Как увеличить выделение VRAM на системах Ryzen AI Halo
- Запуску vLLM с поддержкой ROCm
- Настройке RCCL для многоузлового тензорно-параллельного вывода на четырёх системах Ryzen AI Halo
- Запуску модели с 397 млрд параметров на четырёх объединённых в сеть системах Ryzen AI Halo

## Предварительные требования

### Оборудование

Для этого руководства требуются четыре устройства Ryzen AI Halo и один коммутатор Ethernet, соединённые по топологии «звезда», при этом каждое устройство подключается напрямую к коммутатору.

| Компонент | Количество | Описание |
|-----------|----------|-------------|
| Ryzen AI Halo | 4 | Вычислительные узлы, образующие кластер |
| Коммутатор Ethernet 10 Гбит/с | 1 | Центральный коммутатор для обеспечения многоузловой связи между устройствами Ryzen AI Halo (не менее 4 портов) |
| Кабель Ethernet | 4 | Подключает каждое устройство Halo к коммутатору (рекомендуется Cat 7 или выше) |

> **Примечание**: для подключения четырёх устройств Ryzen AI Halo требуется четыре порта коммутатора Ethernet. Пятый порт необходим, если вы обращаетесь к модели с отдельного клиентского компьютера, а не с одного из устройств Halo.

## Настройка физического оборудования

> **Примечание**: выполните этот шаг на всех четырёх машинах (с Машины 1 по Машину 4).

Подключите каждое устройство Ryzen AI Halo к коммутатору Ethernet с помощью кабеля Cat 7 (или выше). Это обеспечивает соединение 10 Гбит/с, используемое для высокоскоростной связи между узлами.

### 1. Определение сетевых интерфейсов

На каждой машине найдите имя её сетевого интерфейса и запишите его (далее по тексту он будет упоминаться как `IFNAME`). Выполните:

```bash
ip route get 1.1.1.1 | grep -oP 'dev \K\S+'
```

Это выведет имя интерфейса напрямую, например:

```bash
enp191s0
```

### 2. Проверка скорости сетевого соединения

Убедитесь, что соединение активно и работает на полной скорости, проверив скорость вашего интерфейса:

```bash
sudo ethtool <IFNAME> | grep Speed
```

> **Примечание**: замените `<IFNAME>` именем выходного интерфейса из раздела [1. Определение сетевых интерфейсов](#1-determine-network-interfaces)

Вы должны увидеть скорость `10000Mb/s`:

```bash
	Speed: 10000Mb/s
```

> **Примечание**: если скорость ниже `10000Mb/s` или соединение не устанавливается, проверьте подключение кабеля и убедитесь, что порт коммутатора настроен на 10 Гбит/с. Некоторым коммутаторам требуется отключить автосогласование и задать скорость соединения вручную; обратитесь к документации вашего коммутатора.

## Увеличение выделения VRAM

> **Примечание**: выполните этот шаг на всех четырёх машинах (с Машины 1 по Машину 4).

### Настройка памяти для запуска больших моделей

В Linux ROCm использует общий пул системной памяти, и по умолчанию этот пул настроен на половину системной памяти.

Этот объём можно увеличить, изменив настройку страниц Translation Table Manager (TTM) ядра, следуя приведённым ниже инструкциям. AMD рекомендует задать в BIOS минимальный объём выделенной VRAM (0,5 ГБ).

* Установите утилиту pipx и добавьте путь к установленным с её помощью пакетам в системный путь поиска.

  ```bash
  sudo apt install pipx
  pipx ensurepath
  ```

* Установите пакет amd-debug-tools из PyPI.
  ```bash
  pipx install amd-debug-tools
  ```

* Запустите утилиту amd-ttm, чтобы узнать текущие настройки общей памяти.
  ```bash
  amd-ttm
  ```

* Переконфигурируйте настройки общей памяти на значение **120 ГБ**:
  ```bash
  amd-ttm --set 120
  ```

* Перезагрузите систему, чтобы изменения вступили в силу.

## Инициализация контейнера vLLM

> **Примечание**: выполните этот шаг на всех четырёх машинах (с Машины 1 по Машину 4).

Ваш Ryzen AI Halo поставляется с vLLM, упакованным внутри готового образа контейнера, который вы запускаете с помощью Podman — бесплатного инструмента для работы с контейнерами с открытым исходным кодом.

### 1. Создание каталога для загрузки модели

Когда вы запустите модель Qwen3.5-397B в этом руководстве, vLLM автоматически загрузит веса модели в вашу систему. Чтобы эти веса были доступны изнутри контейнера, сначала создайте каталог моделей, который контейнер сможет смонтировать:

```bash
mkdir -p ~/.local/share/vLLM/models
```

### 2. Запуск контейнера vLLM

Приведённая ниже команда запускает контейнер и открывает интерактивную оболочку. Она монтирует только что созданный каталог моделей и передаёт ваш `IFNAME` в `NCCL_SOCKET_IFNAME` и `GLOO_SOCKET_IFNAME`, указывая RCCL (библиотеке, которую vLLM использует для координации GPU в кластере), какой интерфейс использовать.

Запустите контейнер с помощью:

```bash
sudo podman run -it --name vllm_cluster --replace --pull missing --network=host --device /dev/kfd --device /dev/dri -v ~/.local/share/vLLM/models:/opt/vLLM/models --env HF_HOME=/opt/vLLM/models --entrypoint="bin/bash" --shm-size=64g --pids-limit=-1 -e NCCL_SOCKET_IFNAME=<IFNAME> -e GLOO_SOCKET_IFNAME=<IFNAME> oci-registry.ryai.dev/ryai-vllm:latest
```

> **Примечание**: замените `<IFNAME>` именем выходного интерфейса из раздела [1. Определение сетевых интерфейсов](#1-determine-network-interfaces)

## Запуск модели на кластере

vLLM использует Ray для оркестрации кластера и RCCL для обработки связи между GPU на разных узлах. Одна машина выступает в роли головного узла (Машина 1), координируя вывод. Остальные три присоединяются как узлы-воркеры (Машины 2, 3 и 4), предоставляя свою память GPU и вычислительные ресурсы.

> **Примечание**: Ray является опциональной зависимостью для vLLM и доступен только изнутри предварительно настроенного контейнера Podman.

При запуске vLLM разбивает модель на части по всем четырём узлам с помощью тензорного параллелизма. После загрузки вывод выполняется так, как если бы он работал на одном ускорителе.

#### Предотвращение ошибок нехватки памяти (OOM) в Ray

По умолчанию Ray отслеживает память хоста на каждом узле и завершает самый крупный процесс, когда использование памяти превышает 95%. На вашем Ryzen™ AI Halo GPU и хост используют один общий пул памяти, поэтому загрузка модели может вызвать `ray.exceptions.OutOfMemoryError` и завершение процесса воркера.

Чтобы это предотвратить, мы экспортируем `RAY_memory_monitor_refresh_ms=0` на каждой машине перед запуском и присоединением к кластеру.
### Шаг 1: Запуск головного узла Ray (Машина 1)

На Машине 1 запустите головной узел Ray для инициализации кластера:

```bash
export RAY_memory_monitor_refresh_ms=0
ray start --head --port=6379 --node-ip-address=<MACHINE_1_IP> --num-gpus=1
```

> **Определение `<MACHINE_1_IP>`**: на Машине 1 выполните `hostname -I | awk '{print $1}'`, чтобы узнать её локальный IP-адрес.

### Шаг 2: Подключение к кластеру (Машины 2, 3 и 4)

На каждой из Машин 2, 3 и 4 подключитесь к головному узлу, чтобы сформировать кластер:

```bash
export RAY_memory_monitor_refresh_ms=0
ray start --address=<MACHINE_1_IP>:6379 --node-ip-address=<MACHINE_N_IP> --num-gpus=1
```

> **Определение `<MACHINE_N_IP>`**: на каждой рабочей машине выполните `hostname -I | awk '{print $1}'`, чтобы узнать её локальный IP-адрес.

### Шаг 3: Запуск модели (Машина 1)

На Машине 1 запустите сервер vLLM. Он автоматически загрузит модель и начнёт обслуживать её на всех четырёх узлах:

```bash
vllm serve Qwen/Qwen3.5-397B-A17B-GPTQ-Int4 \
  --port 7000 \
  --host 0.0.0.0 \
  --max-model-len 131072 \
  --gpu-memory-utilization 0.8 \
  --dtype float16 \
  --tensor-parallel-size 4 \
  --distributed-executor-backend ray \
  --enforce-eager \
  --language-model-only \
  --reasoning-parser qwen3
```

#### Справочник по параметрам

| Флаг | Назначение |
|------|------------|
| `--port` | Порт, на котором обслуживается HTTP API |
| `--host` | IP-адрес, к которому привязывается сервер (`0.0.0.0` для всех интерфейсов) |
| `--max-model-len` | Максимальная длина контекста в токенах |
| `--gpu-memory-utilization` | Доля памяти GPU для выделения (0.0–1.0) |
| `--dtype` | Тип данных для весов модели |
| `--tensor-parallel-size` | Количество GPU, между которыми распределяется модель (укажите общее число GPU в кластере) |
| `--distributed-executor-backend` | Бэкенд для многоузлового выполнения (`ray` для развёртывания на кластере) |
| `--enforce-eager` | Отключает компиляцию CUDA graph для совместимости |
| `--language-model-only` | Пропускает загрузку вспомогательных компонентов модели (например, визуального энкодера) |
| `--reasoning-parser` | Включает структурированный разбор вывода рассуждений модели |

Полное описание параметров см. в [документации vLLM](https://docs.vllm.ai/en/latest/configuration/engine_args/).

## Доступ к модели

vLLM предоставляет API, совместимый с OpenAI, поэтому к вашему кластеру можно подключить любой совместимый клиент или интерфейс. Один из популярных вариантов — [Open WebUI](https://github.com/open-webui/open-webui), который предоставляет веб-интерфейс чата в браузере.

Чтобы подключить Open WebUI к вашей конечной точке vLLM:

1. Откройте **Settings** > **Admin Panel** > **Connections**
2. Нажмите **+** рядом с **Manage OpenAI API Connections**
3. Установите для **Connection Type** значение **External**
4. Установите **URL** равным `http://<MACHINE_1_IP>:7000/v1`
5. В разделе **Auth** выберите **None** из выпадающего списка
6. Оставьте поле **Model IDs** пустым, чтобы автоматически обнаружить все модели на конечной точке

> **Определение `<MACHINE_1_IP>`**: на Машине 1 выполните `hostname -I | awk '{print $1}'`, чтобы узнать её локальный IP-адрес. Если вы обращаетесь к Open WebUI с самой Машины 1, можно использовать `http://localhost:7000/v1`.

![Настройки подключения Open WebUI к конечной точке vLLM](assets/openwebui-connection.png)

После подключения выберите модель из выпадающего списка моделей в Open WebUI и начните общение. Теперь модель работает на всех четырёх узлах Ryzen AI Halo:

![Общение с Qwen3.5-397B в Open WebUI](assets/openwebui-chat.png)

Выполните шаги из раздела [Шаг 2: Подключение к кластеру](#step-2-join-the-cluster-machines-2-3-and-4) на каждом дополнительном рабочем узле и соответственно увеличьте значение `--tensor-parallel-size`
- **Попробуйте другие стратегии параллелизма**: vLLM поддерживает [expert parallel](https://docs.vllm.ai/en/latest/serving/expert_parallel_deployment/) для моделей mixture-of-experts и [data parallel](https://docs.vllm.ai/en/latest/serving/data_parallel_deployment/) для более высокой пропускной способности. Поэкспериментируйте с `--enable-expert-parallel` и `--data-parallel-size`, чтобы подобрать оптимальную конфигурацию для вашей нагрузки
