## Обзор

[OpenHands](https://github.com/All-Hands-AI/OpenHands) — это ИИ-агент для работы с ПО,
который может писать код, запускать команды, просматривать веб-страницы и редактировать файлы в реальном
рабочем пространстве. Вместо того чтобы копировать предложения из окна чата, вы указываете
агенту папку проекта и позволяете ему выполнять работу: реализовать функцию, исправить
ошибку, написать тесты или объяснить кодовую базу.

[Agent Canvas](https://github.com/OpenHands/agent-canvas) — это рекомендуемый
браузерный интерфейс для запуска OpenHands. Единая команда `agent-canvas` запускает
сервер агента, автоматизированный бэкенд и веб-фронтенд вместе, позволяя вам
вести беседу с агентом прямо из браузера.

Чтобы всё оставалось на вашей системе AMD, агент взаимодействует с локальной моделью, которую обслуживает
Lemonade Server. Lemonade предоставляет доступ к этой модели через API, совместимый с OpenAI,
поэтому Agent Canvas может настроить её как любую другую конечную точку в стиле OpenAI,
при этом модель, ваш код и контекст беседы остаются на вашей
машине.

В этом playbook вы запустите локальную модель, откроете Agent Canvas, настроите её
на использование этой модели и выполните свою первую задачу по написанию кода на реальной папке проекта.

## Чему вы научитесь

- Как запустить Lemonade Server и убедиться, что локальная модель отвечает на запросы чата
- Как установить и запустить Agent Canvas из пакета npm
- Как настроить Agent Canvas на использование локальной модели Lemonade в качестве LLM
- Как начать беседу OpenHands и наблюдать, как агент редактирует файлы и выполняет
  команды в рабочем пространстве
- Как проверить изменения, внесённые агентом, и направлять его последующими сообщениями

| Понятие | Что это такое | Место в этом playbook |

## 1. Запустите Lemonade Server

Запустите модель из CLI Lemonade:

```bash
lemonade config set llamacpp.backend=vulkan
lemonade config set ctx_size=65536
lemonade run "Qwen3.6-35B-A3B-GGUF"
```

Lemonade предоставляет API, совместимый с OpenAI, по адресу:

```text
http://127.0.0.1:13305/api/v1
```



## 2. Проверьте локальную модель

Убедитесь, что Lemonade может обслуживать выбранную модель:

```bash
curl -s "http://127.0.0.1:13305/api/v1/models" | python3 -m json.tool
```

Затем отправьте небольшой запрос чата:

```bash
curl -sS "http://127.0.0.1:13305/api/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "Qwen3.6-35B-A3B-GGUF",
    "messages": [
      {"role": "user", "content": "Reply with exactly: OK"}
    ],
    "temperature": 0,
    "max_tokens": 64
  }' | python3 -m json.tool
```

Если в ответ приходит массив `choices`, значит Lemonade готов к работе с Agent Canvas.

## 3. Установите и запустите Agent Canvas

Установите опубликованный пакет Agent Canvas глобально:

```bash
npm install -g @openhands/agent-canvas
```

Затем запустите весь стек из терминала:

```bash
agent-canvas
```

По умолчанию Agent Canvas запускается по адресу `http://localhost:8000`. Откройте этот URL
в браузере. Если порт 8000 уже используется, передайте `--port` (или `-p`) при
запуске Agent Canvas:

```bash
agent-canvas --port 3000
```

Та же команда работает в PowerShell в Windows. Затем откройте
`http://localhost:3000` вместо указанного выше адреса. Локальный бэкенд по умолчанию должен отображаться на
главном экране как исправный.

Команда `agent-canvas` запускает сервер агента, автоматизированный бэкенд и
веб-фронтенд вместе. Вам нужна только эта одна команда для запуска OpenHands
локально.

## 4. Настройте локальную LLM

При первом запуске Agent Canvas открывает процесс первоначальной настройки. В этом процессе:

1. Оставьте **OpenHands** выбранным в качестве агента и нажмите **Next**.
2. На экране **Set up your LLM** выберите **Advanced**.
3. Оставьте **Authentication** установленным на **API key**.
4. Установите **Custom Model** на `openai/Qwen3.6-35B-A3B-GGUF`.
5. Установите **Base URL** на `http://127.0.0.1:13305/api/v1`.
6. В поле **API Key** введите любой непустой заполнитель, например `lemonade-local`.
   Lemonade не требует настоящего ключа, но клиенту OpenHands нужно передать какое-либо значение.
7. Нажмите **Next**.

Заполненные настройки Advanced должны выглядеть следующим образом. Поле ключа API
скрыто интерфейсом.

![Настройки Agent Canvas Advanced LLM при первом использовании с моделью Lemonade и локальным Base URL](assets/01-llm-advanced-settings.png)

Agent Canvas сохраняет эти значения как профиль LLM. Если ваша версия просит вас
назвать этот профиль, используйте имя без пробелов, например `lemonade-local`. Если вы измените
модели позже, откройте **Settings > LLM** и обновите те же поля Advanced. Вы
можете переключать сохранённые профили из поля ввода чата с помощью команды `/model`.

## 5. Откройте рабочее пространство

Агент может только читать и изменять файлы внутри выбранного вами рабочего пространства. Перед
началом задачи направьте Agent Canvas на папку вашего проекта:

1. На главном экране выберите **Open Workspace**.
2. Выберите папку, содержащую ваш проект (например, git-репозиторий,
   над которым вы хотите, чтобы работал агент).
3. Начните новую беседу в этом рабочем пространстве.

Всё, что делает агент — чтение файлов, выполнение команд, редактирование кода — ограничено
этим рабочим пространством.

![Главный экран Agent Canvas после первоначальной настройки](assets/02-agent-canvas-home.png)
## 6. Запустите первую задачу для написания кода

Открыв рабочую область и выбрав локальную LLM, введите в чат конкретную задачу. Хорошая первая задача должна быть небольшой и легко проверяемой, например:

```text
Create a new file called hello.py that defines a function greet(name) that
returns "Hello, {name}!", and add a small test that prints greet("World")
when run as a script.
```

Наблюдайте за хронологией беседы. OpenHands будет:

- Изучать рабочую область, чтобы понять её структуру.
- Создаст `hello.py` с запрошенной функцией и тестовым блоком.
- При необходимости выполнит `python3 hello.py`, чтобы проверить результат.
- Сообщит в чате о том, что было сделано, и о результатах выполнения команд.

Вы должны увидеть новый файл в рабочей области, а в итоговом сообщении агента должно быть описано внесённое изменение. Это и есть тот самый ключевой момент: агент написал и выполнил реальный код в папке вашего проекта.

## 7. Проверка результатов и корректировка действий агента

После того как агент завершит шаг, проверьте его работу, прежде чем принимать следующий:

- **Изменения файлов**: используйте обозреватель файлов рабочей области или представление diff агента, чтобы точно увидеть, что было добавлено, изменено или удалено.
- **Вывод команд**: разверните любую выполненную агентом команду, чтобы увидеть stdout, stderr и код завершения.
- **Дальнейшие действия**: если результат не соответствует ожиданиям, ответьте в этом же диалоге с исправлением. Агент сохраняет предыдущий контекст и продолжает работу с теми же файлами.

Например, если тест не вывел ожидаемое приветствие, ответьте:

```text
The script did not print anything. Run python3 hello.py and fix it so the
greet("World") test prints to stdout.
```

Агент повторно прочитает файл, выполнит команду, диагностирует проблему и снова отредактирует файл — всё в рамках того же диалога.

## Устранение неполадок

- **`agent-canvas` отсутствует в PATH:** переустановите с помощью
  `npm install -g @openhands/agent-canvas` и убедитесь, что каталог глобальных бинарных файлов npm указан в PATH. В Windows выполните `npm config get prefix`; возвращённый каталог, часто `%APPDATA%\npm` или `%USERPROFILE%\.npm-global`,
  должен быть добавлен в пользовательский PATH, прежде чем `agent-canvas` можно будет запускать из нового терминала.
- **`npm install -g` завершается с ошибкой доступа:** настройте пользовательский каталог для глобальных пакетов npm, затем заново откройте терминал и снова установите Agent Canvas.

  <!-- @os:linux -->
  ```bash
  mkdir -p ~/.npm-global
  npm config set prefix ~/.npm-global
  echo 'export PATH="$HOME/.npm-global/bin:$PATH"' >> ~/.profile
  . ~/.profile
  npm install -g @openhands/agent-canvas
  ```
  <!-- @os:end -->

  <!-- @os:windows -->
  ```powershell
  New-Item -ItemType Directory -Force "$env:USERPROFILE\.npm-global"
  npm config set prefix "$env:USERPROFILE\.npm-global"
  $env:Path = "$env:USERPROFILE\.npm-global;$env:Path"
  npm install -g @openhands/agent-canvas
  ```

  Чтобы сделать изменение PATH в Windows постоянным, добавьте `%USERPROFILE%\.npm-global` в
  пользовательский PATH через **Settings > System > About > Advanced system settings >
  Environment Variables** и откройте новый терминал.
  <!-- @os:end -->
- **Интерфейс загружается, но состояние бэкенда отображается как нездоровое:** подождите несколько секунд, пока сервер агента завершит запуск, затем обновите страницу. Если состояние по-прежнему нездоровое, перезапустите
  `agent-canvas` и проверьте вывод терминала на наличие ошибок.
- **Запросы к чату Lemonade завершаются ошибкой соединения:** убедитесь, что
  `curl -fsS "http://127.0.0.1:13305/api/v1/health"` выполняется успешно и что
  Lemonade всё ещё обслуживает модель, с помощью `lemonade status`.
- **Агент выдаёт ошибку, связанную с длиной контекста или лимитом токенов:** перезапустите
  Lemonade с большим значением `ctx_size` (например, `ctx_size=65536`) и начните
  новый диалог, чтобы агент не переносил чрезмерно большую историю.
- **Агент выдаёт результаты низкого качества или неполные изменения:** переключитесь на более крупную
  модель в Lemonade или поставьте агенту более маленькую и конкретную задачу и дайте ему
  завершить её, прежде чем запрашивать следующее изменение.
- **Отсутствует `uv`:** установите его из
  [руководства по установке uv](https://docs.astral.sh/uv/getting-started/installation/).
  Agent Canvas использует `uv` для управления Python-окружением сервера агента.

## Дальнейшие шаги

- Попробуйте более крупную задачу в той же рабочей области, например добавление файла модульного теста или
  исправление известной ошибки, и просмотрите diff агента, прежде чем сохранять изменение.
- Подключите MCP-сервер, например GitHub или Slack, в разделе **Customize**, чтобы
  агент мог читать issue или публиковать обновления во время работы.
- Сохраните несколько профилей LLM (быструю небольшую модель и более мощную крупную модель) и
  переключайтесь между ними с помощью `/model` прямо в ходе диалога.
- Перейдите к разделу [автоматизации OpenHands](https://docs.openhands.dev/openhands/usage/automations/overview), чтобы
  превратить повторяющиеся циклы разработки в запуски агента по расписанию или по событию.
