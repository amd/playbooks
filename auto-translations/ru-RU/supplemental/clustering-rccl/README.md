# Объединение двух Ryzen™ AI Halo в кластер с помощью RCCL

## Обзор

Ваш Ryzen™ AI Halo уже способен локально запускать большие языковые модели. Кластеризация выводит это на новый уровень, объединяя GPU-память нескольких систем через локальную сеть, что даёт доступ к ещё более крупным моделям с более сильными способностями к рассуждению, лучшей генерацией кода и более глубоким пониманием многоязычного текста — и всё это полностью на вашем собственном оборудовании.

Этот playbook научит вас объединять в кластер две системы Ryzen AI Halo с помощью RCCL (ROCm Communication Collectives Library) вместе с vLLM и запускать Qwen3.5-397B, модель с 397 миллиардами параметров, на обеих машинах с ускорением ROCm.

## Чему вы научитесь

- Как расширить выделение VRAM на системах Ryzen AI Halo
- Запуску vLLM с поддержкой ROCm
- Настройке RCCL для многоузлового тензорно-параллельного инференса между двумя системами Ryzen AI Halo
- Запуску модели с 397 миллиардами параметров на двух объединённых в сеть системах Ryzen AI Halo

## Предварительные требования

### Оборудование

Для этого playbook требуются два блока Ryzen AI Halo и один Ethernet-коммутатор, соединённые по топологии «звезда», где каждый блок подключён напрямую к коммутатору.

| Компонент | Количество | Описание |
|-----------|----------|-------------|
| Ryzen AI Halo | 2 | Вычислительные узлы, образующие кластер |
| Ethernet-коммутатор 10 Гбит/с | 1 | Центральный коммутатор для обеспечения связи между несколькими узлами Ryzen AI Halo (не менее 2 портов) |
| Ethernet-кабель | 2 | Соединяет каждый блок Halo с коммутатором (рекомендуется Cat 7 или выше) |

> **Примечание**: Для соединения двух блоков Ryzen AI Halo требуется два порта Ethernet-коммутатора. Третий порт нужен, если вы обращаетесь к модели с отдельной клиентской машины, а не с одного из блоков Halo.

## Настройка физического оборудования

> **Примечание**: Выполните этот шаг как на Machine 1, так и на Machine 2.

Подключите каждый блок Ryzen AI Halo к Ethernet-коммутатору с помощью кабеля Cat 7 (или выше). Это устанавливает канал 10 Гбит/с, используемый для высокоскоростного обмена данными между узлами.

### 1. Определение сетевых интерфейсов

На каждой машине найдите имя её сетевого интерфейса и запишите его (далее в инструкциях оно будет обозначаться как `IFNAME`). Выполните:

```bash
ip route get 1.1.1.1 | grep -oP 'dev \K\S+'
```

Это выводит имя интерфейса напрямую, например:

```bash
enp191s0
```

### 2. Проверка скорости сетевого соединения

Убедитесь, что соединение активно и работает на полной скорости, проверив скорость вашего интерфейса:

```bash
sudo ethtool <IFNAME> | grep Speed
```

> **Примечание**: Замените `<IFNAME>` на имя выходного интерфейса из раздела [1. Определение сетевых интерфейсов](#1-определение-сетевых-интерфейсов)

Вы должны увидеть скорость `10000Mb/s`:

```bash
	Speed: 10000Mb/s
```

> **Примечание**: Если скорость ниже `10000Mb/s` или соединение не устанавливается, проверьте подключение кабеля и убедитесь, что порт коммутатора настроен на 10 Гбит/с. На некоторых коммутаторах требуется отключить автосогласование и вручную установить скорость соединения; обратитесь к документации вашего коммутатора.

## Расширение выделения VRAM

> **Примечание**: Выполните этот шаг как на Machine 1, так и на Machine 2.

### Настройка памяти для запуска больших моделей

В Linux ROCm использует общий пул системной памяти, и по умолчанию этот пул настроен на половину объёма системной памяти.

Этот объём можно увеличить, изменив настройку страниц Translation Table Manager (TTM) ядра, следуя приведённым ниже инструкциям. AMD рекомендует задать минимальный выделенный объём VRAM в BIOS (0,5 ГБ).

* Установите утилиту pipx и добавьте путь для установленных через pipx wheel-пакетов в системный путь поиска.

  ```bash
  sudo apt install pipx
  pipx ensurepath
  ```

* Установите wheel-пакет amd-debug-tools из PyPI.
  ```bash
  pipx install amd-debug-tools
  ```

* Запустите инструмент amd-ttm, чтобы узнать текущие настройки общей памяти.
  ```bash
  amd-ttm
  ```

* Измените настройки общей памяти на **120 ГБ**:
  ```bash
  amd-ttm --set 120
  ```

* Перезагрузите систему, чтобы изменения вступили в силу.

## Инициализация контейнера vLLM

> **Примечание**: Выполните этот шаг как на Machine 1, так и на Machine 2.

Ваш Ryzen AI Halo поставляется с vLLM, упакованным внутри готового образа контейнера, который вы запускаете с помощью Podman — бесплатного инструмента для работы с контейнерами с открытым исходным кодом.

### 1. Создание каталога для загрузки модели

Когда вы запустите модель Qwen3.5-397B в этом playbook, vLLM автоматически загрузит веса модели в вашу систему. Чтобы эти веса были доступны изнутри контейнера, сначала создайте каталог models, который контейнер сможет смонтировать:

```bash
mkdir -p ~/.local/share/vLLM/models
```

### 2. Запуск контейнера vLLM

Приведённая ниже команда запускает контейнер и помещает вас в интерактивную оболочку. Она монтирует только что созданный каталог models и передаёт ваш `IFNAME` в `NCCL_SOCKET_IFNAME` и `GLOO_SOCKET_IFNAME`, сообщая RCCL (библиотеке, которую vLLM использует для координации GPU в кластере), какой интерфейс использовать.

Запустите контейнер с помощью:

```bash
sudo podman run -it --name vllm_cluster --replace --pull missing --network=host --device /dev/kfd --device /dev/dri -v ~/.local/share/vLLM/models:/opt/vLLM/models --env HF_HOME=/opt/vLLM/models --entrypoint="bin/bash" --shm-size=64g -e NCCL_SOCKET_IFNAME=<IFNAME> -e GLOO_SOCKET_IFNAME=<IFNAME> oci-registry.ryai.dev/ryai-vllm:latest
```

> **Примечание**: Замените `<IFNAME>` на имя выходного интерфейса из раздела [1. Определение сетевых интерфейсов](#1-определение-сетевых-интерфейсов)

## Запуск модели на кластере

vLLM использует Ray для оркестрации кластера и RCCL для организации связи GPU-GPU между узлами. Одна машина выступает в роли **головного узла** (Machine 1), координирующего инференс. Другая присоединяется в роли **рабочего узла** (Machine 2), предоставляя свою GPU-память и вычислительные мощности.

> **Примечание**: Ray является опциональной зависимостью для vLLM и доступен только внутри предварительно настроенного контейнера Podman.

При запуске vLLM разбивает модель между обоими узлами с помощью тензорного параллелизма. После загрузки инференс выполняется так, как если бы он работал на одном ускорителе.

### Шаг 1: Запуск головного узла Ray (Machine 1)

На Machine 1 запустите головной узел Ray, чтобы инициализировать кластер:

```bash
ray start --head --port=6379 --node-ip-address=<MACHINE_1_IP> --num-gpus=1
```

> **Определение `<MACHINE_1_IP>`**: На Machine 1 выполните `hostname -I | awk '{print $1}'`, чтобы узнать её локальный IP-адрес.
### Шаг 2: Присоединение к кластеру (Машина 2)

На Машине 2 подключитесь к головному узлу, чтобы сформировать кластер:

```bash
ray start --address=<MACHINE_1_IP>:6379 --node-ip-address=<MACHINE_2_IP> --num-gpus=1
```

> **Определение `<MACHINE_2_IP>`**: на Машине 2 выполните `hostname -I | awk '{print $1}'`, чтобы узнать её локальный IP-адрес.

### Шаг 3: Запуск модели (Машина 1)

На Машине 1 запустите сервер vLLM. Он автоматически загрузит модель и начнёт обслуживать её на обоих узлах:

```bash
vllm serve Qwen/Qwen3.5-397B-A17B-GPTQ-Int4 \
  --port 7000 \
  --host 0.0.0.0 \
  --max-model-len 32768 \
  --gpu-memory-utilization 0.9 \
  --dtype float16 \
  --tensor-parallel-size 2 \
  --distributed-executor-backend ray \
  --enforce-eager \
  --language-model-only \
  --reasoning-parser qwen3
```

#### Справочник по параметрам

| Флаг | Назначение |
|------|---------|
| `--port` | Порт для обслуживания HTTP API |
| `--host` | IP-адрес для привязки сервера (`0.0.0.0` для всех интерфейсов) |
| `--max-model-len` | Максимальная длина контекста в токенах |
| `--gpu-memory-utilization` | Доля памяти GPU для выделения (0.0–1.0) |
| `--dtype` | Тип данных для весов модели |
| `--tensor-parallel-size` | Количество GPU для разделения модели (укажите общее число GPU в кластере) |
| `--distributed-executor-backend` | Бэкенд для многоузлового выполнения (`ray` для развёртываний кластера) |
| `--enforce-eager` | Отключает компиляцию CUDA-графов для совместимости |
| `--language-model-only` | Пропускает загрузку вспомогательных компонентов модели (например, визуального энкодера) |
| `--reasoning-parser` | Включает разбор структурированного вывода рассуждений для модели |

Полное описание использования параметров см. в [документации vLLM](https://docs.vllm.ai/en/latest/configuration/engine_args/).

## Доступ к модели

vLLM предоставляет API, совместимый с OpenAI, поэтому вы можете подключить к своему кластеру любой совместимый клиент или интерфейс. Один из популярных вариантов — [Open WebUI](https://github.com/open-webui/open-webui), который предоставляет чат-интерфейс на базе браузера.

Чтобы подключить Open WebUI к вашей конечной точке vLLM:

1. Откройте **Settings** > **Admin Panel** > **Connections**
2. Нажмите **+** рядом с **Manage OpenAI API Connections**
3. Установите **Connection Type** в значение **External**
4. Установите **URL** в значение `http://<MACHINE_1_IP>:7000/v1`
5. В разделе **Auth** выберите **None** из выпадающего списка
6. Оставьте поле **Model IDs** пустым, чтобы автоматически обнаружить все модели из конечной точки

> **Определение `<MACHINE_1_IP>`**: на Машине 1 выполните `hostname -I | awk '{print $1}'`, чтобы узнать её локальный IP-адрес. Если вы обращаетесь к Open WebUI с самой Машины 1, можно использовать `http://localhost:7000/v1`.

![Настройки подключения Open WebUI к конечной точке vLLM](assets/openwebui-connection.png)

После подключения выберите модель из выпадающего списка моделей в Open WebUI и начните общение. Теперь модель работает на обоих узлах Ryzen AI Halo:

![Общение с Qwen3.5-397B в Open WebUI](assets/openwebui-chat.png)

## Дальнейшие шаги

- **Изучите другие модели**: найдите новые модели на [Hugging Face](https://huggingface.co/models?&sort=trending), которые подходят по объёму под совокупную память GPU вашего кластера
- **Масштабирование до четырёх узлов**: добавьте ещё две системы Ryzen AI Halo в качестве дополнительных рабочих узлов Ray, чтобы разделять модели между ещё большим числом GPU. Для этого потребуется Ethernet-коммутатор как минимум с четырьмя портами — по одному на каждый узел. Выполните [Шаг 2: Присоединение к кластеру](#step-2-join-the-cluster-machine-2) на каждом дополнительном рабочем узле и соответствующим образом увеличьте значение `--tensor-parallel-size`
- **Попробуйте другие стратегии параллелизма**: vLLM поддерживает [expert parallel](https://docs.vllm.ai/en/latest/serving/expert_parallel_deployment/) для моделей типа mixture-of-experts и [data parallel](https://docs.vllm.ai/en/latest/serving/data_parallel_deployment/) для более высокой пропускной способности. Поэкспериментируйте с `--enable-expert-parallel` и `--data-parallel-size`, чтобы найти оптимальную конфигурацию для вашей нагрузки
