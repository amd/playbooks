# Кластеризация двух Ryzen™ AI Halo с помощью RCCL

## Обзор

Ваш Ryzen™ AI Halo уже способен запускать большие языковые модели локально. Кластеризация расширяет эти возможности, объединяя GPU-память нескольких систем через локальную сеть и открывая доступ к ещё более крупным моделям с улучшенными возможностями рассуждения, генерации кода и многоязычного понимания — и всё это исключительно на вашем собственном оборудовании.

Этот playbook научит вас объединять две системы Ryzen AI Halo в кластер с использованием RCCL (ROCm Communication Collectives Library) совместно с vLLM, а также запускать Qwen3.5-397B — модель с 397 миллиардами параметров — на обеих машинах с ускорением ROCm.

## Что вы узнаете

- Как расширить выделение VRAM на системах Ryzen AI Halo
- Как запустить vLLM с поддержкой ROCm
- Как настроить RCCL для многоузлового тензорно-параллельного инференса на двух системах Ryzen AI Halo
- Как запустить модель с 397 миллиардами параметров на двух объединённых в сеть системах Ryzen AI Halo

## Предварительные требования

### Оборудование

Для этого playbook требуются два устройства Ryzen AI Halo и один коммутатор Ethernet, соединённые по топологии «звезда», при которой каждое устройство подключено напрямую к коммутатору.

| Компонент | Количество | Описание |
|-----------|----------|-------------|
| Ryzen AI Halo | 2 | Вычислительные узлы, образующие кластер |
| Коммутатор Ethernet 10 Гбит/с | 1 | Центральный коммутатор для обеспечения многоузловой связи между устройствами Ryzen AI Halo (не менее 2 портов) |
| Кабель Ethernet | 2 | Подключает каждое устройство Halo к коммутатору (рекомендуется Cat 7 или выше) |

> **Примечание**: Для подключения двух устройств Ryzen AI Halo требуются два порта коммутатора Ethernet. Третий порт необходим, если вы обращаетесь к модели с отдельной клиентской машины, а не с одного из устройств Halo.

## Физическая настройка оборудования

> **Примечание**: Выполните этот шаг на обеих машинах — Machine 1 и Machine 2.

Подключите каждое устройство Ryzen AI Halo к коммутатору Ethernet с помощью кабеля Cat 7 (или выше). Это обеспечивает канал 10 Гбит/с для высокоскоростного обмена данными между узлами.

### 1. Определение сетевых интерфейсов

На каждой машине найдите имя сетевого интерфейса и запишите его (в дальнейших инструкциях оно будет обозначаться как `IFNAME`). Выполните:

```bash
ip route get 1.1.1.1 | grep -oP 'dev \K\S+'
```

Команда выведет имя интерфейса напрямую, например:

```bash
enp191s0
```

### 2. Проверка скорости сетевого соединения

Убедитесь, что соединение активно и работает на полной скорости, проверив скорость вашего интерфейса:

```bash
sudo ethtool <IFNAME> | grep Speed
```

> **Примечание**: Замените `<IFNAME>` именем интерфейса, полученным в разделе [1. Определение сетевых интерфейсов](#1-determine-network-interfaces)

Вы должны увидеть скорость `10000Mb/s`:

```bash
	Speed: 10000Mb/s
```

> **Примечание**: Если скорость ниже `10000Mb/s` или соединение не устанавливается, проверьте подключение кабеля и убедитесь, что порт коммутатора настроен на 10 Гбит/с. На некоторых коммутаторах может потребоваться отключить автосогласование и задать скорость соединения вручную; обратитесь к документации вашего коммутатора.

## Расширение выделения VRAM

> **Примечание**: Выполните этот шаг на обеих машинах — Machine 1 и Machine 2.

### Настройка памяти для запуска больших моделей

В Linux ROCm использует общий пул системной памяти, который по умолчанию настроен на половину объёма системной памяти.

Этот объём можно увеличить, изменив параметр страниц Translation Table Manager (TTM) ядра, следуя приведённым ниже инструкциям. AMD рекомендует задать минимальный выделенный объём VRAM в BIOS (0,5 ГБ).

* Установите утилиту pipx и добавьте путь к установленным pipx пакетам в системный путь поиска.

  ```bash
  sudo apt install pipx
  pipx ensurepath
  ```

* Установите пакет amd-debug-tools из PyPI.
  ```bash
  pipx install amd-debug-tools
  ```

* Запустите инструмент amd-ttm для просмотра текущих настроек общей памяти.
  ```bash
  amd-ttm
  ```

* Перенастройте параметры общей памяти на **120 ГБ**:
  ```bash
  amd-ttm --set 120
  ```

* Перезагрузите систему, чтобы изменения вступили в силу.

## Инициализация контейнера vLLM

> **Примечание**: Выполните этот шаг на обеих машинах — Machine 1 и Machine 2.

Ваш Ryzen AI Halo поставляется с vLLM, упакованным в готовый образ контейнера, который запускается с помощью Podman — свободного инструмента для работы с контейнерами с открытым исходным кодом.

### 1. Создание каталога для загрузки моделей

При запуске модели Qwen3.5-397B в этом playbook vLLM автоматически загрузит веса модели на вашу систему. Чтобы эти веса были доступны изнутри контейнера, сначала создайте каталог models, который контейнер сможет монтировать:

```bash
mkdir -p ~/.local/share/vLLM/models
```

### 2. Запуск контейнера vLLM

Приведённая ниже команда запускает контейнер и открывает интерактивную оболочку. Она монтирует только что созданный каталог models и передаёт ваш `IFNAME` в `NCCL_SOCKET_IFNAME` и `GLOO_SOCKET_IFNAME`, указывая RCCL (библиотеке, которую vLLM использует для координации GPU в кластере), какой интерфейс использовать.

Запустите контейнер командой:

```bash
sudo podman run -it --name vllm_cluster --replace --pull missing --network=host --device /dev/kfd --device /dev/dri -v ~/.local/share/vLLM/models:/opt/vLLM/models --env HF_HOME=/opt/vLLM/models --entrypoint="bin/bash" --shm-size=64g -e NCCL_SOCKET_IFNAME=<IFNAME> -e GLOO_SOCKET_IFNAME=<IFNAME> oci-registry.ryai.dev/ryai-vllm:latest
```

> **Примечание**: Замените `<IFNAME>` именем интерфейса, полученным в разделе [1. Определение сетевых интерфейсов](#1-determine-network-interfaces)

## Запуск модели на кластере

vLLM использует Ray для оркестрации кластера и RCCL для обеспечения GPU-to-GPU коммуникации между узлами. Одна машина выступает в роли **головного узла** (Machine 1), координируя инференс. Другая присоединяется как **рабочий узел** (Machine 2), предоставляя свою GPU-память и вычислительные ресурсы.

> **Примечание**: Ray является необязательной зависимостью для vLLM и доступен только внутри предварительно настроенного контейнера Podman.

При запуске vLLM распределяет модель между обоими узлами с использованием тензорного параллелизма. После загрузки инференс выполняется так, как если бы он работал на одном ускорителе.

### Шаг 1: Запуск головного узла Ray (Machine 1)

На Machine 1 запустите головной узел Ray для инициализации кластера:

```bash
ray start --head --port=6379 --node-ip-address=<MACHINE_1_IP> --num-gpus=1
```

> **Как найти `<MACHINE_1_IP>`**: На Machine 1 выполните `hostname -I | awk '{print $1}'`, чтобы узнать её локальный IP-адрес.

### Шаг 2: Присоединение к кластеру (Machine 2)

На Machine 2 подключитесь к головному узлу для формирования кластера:

```bash
ray start --address=<MACHINE_1_IP>:6379 --node-ip-address=<MACHINE_2_IP> --num-gpus=1
```

> **Как найти `<MACHINE_2_IP>`**: На Machine 2 выполните `hostname -I | awk '{print $1}'`, чтобы узнать её локальный IP-адрес.

### Шаг 3: Запуск модели (Machine 1)

На Machine 1 запустите сервер vLLM. Он автоматически загрузит модель и начнёт обслуживать запросы на обоих узлах:

```bash
vllm serve Qwen/Qwen3.5-397B-A17B-GPTQ-Int4 \
  --port 7000 \
  --host 0.0.0.0 \
  --max-model-len 32768 \
  --gpu-memory-utilization 0.9 \
  --dtype float16 \
  --tensor-parallel-size 2 \
  --distributed-executor-backend ray \
  --enforce-eager \
  --language-model-only \
  --reasoning-parser qwen3
```

#### Справочник по параметрам

| Флаг | Назначение |
|------|---------|
| `--port` | Порт для HTTP API |
| `--host` | IP-адрес для привязки сервера (`0.0.0.0` для всех интерфейсов) |
| `--max-model-len` | Максимальная длина контекста в токенах |
| `--gpu-memory-utilization` | Доля GPU-памяти для выделения (0.0–1.0) |
| `--dtype` | Тип данных для весов модели |
| `--tensor-parallel-size` | Количество GPU для распределения модели (задаётся равным общему числу GPU в кластере) |
| `--distributed-executor-backend` | Бэкенд для многоузлового выполнения (`ray` для кластерных развёртываний) |
| `--enforce-eager` | Отключает компиляцию CUDA-графов для обеспечения совместимости |
| `--language-model-only` | Пропускает загрузку вспомогательных компонентов модели (например, визуального энкодера) |
| `--reasoning-parser` | Включает структурированный разбор вывода рассуждений для модели |

Полное описание параметров см. в [документации vLLM](https://docs.vllm.ai/en/latest/configuration/engine_args/).

## Доступ к модели

vLLM предоставляет OpenAI-совместимый API, поэтому вы можете подключить к вашему кластеру любой совместимый клиент или интерфейс. Одним из популярных вариантов является [Open WebUI](https://github.com/open-webui/open-webui) — браузерный интерфейс для общения в чате.

Чтобы подключить Open WebUI к вашей конечной точке vLLM:

1. Откройте **Settings** > **Admin Panel** > **Connections**
2. Нажмите **+** в разделе **Manage OpenAI API Connections**
3. Установите **Connection Type** в значение **External**
4. Задайте **URL** как `http://<MACHINE_1_IP>:7000/v1`
5. В разделе **Auth** выберите **None** из выпадающего списка
6. Оставьте поле **Model IDs** пустым для автоматического обнаружения всех моделей из конечной точки

> **Как найти `<MACHINE_1_IP>`**: На Machine 1 выполните `hostname -I | awk '{print $1}'`, чтобы узнать её локальный IP-адрес. Если вы обращаетесь к Open WebUI непосредственно с Machine 1, можно использовать `http://localhost:7000/v1`.

![Настройки подключения Open WebUI для конечной точки vLLM](assets/openwebui-connection.png)

После подключения выберите модель в выпадающем списке моделей в Open WebUI и начните общение. Модель теперь работает на обоих узлах вашего кластера Ryzen AI Halo:

![Общение с Qwen3.5-397B в Open WebUI](assets/openwebui-chat.png)

## Дальнейшие шаги

- **Исследуйте другие модели**: Откройте для себя новые модели на [Hugging Face](https://huggingface.co/models?&sort=trending), которые умещаются в суммарной GPU-памяти вашего кластера
- **Масштабируйте до четырёх узлов**: Добавьте ещё два устройства Ryzen AI Halo в качестве дополнительных рабочих узлов Ray, чтобы распределить модели на ещё большее количество GPU. Для этого потребуется коммутатор Ethernet не менее чем с четырьмя портами — по одному на каждый узел. Выполните [Шаг 2: Присоединение к кластеру](#step-2-join-the-cluster-machine-2) на каждом дополнительном рабочем узле и соответственно увеличьте значение `--tensor-parallel-size`
- **Попробуйте другие стратегии параллелизма**: vLLM поддерживает [экспертный параллелизм](https://docs.vllm.ai/en/latest/serving/expert_parallel_deployment/) для моделей типа mixture-of-experts и [параллелизм данных](https://docs.vllm.ai/en/latest/serving/data_parallel_deployment/) для повышения пропускной способности. Экспериментируйте с `--enable-expert-parallel` и `--data-parallel-size`, чтобы найти оптимальную конфигурацию для вашей рабочей нагрузки
