# Кластеризация двух Ryzen™ AI Halo с использованием RCCL

## Обзор

Ваш Ryzen™ AI Halo уже способен локально запускать большие языковые модели. Кластеризация выводит эти возможности на новый уровень, объединяя память GPU нескольких систем через локальную сеть, что открывает доступ к ещё более крупным моделям с более сильным логическим выводом, улучшенной генерацией кода и более глубоким пониманием многоязычного текста — и всё это полностью на вашем собственном оборудовании.

Это руководство научит вас объединять в кластер две системы Ryzen AI Halo с использованием RCCL (ROCm Communication Collectives Library) вместе с vLLM и запускать Qwen3.5-397B — модель с 397 миллиардами параметров — на обеих машинах с ускорением ROCm.

## Чему вы научитесь

- Как расширить выделение VRAM на системах Ryzen AI Halo
- Запуску vLLM с поддержкой ROCm
- Настройке RCCL для многоузлового тензорно-параллельного вывода на двух системах Ryzen AI Halo
- Запуску модели с 397 миллиардами параметров на двух объединённых в сеть системах Ryzen AI Halo

## Предварительные требования

### Оборудование

Для этого руководства потребуются два устройства Ryzen AI Halo и один Ethernet-коммутатор, соединённые по топологии «звезда», при этом каждое устройство подключается напрямую к коммутатору.

| Компонент | Количество | Описание |
|-----------|----------|-------------|
| Ryzen AI Halo | 2 | Вычислительные узлы, образующие кластер |
| Ethernet-коммутатор 10 Гбит/с | 1 | Центральный коммутатор для обеспечения связи между несколькими узлами Ryzen AI Halo (минимум 2 порта) |
| Ethernet-кабель | 2 | Подключает каждое устройство Halo к коммутатору (рекомендуется Cat 7 или выше) |

> **Примечание**: для подключения двух устройств Ryzen AI Halo требуется два порта Ethernet-коммутатора. Третий порт необходим, если вы обращаетесь к модели с отдельной клиентской машины, а не с одного из устройств Halo.

## Физическая настройка оборудования

> **Примечание**: выполните этот шаг как на Машине 1, так и на Машине 2.

Подключите каждое устройство Ryzen AI Halo к Ethernet-коммутатору с помощью кабеля Cat 7 (или выше). Это обеспечит соединение со скоростью 10 Гбит/с, используемое для высокоскоростной связи между узлами.

### 1. Определение сетевых интерфейсов

На каждой машине найдите имя её сетевого интерфейса и запишите его (далее в инструкциях оно будет обозначаться как `IFNAME`). Выполните:

```bash
ip route get 1.1.1.1 | grep -oP 'dev \K\S+'
```

Эта команда выводит имя интерфейса напрямую, например:

```bash
enp191s0
```

### 2. Проверка скорости сетевого соединения

Убедитесь, что соединение активно и работает на полной скорости, проверив скорость вашего интерфейса:

```bash
sudo ethtool <IFNAME> | grep Speed
```

> **Примечание**: замените `<IFNAME>` на имя интерфейса, полученное в разделе [1. Определение сетевых интерфейсов](#1-determine-network-interfaces)

Вы должны увидеть скорость `10000Mb/s`:

```bash
	Speed: 10000Mb/s
```

> **Примечание**: если скорость ниже `10000Mb/s` или соединение не устанавливается, проверьте кабельное подключение и убедитесь, что порт коммутатора настроен на 10 Гбит/с. На некоторых коммутаторах требуется отключить автосогласование и вручную задать скорость соединения; обратитесь к документации вашего коммутатора.

## Расширение выделения VRAM

> **Примечание**: выполните этот шаг как на Машине 1, так и на Машине 2.

### Настройка памяти для запуска больших моделей

В Linux ROCm использует общий пул системной памяти, и по умолчанию этот пул настроен на половину объёма системной памяти.

Этот объём можно увеличить, изменив настройку страниц Translation Table Manager (TTM) ядра, следуя приведённым ниже инструкциям. AMD рекомендует задать минимальный объём выделенной VRAM в BIOS (0,5 ГБ).

* Установите утилиту pipx и добавьте путь к установленным через pipx пакетам в системный путь поиска.

  ```bash
  sudo apt install pipx
  pipx ensurepath
  ```

* Установите пакет amd-debug-tools из PyPI.
  ```bash
  pipx install amd-debug-tools
  ```

* Запустите утилиту amd-ttm, чтобы узнать текущие настройки общей памяти.
  ```bash
  amd-ttm
  ```

* Измените настройки общей памяти на **120 ГБ**:
  ```bash
  amd-ttm --set 120
  ```

* Перезагрузите систему, чтобы изменения вступили в силу.

## Инициализация контейнера vLLM

> **Примечание**: выполните этот шаг как на Машине 1, так и на Машине 2.

Ваш Ryzen AI Halo поставляется с vLLM, упакованным в готовый образ контейнера, который вы запускаете с помощью Podman — бесплатного инструмента для работы с контейнерами с открытым исходным кодом.

### 1. Создание каталога для загрузки модели

Когда вы запустите модель Qwen3.5-397B в этом руководстве, vLLM автоматически загрузит веса модели в вашу систему. Чтобы обеспечить доступ к этим весам изнутри контейнера, сначала создайте каталог для моделей, который можно будет смонтировать в контейнер:

```bash
mkdir -p ~/.local/share/vLLM/models
```

### 2. Запуск контейнера vLLM

Приведённая ниже команда запускает контейнер и переводит вас в интерактивную оболочку. Она монтирует только что созданный каталог моделей и передаёт ваш `IFNAME` в переменные `NCCL_SOCKET_IFNAME` и `GLOO_SOCKET_IFNAME`, указывая RCCL (библиотеке, которую vLLM использует для координации GPU в кластере), какой интерфейс использовать.

Запустите контейнер с помощью:

```bash
sudo podman run -it --name vllm_cluster --replace --pull missing --network=host --device /dev/kfd --device /dev/dri -v ~/.local/share/vLLM/models:/opt/vLLM/models --env HF_HOME=/opt/vLLM/models --entrypoint="bin/bash" --shm-size=64g --pids-limit=-1 -e NCCL_SOCKET_IFNAME=<IFNAME> -e GLOO_SOCKET_IFNAME=<IFNAME> oci-registry.ryai.dev/ryai-vllm:latest
```

> **Примечание**: замените `<IFNAME>` на имя интерфейса, полученное в разделе [1. Определение сетевых интерфейсов](#1-determine-network-interfaces)

## Запуск модели на кластере

vLLM использует Ray для оркестрации кластера и RCCL для обработки связи между GPU на разных узлах. Одна машина выступает в роли **головного узла** (Машина 1), координируя вывод. Другая присоединяется как **рабочий узел** (Машина 2), предоставляя свою память GPU и вычислительные ресурсы.

> **Примечание**: Ray является опциональной зависимостью для vLLM и доступен только внутри предварительно настроенного контейнера Podman.

При запуске vLLM разбивает модель на части между обоими узлами, используя тензорный параллелизм. После загрузки вывод выполняется так, как если бы он выполнялся на одном ускорителе.

#### Предотвращение ошибок нехватки памяти (OOM) в Ray

По умолчанию Ray отслеживает использование памяти хоста на каждом узле и завершает самый крупный процесс при превышении использования памяти 95%. На вашем Ryzen™ AI Halo GPU и хост используют общий пул памяти, поэтому загрузка модели может вызвать `ray.exceptions.OutOfMemoryError` и привести к завершению рабочего процесса.

Чтобы предотвратить это, мы экспортируем переменную `RAY_memory_monitor_refresh_ms=0` на каждой машине перед запуском кластера и присоединением к нему.
### Шаг 1: Запуск головного узла Ray (Машина 1)

На Машине 1 запустите головной узел Ray, чтобы инициализировать кластер:

```bash
export RAY_memory_monitor_refresh_ms=0
ray start --head --port=6379 --node-ip-address=<MACHINE_1_IP> --num-gpus=1
```

> **Определение `<MACHINE_1_IP>`**: на Машине 1 выполните `hostname -I | awk '{print $1}'`, чтобы узнать её локальный IP-адрес.

### Шаг 2: Присоединение к кластеру (Машина 2)

На Машине 2 подключитесь к головному узлу, чтобы сформировать кластер:

```bash
export RAY_memory_monitor_refresh_ms=0
ray start --address=<MACHINE_1_IP>:6379 --node-ip-address=<MACHINE_2_IP> --num-gpus=1
```

> **Определение `<MACHINE_2_IP>`**: на Машине 2 выполните `hostname -I | awk '{print $1}'`, чтобы узнать её локальный IP-адрес.

### Шаг 3: Запуск модели (Машина 1)

На Машине 1 запустите сервер vLLM. Это автоматически загрузит модель и начнёт обслуживать её на обоих узлах:

```bash
vllm serve Qwen/Qwen3.5-397B-A17B-GPTQ-Int4 \
  --port 7000 \
  --host 0.0.0.0 \
  --max-model-len 32768 \
  --gpu-memory-utilization 0.9 \
  --dtype float16 \
  --tensor-parallel-size 2 \
  --distributed-executor-backend ray \
  --enforce-eager \
  --language-model-only \
  --reasoning-parser qwen3
```

#### Справочник по параметрам

| Флаг | Назначение |
|------|---------|
| `--port` | Порт для обслуживания HTTP API |
| `--host` | IP-адрес для привязки сервера (`0.0.0.0` для всех интерфейсов) |
| `--max-model-len` | Максимальная длина контекста в токенах |
| `--gpu-memory-utilization` | Доля выделяемой памяти GPU (0.0–1.0) |
| `--dtype` | Тип данных для весов модели |
| `--tensor-parallel-size` | Количество GPU для распределения модели (установите равным общему числу GPU в кластере) |
| `--distributed-executor-backend` | Бэкенд для многоузлового выполнения (`ray` для развёртываний в кластере) |
| `--enforce-eager` | Отключает компиляцию CUDA-графов для совместимости |
| `--language-model-only` | Пропускает загрузку вспомогательных компонентов модели (например, визуального энкодера) |
| `--reasoning-parser` | Включает структурированный разбор вывода рассуждений для модели |

Полное описание использования параметров см. в [документации vLLM](https://docs.vllm.ai/en/latest/configuration/engine_args/).

## Доступ к модели

vLLM предоставляет API, совместимый с OpenAI, поэтому вы можете подключить любой совместимый клиент или интерфейс к вашему кластеру. Один из популярных вариантов — [Open WebUI](https://github.com/open-webui/open-webui), который предоставляет чат-интерфейс на основе браузера.

Чтобы подключить Open WebUI к вашей конечной точке vLLM:

1. Откройте **Settings** > **Admin Panel** > **Connections**
2. Нажмите **+** рядом с **Manage OpenAI API Connections**
3. Установите **Connection Type** в значение **External**
4. Установите **URL** в значение `http://<MACHINE_1_IP>:7000/v1`
5. В разделе **Auth** выберите **None** из выпадающего списка
6. Оставьте поле **Model IDs** пустым, чтобы автоматически обнаружить все модели с конечной точки

> **Определение `<MACHINE_1_IP>`**: на Машине 1 выполните `hostname -I | awk '{print $1}'`, чтобы узнать её локальный IP-адрес. Если вы обращаетесь к Open WebUI с самой Машины 1, можно использовать `http://localhost:7000/v1`.

![Настройки подключения Open WebUI к конечной точке vLLM](assets/openwebui-connection.png)

После подключения выберите модель из выпадающего списка моделей в Open WebUI и начните общение. Теперь модель работает на обоих ваших узлах Ryzen AI Halo:

## Дальнейшие шаги

- **Изучите другие модели**: найдите новые модели на [Hugging Face](https://huggingface.co/models?&sort=trending), которые помещаются в суммарную память GPU вашего кластера
- **Масштабирование до четырёх узлов**: добавьте ещё две системы Ryzen AI Halo в качестве дополнительных воркеров Ray, чтобы распределять модели ещё на большее число GPU. Для этого потребуется Ethernet-коммутатор как минимум с четырьмя портами, по одному на каждый узел. Выполните шаги из раздела [Шаг 2: Присоединение к кластеру](#step-2-join-the-cluster-machine-2) на каждом дополнительном воркере и соответствующим образом увеличьте `--tensor-parallel-size`
- **Попробуйте другие стратегии параллелизма**: vLLM поддерживает [expert parallel](https://docs.vllm.ai/en/latest/serving/expert_parallel_deployment/) для моделей типа mixture-of-experts и [data parallel](https://docs.vllm.ai/en/latest/serving/data_parallel_deployment/) для повышения пропускной способности. Поэкспериментируйте с `--enable-expert-parallel` и `--data-parallel-size`, чтобы подобрать оптимальную конфигурацию для вашей нагрузки
