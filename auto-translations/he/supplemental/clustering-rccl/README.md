# צביר שני מחשבי Ryzen™ AI Halo באמצעות RCCL

## סקירה כללית

מחשב ה-Ryzen™ AI Halo שברשותכם מסוגל כבר להריץ מודלי שפה גדולים באופן מקומי. צביר לוקח זאת צעד קדימה על ידי שילוב זיכרון ה-GPU של מספר מערכות דרך רשת מקומית, ומעניק לכם גישה למודלים גדולים אף יותר עם יכולות היגיון חזקות יותר, יצירת קוד טובה יותר, והבנה רב-לשונית מעמיקה יותר, כל זאת לחלוטין על החומרה שלכם.

מדריך זה ילמד אתכם כיצד לצבר שתי מערכות Ryzen AI Halo באמצעות RCCL‏ (ROCm Communication Collectives Library) יחד עם vLLM ולהריץ את Qwen3.5-397B, מודל בעל 397 מיליארד פרמטרים, על פני שתי המכונות עם האצת ROCm.

## מה תלמדו

- כיצד להרחיב את הקצאת ה-VRAM במערכות Ryzen AI Halo
- הפעלת vLLM עם תמיכת ROCm
- הגדרת RCCL להסקה מקבילת-טנזורים בין צמתים (multi-node) על פני שתי מערכות Ryzen AI Halo
- הרצת מודל בעל 397 מיליארד פרמטרים על פני שתי מערכות Ryzen AI Halo מקושרות ברשת

## הגדרת החומרה הפיזית

> **הערה**: השלימו שלב זה הן על מכונה 1 והן על מכונה 2.

חברו כל יחידת Ryzen AI Halo למתג ה-Ethernet באמצעות כבל Cat 7 (או גבוה יותר). פעולה זו מקימה את קישור ה-10Gbps המשמש לתקשורת מהירה בין הצמתים.

### 1. קביעת ממשקי הרשת

בכל מכונה, מצאו את שם ממשק הרשת שלה ורשמו אותו (הוא יכונה בהמשך ההוראות `IFNAME`). הריצו:

```bash
ip route get 1.1.1.1 | grep -oP 'dev \K\S+'
```

פעולה זו מדפיסה את שם הממשק ישירות, לדוגמה:

```bash
enp191s0
```

### 2. אימות מהירויות קישור הרשת

ודאו שהקישור פעיל ורץ במהירות המלאה על ידי בדיקת מהירות הממשק שלכם:

```bash
sudo ethtool <IFNAME> | grep Speed
```

> **הערה**: החליפו את `<IFNAME>` בשם ממשק היציאה מ-[1. קביעת ממשקי הרשת](#1-קביעת-ממשקי-הרשת)

אתם אמורים לראות מהירות של `10000Mb/s`:

```bash
	Speed: 10000Mb/s
```

> **הערה**: אם המהירות נמוכה מ-`10000Mb/s` או שהקישור אינו עולה, בדקו את חיבור הכבל ווודאו שיציאת המתג מוגדרת ל-10Gbps. חלק מהמתגים דורשים ביטול משא ומתן אוטומטי (auto-negotiation) והגדרת מהירות הקישור באופן ידני; עיינו בתיעוד המתג שלכם.

## הרחבת הקצאת ה-VRAM

> **הערה**: השלימו שלב זה הן על מכונה 1 והן על מכונה 2.

### תצורת זיכרון להרצת מודלים גדולים

ב-Linux‏, ROCm משתמשת במאגר זיכרון מערכת משותף, ומאגר זה מוגדר כברירת מחדל לחצי מזיכרון המערכת.

ניתן להגדיל כמות זו על ידי שינוי הגדרת עמודי Translation Table Manager‏ (TTM) של הליבה (kernel), בהתאם להוראות הבאות. AMD ממליצה להגדיר את מינימום ה-VRAM הייעודי ב-BIOS (0.5 GB).

* התקינו את הכלי pipx והוסיפו את הנתיב לחבילות (wheels) המותקנות דרך pipx לנתיב החיפוש של המערכת.

  ```bash
  sudo apt install pipx
  pipx ensurepath
  ```

* התקינו את חבילת amd-debug-tools מ-PyPI.
  ```bash
  pipx install amd-debug-tools
  ```

* הריצו את הכלי amd-ttm כדי לבדוק את ההגדרות הנוכחיות לזיכרון משותף.
  ```bash
  amd-ttm
  ```

* הגדירו מחדש את הגדרות הזיכרון המשותף ל-**120 GB**:
  ```bash
  amd-ttm --set 120
  ```

* הפעילו מחדש את המערכת כדי שהשינויים ייכנסו לתוקף.

## אתחול מכולת vLLM

> **הערה**: השלימו שלב זה הן על מכונה 1 והן על מכונה 2.

מחשב ה-Ryzen AI Halo שברשותכם מגיע עם vLLM ארוזה בתוך תמונת מכולה (container image) בנויה מראש, אותה תריצו באמצעות Podman, כלי מכולות חופשי וקוד פתוח.

### 1. יצירת ספריית הורדת המודל

כאשר תגישו את המודל Qwen3.5-397B במדריך זה, vLLM תוריד אוטומטית את משקלי המודל למערכת שלכם. כדי לוודא שהמשקלים האלה נגישים מתוך המכולה, צרו תחילה ספריית models שהמכולה יכולה לעגן (mount):

```bash
mkdir -p ~/.local/share/vLLM/models
```

### 2. הפעלת מכולת vLLM

הפקודה למטה מפעילה את המכולה ומעבירה אתכם למעטפת אינטראקטיבית (interactive shell). היא מעגנת את ספריית ה-models שיצרתם זה עתה ומעבירה את `IFNAME` שלכם אל `NCCL_SOCKET_IFNAME` וגם אל `GLOO_SOCKET_IFNAME`, ומודיעה ל-RCCL (הספרייה ש-vLLM משתמשת בה כדי לתאם GPU-ים על פני הצביר) איזה ממשק להשתמש בו.

הפעילו את המכולה עם:

```bash
sudo podman run -it --name vllm_cluster --replace --pull missing --network=host --device /dev/kfd --device /dev/dri -v ~/.local/share/vLLM/models:/opt/vLLM/models --env HF_HOME=/opt/vLLM/models --entrypoint="bin/bash" --shm-size=64g -e NCCL_SOCKET_IFNAME=<IFNAME> -e GLOO_SOCKET_IFNAME=<IFNAME> oci-registry.ryai.dev/ryai-vllm:latest
```

> **הערה**: החליפו את `<IFNAME>` בשם ממשק היציאה מ-[1. קביעת ממשקי הרשת](#1-קביעת-ממשקי-הרשת)

## הרצת המודל על הצביר

vLLM משתמשת ב-Ray כדי לתזמר את הצביר וב-RCCL כדי לטפל בתקשורת בין GPU-ים על פני צמתים. מכונה אחת פועלת בתור **צומת ראשי** (head node) (מכונה 1), ומתאמת את ההסקה. המכונה השנייה מצטרפת בתור **צומת עובד** (worker node) (מכונה 2), ותורמת את זיכרון ה-GPU וכוח החישוב שלה.

> **הערה**: Ray היא תלות אופציונלית עבור vLLM וזמינה רק מתוך מכולת ה-Podman המוגדרת מראש.

בעת ההפעלה, vLLM מפצלת את המודל בין שני הצמתים באמצעות מקבול טנזורים (tensor parallelism). לאחר הטעינה, ההסקה ממשיכה כאילו היא רצה על מאיץ יחיד.

### שלב 1: הפעלת צומת ה-Ray הראשי (מכונה 1)

על מכונה 1, הפעילו את צומת ה-Ray הראשי כדי לאתחל את הצביר:

```bash
ray start --head --port=6379 --node-ip-address=<MACHINE_1_IP> --num-gpus=1
```

> **מציאת `<MACHINE_1_IP>`**: על מכונה 1, הריצו `hostname -I | awk '{print $1}'` כדי למצוא את כתובת ה-IP המקומית שלה.
### שלב 2: הצטרפות לאשכול (מכונה 2)

במכונה 2, התחברו לצומת הראשי כדי ליצור את האשכול:

```bash
ray start --address=<MACHINE_1_IP>:6379 --node-ip-address=<MACHINE_2_IP> --num-gpus=1
```

> **איתור `<MACHINE_2_IP>`**: במכונה 2, הריצו `hostname -I | awk '{print $1}'` כדי למצוא את כתובת ה-IP המקומית שלה.

### שלב 3: הפעלת המודל (מכונה 1)

במכונה 1, הפעילו את שרת vLLM. פעולה זו תוריד באופן אוטומטי את המודל ותתחיל להגיש אותו על פני שני הצמתים:

```bash
vllm serve Qwen/Qwen3.5-397B-A17B-GPTQ-Int4 \
  --port 7000 \
  --host 0.0.0.0 \
  --max-model-len 32768 \
  --gpu-memory-utilization 0.9 \
  --dtype float16 \
  --tensor-parallel-size 2 \
  --distributed-executor-backend ray \
  --enforce-eager \
  --language-model-only \
  --reasoning-parser qwen3
```

#### מדריך פרמטרים

| דגל | מטרה |
|------|---------|
| `--port` | הפורט שדרכו יוגש ה-API של HTTP |
| `--host` | כתובת ה-IP שאליה יאוגד השרת (`0.0.0.0` עבור כל הממשקים) |
| `--max-model-len` | אורך ההקשר המרבי בטוקנים |
| `--gpu-memory-utilization` | החלק היחסי מזיכרון ה-GPU שיוקצה (0.0–1.0) |
| `--dtype` | סוג הנתונים עבור משקלי המודל |
| `--tensor-parallel-size` | מספר כרטיסי ה-GPU שעליהם יפוצל המודל (יש להגדיר לסך כל כרטיסי ה-GPU באשכול) |
| `--distributed-executor-backend` | מנוע העיבוד להרצה מרובת צמתים (`ray` עבור פריסות אשכול) |
| `--enforce-eager` | משבית הידור גרפי CUDA לצורך תאימות |
| `--language-model-only` | מדלג על טעינת רכיבי עזר של המודל (למשל, מקודד ראייה) |
| `--reasoning-parser` | מפעיל ניתוח פלט חשיבה מובנה עבור המודל |

לשימוש מלא בפרמטרים, עיינו ב[תיעוד vLLM](https://docs.vllm.ai/en/latest/configuration/engine_args/).

## גישה למודל

vLLM חושף API תואם-OpenAI, כך שניתן לחבר כל לקוח או ממשק תואם לאשכול שלכם. אפשרות פופולרית אחת היא [Open WebUI](https://github.com/open-webui/open-webui), המספקת ממשק צ'אט מבוסס דפדפן.

כדי לחבר את Open WebUI לנקודת הקצה של vLLM שלכם:

1. פתחו **הגדרות** > **פאנל ניהול** > **חיבורים**
2. לחצו על **+** ליד **ניהול חיבורי OpenAI API**
3. הגדירו את **סוג החיבור** ל-**חיצוני**
4. הגדירו את **הכתובת (URL)** ל-`http://<MACHINE_1_IP>:7000/v1`
5. תחת **אימות**, בחרו **ללא** מהתפריט הנפתח
6. השאירו את **מזהי המודל** ריקים כדי לגלות אוטומטית את כל המודלים מנקודת הקצה

> **איתור `<MACHINE_1_IP>`**: במכונה 1, הריצו `hostname -I | awk '{print $1}'` כדי למצוא את כתובת ה-IP המקומית שלה. אם אתם ניגשים ל-Open WebUI ממכונה 1 עצמה, ניתן להשתמש ב-`http://localhost:7000/v1`.

![הגדרות חיבור Open WebUI עבור נקודת הקצה של vLLM](assets/openwebui-connection.png)

לאחר החיבור, בחרו את המודל מתפריט המודלים הנפתח ב-Open WebUI והתחילו לשוחח. המודל פועל כעת על פני שני צמתי ה-Ryzen AI Halo שלכם:

![צ'אט עם Qwen3.5-397B ב-Open WebUI](assets/openwebui-chat.png)

## השלבים הבאים

- **חקרו מודלים נוספים**: גלו מודלים חדשים ב-[Hugging Face](https://huggingface.co/models?&sort=trending) שמתאימים לזיכרון ה-GPU המשולב של האשכול שלכם
- **הרחיבו לארבעה צמתים**: הוסיפו שתי מערכות Ryzen AI Halo נוספות כעובדי Ray נוספים כדי לפצל מודלים על פני כרטיסי GPU רבים עוד יותר. הדבר מחייב מתג Ethernet עם לפחות ארבעה יציאות, אחת עבור כל צומת. בצעו את [שלב 2: הצטרפות לאשכול](#step-2-join-the-cluster-machine-2) על כל עובד נוסף והגדילו את `--tensor-parallel-size` בהתאם
- **נסו אסטרטגיות מקבילות נוספות**: vLLM תומך ב[מקבילות מומחים](https://docs.vllm.ai/en/latest/serving/expert_parallel_deployment/) עבור מודלי mixture-of-experts וב[מקבילות נתונים](https://docs.vllm.ai/en/latest/serving/data_parallel_deployment/) עבור תפוקה גבוהה יותר. נסו את `--enable-expert-parallel` ואת `--data-parallel-size` כדי למצוא את התצורה הטובה ביותר עבור עומס העבודה שלכם
